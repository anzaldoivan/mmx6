## Rationale
- Order: static oracle first (T1) because the round trip (T3), the exe-load proof (T4: function bodies from the export) and the boundary scan (T8) consume it; runtime oracle (T4) before load capture (T5) so the bridge is proven on the cheap exe case before the overlay grind (isolate the variable on one cheap case). Load map (T6) needs T5's captures; overlay programs in Ghidra (T7) need T6's proven bases; boundaries (T8) need every program in the database.
- T2 (MCP) split from T1: different failure modes (server lifecycle vs import/analysis); T2 is small and can run in parallel with T3.
- Round trip = export E1 from the analysed database → fresh import + auto-analysis + ImportAnnotations(E1) in a scratch project → export E2 → `cmp E1 E2`, run twice. Rejected: the kit's baseline-delta method (needs splat ELF, 1.3). If analysis proves nondeterministic, T3 falls back to exporting only hand-authored rows (delta vs a fresh baseline, kit `ghidra_annotations_delta.py`) and records why.
- Load proof uses a before/after diff per load event (RAM at dest captured at `BinSeek` entry and at read completion; after == member bytes, before ≠) — G5's controlled diff in one run — plus three events where available. Rejected: Redux's web server + polling (`ram_probe.py` style): timing-dependent; breakpoints in batch Lua are exact and unattended.
- Redux runs `-no-ui -testmode -lua_stdout -bios … -iso … -run -dofile <lua>` (R1.2-001); stage progress by Lua pad overrides on a frame schedule. Save states are game-derived: kept under `.run/`, never tracked.
- Load-map tool combines a static enumeration (call sites + selector tables → member→base candidates) with runtime confirmation; it is the "regenerated from the bytes" map, rerunnable from extracted bytes + `.run/` captures, with control rows: positive (exe found at header load 0x80010000; each runtime-proven member at its base) and negative (a member checked at a wrong base, member k vs member j's capture, a shuffled capture must all fail; G25). `config/loadmap.txt` is generated, tracked, never hand-edited; `make loadmap` regenerates and must leave git clean.
- N = 1 (the exe) + the number of members classified `code` (holds MIPS functions and is entered from a loaded caller); `empty` (41, 42) and `data` members are listed, not counted. The criterion is stated in `docs/memory-map.md` with its counts (G27). Engineering, not a developer call: the constitution delegates N to this load map (PROJECT_CONTEXT.md:84).
- Boundaries (T8) from two independent paths (G21): our own jump-table scan over the bytes vs Ghidra's switch recovery from the export; disagreements listed, not hidden. Library-object spans from psx_ldr signature matches; opt-level candidates (frame-pointer/-O0 shapes) recorded as candidates only — segmentation decides in 1.3.
- L4 (Kuumba123) 68 code addresses checked against Ghidra's function starts in T7 (cheap once the database exists); its 20 RAM addresses stay leads until a later phase uses them (no task needs them now; proportionality).
- Coder tier opus55 everywhere (the only tier). No `effort: high`: preset max5 has no hard rung; the one judgment-heavy step (N's criterion) is pinned by the rule above and checked by control rows.
- `review: yes` nowhere: every done-when is a command; the developer sees N and the base verdicts in the phase recap.
