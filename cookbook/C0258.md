# C0258 — Repin keeps a stale callee prototype: it compiles, the hash fails, so cast the call
tags: x4,repin,port,preamble,prototype,diff,regalloc · date: 2026-10-25 · phase/task: 2.1/T5 · origin: 2.1 T5.c1

Problem: upstream changed a call from a cast (`((void (*)())f)(x)`) to a direct `f(x)` with a real prototype. `x4port --repin` swaps only the body. The kept preamble still declares `M2C_UNK f(void*);` (s32 return). It compiles, but regalloc differs (e.g. `lb v1` vs `lb v0` right after `jal`), so the overlay sha fails. This is the silent form of C0257.

Why not take the draft preamble: shared files are #included into one TU per overlay. Siblings keep the m2c decl, which gives `conflicting types for f`.

Fix (tools/mmx6/x4port.py `cast_calls`, 2.1 T5.c1): it runs on the `changed` path only. Take each function that the draft prototypes and the kept preamble also declares. If the return type differs (resolve `#define` aliases, so `M2C_UNK`==`s32`), or the non-pointer params differ, rewrite its direct calls to `((R (*)())f)(`. R is the draft's return type. Then run `make format`, since drafts carry the upstream brace style.

Diffing a failed overlay: make deletes the bin on a sha fail. Regenerate it with objcopy from `build/<prog>.elf`. Then run `diff.sh <f> --no-pager`, because the container has no `less`. Expected comes from `make expected` on the original sources. Stage scratch files under `waves/` so they survive a sync (`mx.sh push` takes only waves/ paths).
