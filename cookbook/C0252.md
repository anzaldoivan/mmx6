# C0252 — Ghidra: mirror external names as a delta JSONL through the existing importer, then re-export
tags: ghidra,import,rename,jsonl,roundtrip · date: 2026-10-25 · phase/task: 1.10/T10 · origin: mmx6 T10.c1

When names decided outside Ghidra (symbols files, a names table) must reach the project database:
- Do not write a new Ghidra script. Emit per-program delta rows in the export's own JSONL schema.
- A `label` row (primary, USER_DEFINED, `"func":true`) renames the function.
- Add a `func` row only where no function exists. Write one `comment` plate row per address, with the full merged text.
- Feed the delta directory to ImportAnnotations.java in one headless JVM.
- Back the project (`.gpr` + `.rep`) up once before the first write. Use a tmp dir + mv. Never overwrite a backup.
- Gate on the importer's per-program summary line (`failed=0`, line count = program count), not the exit code (C0017, C0025).
- Re-export all programs. A rerun must report every delta row `unchanged` and re-export byte-equal.
- Confirm in the db itself. Run a read-only single-program export to scratch and `cmp` it against the committed export.
- mmx6: tools/mmx6/x4adapter.py --mirror, tools/mmx6/ghidra/mirror.sh, `make ghidra-mirror` (1.10/T10).
