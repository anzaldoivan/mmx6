# C0276 — Header adoption across shared-include TUs: adopt per (TU component, library), check by .o compare
tags: header,include,prototype,conflicting-types,object-compare · date: 2026-10-26 · phase/task: 2.3/T4 · origin: mmx6 T4.c2

Replace callers' own declarations with a shared header include, without moving a byte:
- Your unit is (the set of TUs that #include the same shared files) x library, not a file.
- A header prototype is TU-wide, so one sibling's own differing decl gives `conflicting types`. Adopting file by file deadlocks.
- Per unit: adopt all files at once, then compile and compare each TU's .o (objdump -drz, -r, -s of text/data/rodata/sdata/bss) against a clean baseline.
- On a failure, bisect and give it one retry pass. Re-check the final state of each unit.
- Controls: an unchanged recompile equals the baseline. A deliberately wrong decl is refused.
- Typical refusals: an SDK prototype's arity differs from the retail call (`too many arguments`), or a prototype type change moves bytes (libc memset family). Keep those units' own renamed decls and list them.
- mmx6: .run/2.3/T4/ scratch (adopt.py) and the T4.c2 log. 177 of 218 files adopted fully, 15 partly.
