# C0131 — A wipe-then-untar volume refresh has a window with no tree: concurrent compiles need a snapshot
tags: docker,volume,snapshot,concurrency,sync,hardlink · date: 2026-10-04 · phase/task: 1.8/T2 · origin: mmx6 campaign

- A sync that wipes the volume tree then untars it leaves a window with no Makefile/include/asm; a concurrent compile fails or reads a half tree.
- Run each concurrent compile in a snapshot under a wipe-exempt dir: hardlink the read-only trees (asm/, extracted/), copy the writable ones (1.8/T2 `waves/.iso/`).
