# Make `$(file >path,...)` in a recipe expands before any recipe line runs

Problem: a recipe that writes a list with `$(file >dir/keys.txt,...)` after a `mkdir -p dir` line fails with
`open: dir/keys.txt: No such file or directory. Stop.`. Make expands the whole recipe (all `$(...)` functions) before
running its first line, so the mkdir has not run yet.

Fix: create the directory at expansion time too, on an earlier recipe line: `$(shell mkdir -p dir)`, then the
`$(file ...)` line. Order of expansion within the recipe follows line order.

Use `$(file ...)` to pass a long list to a tool off the command line. Linux caps one argv element at 128 KB
(MAX_ARG_STRLEN).
