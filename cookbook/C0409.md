# Ghidra misses function starts: find them as `jr ra; <delay>` then a jal target or `addiu sp,sp,-N`
- Owner-by-"nearest Ghidra start at or before" credits a missed function's jump tables to the function before it.
- I51: func_8002E974's 4 tables went to func_8002E84C. In all, 159 jtbl rows across 57 programs were wrong, mostly in overlays.
- A missed start is an address `t` with word(t-8) == `jr ra` (0x03E00008).
- Also, t is a jal target (a boundaries.py `fstart` row), or word(t) is `addiu sp,sp,-N` (top 17 bits 0x27BD<<1|1). Case code never opens with a stack decrement, and a jal into case code is not preceded by `jr ra`.
- Check: every re-owned row's owner named `func_<addr>` in its program's src (159/159). A leaf function that is never called directly stays invisible to both tests.
- Code: tools/mmx6/boundaries.py `owner_starts` (2.7 T2). It fixes the C0389 cases too.
