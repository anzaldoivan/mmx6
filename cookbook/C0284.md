# C0284 — Judge a community RAM-map row: code corroborator, superseded sweep, struct-head cast test
tags: names,community,ram,data,struct,basis,code · date: 2026-10-30 · phase/task: 2.3/T11 · origin: mmx6 T11 B8

Use: judging a community RAM-map row (Kuumba123, Archipelago) that names a data address or a function.

1. A RAM map is a lead, not the Tweaks workbook: the v2 community cap stays. Admit only with a `code:` corroborator in
   our C that shows the role. The words are engine words, and the map's role text gives no game words.
2. Most rows are already named by an earlier batch. Reject them as `superseded: named X by B<n>`.
   A script decides these from config/symbols.<prog>.txt and the basis.tsv kinds. Rows inside a named block (g_playthrough_state) are
   `2.4: field of <sym> +0xNN`.
3. Struct-head test before naming a data address: `grep -rhoE "\([^()]*\*\)\s*&D_<VRAM>" src include | sort | uniq -c`.
   Casts to a struct type mean the address is a struct head. The role then names its +0 field.
   Example (2.3/T11): &D_80097420 cast to X4_MainBssState and X4_ObjectHeader. Hold the row for 2.4.
4. One address with rows from two sources takes one rename. Both verdicts are admitted under the same name.
5. Take refuter fixes for a verb narrower than the body. Zeroing the whole 8-byte header is clear_object_slot, not
   deactivate. A loop that also issues reads is pump_, not wait. A `size` that is a stride is `_stride`.
