# A same-unit const data run between two of a unit's tables: `carve.py data`, then the jtbl carve

- Wall (C0379): the jtbl carve refuses `non-contiguous` / `foreign-rodata` when the unit's own const data (a C function's `__builtin_memcpy` initializer) sits between two of its tables.
- Move: `carve.py data <prog> <lo>` (lo = the data dlabel) records `data <lo> <hi> <tu>`. Every reference to the run's symbols must be in `<tu>`, else `foreign-rodata`. The scan reads the asm `.s` of all programs and src C, mapped to units by include closure. The run must touch a table of `<tu>`, else `not-adjacent`. Then `carve.py jtbl` passes.
- Bytes: splat writes `asm/<prog>/nonmatchings/<tu>/<sym>.s` for an unmigrated symbol. Put `INCLUDE_RODATA("asm/<prog>/nonmatchings/<tu>", <sym>);` in the unit's C at its rodata-order position (after the INCLUDE_ASM or body whose rodata comes before it). A directive-only stub is no `asm` debt. Its symbol name adds one `placeholder-use` (count kind: `debt --update`).
- Trap: `include/include_asm.h` is included by no unit. The first build gives `parse error before string constant`. INCLUDE_RODATA is now also in `include/common.h`.
- Not a fix for gaps holding other functions' tables (func_8002F9DC: still `non-contiguous`).
- An `opt` split does not move a unit's `data` rows. `--check` contiguity catches a split that separates them.
