# An Agent worktree starts at an older ref: merge a coder branch 3-way, never by whole-file checkout

Problem: a coder spawned with worktree isolation got a tree based on 229d02dda. That is an older ref, 31 commits
behind the local HEAD it was spawned from. Its fleet-quick was green on that old base.
`git checkout <coder commit> -- <files>` into main then reverted the newer edits in those files (T9/T10 lifts and
hoisted externs). The extern count rose by 504, and the gate still said OK because extern is a count kind.

Move: check `git merge-base <coder commit> HEAD` before a merge. Restore the files to HEAD, then apply each coder's
own diff 3-way: `git diff <base> <commit> -- src | git apply -3`. Re-run fleet-quick on the merged tree.
In 2.5/T11, 105 files and five branches applied with 0 conflicts and fleet-quick was green.
Better still: tell a worktree coder to `git rebase` onto the expert's HEAD commit (named in the brief) first.

Evidence: 2.5/T11 commits 46935885b..6a6cb909f (bad merges), 9d42d5072 (repair).
