# PC probes for a return value or a store, opt-in per schedule

Problem: a gate depends on a callee's return value or a store inside a function, and member-entry breakpoints only show entries.

Move:
- Return value: an Exec breakpoint at the call site's jal + 8 (the return address) and read `v0`. A store: an Exec breakpoint at the store's pc and read the source register (mmx6: `sb v0,5(s0)` at 0x8003F2EC writes action 35).
- Find the sites by decoding the jal/sb words in a scratch scan of the program. Never commit the bytes.
- Record `s0` (the object pointer) with each hit. A pc probe also fires on older code at the same address, before the EXE loads (mmx6: frames 642-645).
- Make probes opt-in per schedule: a breakpoint added for every schedule shifts every later datapoint id and breaks the doc's cites.

Example: tools/mmx6/redux/movement.lua PROBE_DEFS (falcon_store_action, ladder_tile_up/down, armor_init) (2.6 T6.c2).
