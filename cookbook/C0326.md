# Width/sign view keeps lb/lbu when a lifted field's type differs from the reader

## When
Lifting `*(u8*)((u8*)p + o)` to a field whose declared type differs in width or sign (mmx4-derived layouts).

## Move
Spell the read as a view of the field: `*(u8*)&p->member`, `*(s8*)&p->member`. Bytes stay as retail (same lb/lbu),
the floor's `offset` count drops (no `(u8*)p + N`), and the member's type is not changed for other readers.
Decrement as `--*(u8*)&x;` rather than `x = (u8)(*(u8*)&x - 1)` (the latter trips the floor's `(u8 *)p - N` pattern).
Retype the member only with evidence (config/types/fields.tsv row + note).

## Also
Typing the base (local/param `struct T*`) was byte-identical in one pass on 13 functions (object/ task/ player/).
C0118 scheduling did not bite. One read stays an offset: enemy_bits, an array at +0x98 in a 0xA4-stride pool.
Retail adds 0x98 to the induction value. cc1 folds base+0x98 into one addiu, 1 insn short (docs/types/lift.md).
