# A batch rename rebuilds the ledger, and a Ghidra refresh rebuilds boundaries

Context: 2.3/T4.c1, 362 PsyQ names applied with `rename.py --from <basis.tsv>`.

- Asm-only functions have no `func_` token in src/include. rename.py names them through its existence source.
  That source is `config/ghidra/<prog>.jsonl` `"k":"func"` starts plus `config/boundaries.txt` `fstart`/`lib` lo rows.
  Two lib starts carried only plate comments in Ghidra. It inserts `<new> = 0xVRAM; // type:func`.
- After a batch rename, `campaign/ledger.tsv` keeps the old names: the fleet's th-ledger rung fails
  (`missing`, `malformed`). Regenerate with `ledger.py --build` (container), same task.
- After any refresh of `config/ghidra/*.jsonl`, run `make boundaries` before the contract. Its drift step fails
  otherwise. `lib` rows do not move. Fstart and overlay jtbl owners do.
- A name equal to a goto label in a caller TU is refused as `already defined`: rename the label (byte-neutral).
- Builtin-named library functions (memcpy, memset, strcpy) give cc1 `conflicting types for built-in function`
  warnings. No byte moved in 57 binaries.
- `debt --update` after the rename lowers placeholder-use. The SDK build's PROVIDE aliases stay inert.
