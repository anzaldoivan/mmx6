# C0448 — A repair-gated member is pin-free only if its exemplar is: check the exemplar for asm( pins
tags: repair,propagate,pins,exemplar · date: 2026-11-11 · phase/task: 3.1/T15 · origin: T15.c1

Symptom: a refused dup-class member gates with the 3.1 repair switches on (`propagate.py <key> --repair unitcut`).
But the exemplar body it instantiates holds `register ... asm(` pins. Banking the member then adds pins, and pins never
rise.

Move: before a live repair propagate, grep the key's exemplar shared body for `asm(`. Its path is column 3 of
config/dedup_registry.txt, after any unitcut move. A pinned exemplar means the member has no pin-free route. Revert
only that member: its unit block goes back to INCLUDE_ASM, and its registry row goes back to HEAD's text with the
exemplar's new path. Give it a blocker that names the pinned exemplar. The exemplar's own move can stay.

Evidence: 3.1 T15.c1, rock_34 0x800FA848, key dd8a. The exemplar src/shared/rock_04/func_800F1CF0.c holds 5 pins.
Unitcut had moved it out of src/rock_04/800F1738.c. The dry run in refusecause.pilot-all.tsv said `rerun gated, R5
green`. A dry run that gates says nothing about pins.
