# Descending row clear whose counter init issues too early: forward counter plus a separate descending index

Symptom: a fixed-length clear of one table row (`for (i = N-1; i >= 0; i--) a[k*N + i] = 0;`) is followed by a
store to another global. It matches except the entry order. The draft sets the loop counter before the hoisted high
half of the later global. Retail sets it after. A plain forward loop (`i = 0; i < N`) puts the high half first but gcc then
folds the row offset into the shift or walks the row ascending. Statement order, declaration order, pins and
barriers did not move it (W46, ~80 variants).

Lever: count forward for the trip count and keep a separate descending index.

```c
for (i = 0, j = N-1; i < N; i++, j--) a[k*N + j] = 0;
```

Loop reversal turns i into the countdown. It emits the
init in the preheader, after the hoisted high half. The index j keeps the row base and offset as separate adds.

Related: C0135 (statement order), C0210 (sym+K row base). Origin: W46 SLUS func_8002B2F8 (c33 narrowed retry after
c18 27/29).
