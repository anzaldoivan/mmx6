# C0452 — A re-split rewrites include/macro.inc: never pull include/ whole after a carve
tags: carve,splat,macro.inc,pull,incremental-build · date: 2026-11-12 · phase/task: 3.1/T18 · origin: mmx6 T18.c1 W305

Symptom: a carve re-splits a program on the volume. Then `mx.sh pull include/` brings splat's rewritten include/macro.inc to the host, a tracked-file diff nobody made.
The next incremental build is rc 2, with undefined `.L` jump-table labels in the carved program.
Cause: splat rewrites include/macro.inc on every re-split. The carved programs' asm is stale against the restored file until they split again.

Fix: pull only the bank's paths, never include/ whole. If it was pulled, run `git checkout include/macro.inc` on the host.
Then delete the carved programs' split stamps on the volume and rebuild, or let the fleet's clean rebuild re-split.
Seen in 3.1 T18.c1 after the rock_02 ECCF0 and SLUS 3040C rodata carves.
