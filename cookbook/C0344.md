# C0344 — Container /work has no .git: git ls-files tools need a walk fallback
tags: container,git,ls-files,sync,fleet,namesqueue,rung · date: 2026-11-02 · phase/task: 2.6/T1 · origin: mmx6 2.6 T1

Problem: a tool that lists files with `git ls-files` works on the host but dies in the container
(`CalledProcessError ... git -C /work ls-files ... exit 128`). `mx.sh sync` copies files into /work without `.git`.

Move: when `<root>/.git` is absent, walk the directory instead (`os.walk`). In a synced /work the walk equals the
tracked set plus untracked-non-ignored files, which is close enough for validity sets. Example:
`tools/mmx6/namesqueue.py` `list_files` (2.6 T1), so `th-namesqueue` runs in `make fleet`.

Check: before making a host tool a fleet rung, run it once in the container (`mx.sh sync && mx.sh run make -s <rung>`).
