# Substituting PsyQ objects for splat asm TUs in a splat link (mmx6 1.9 T4)

- Recipe, link: rewrite the splat ld script so that the TU's `.s.o(.text)` reads the converted vendor `.o(.text)`.
  Drop the asm .o from the link.
- Recipe, fragment: INCLUDE a generated fragment before `/DISCARD/`, or the fragment is discarded.
  The fragment places the object's other sections NOLOAD at bases solved from its relocations against the retail exe.
  It also holds the PROVIDEs. Expect `dot moved backwards` warnings.
- XBSS commons: psyq-obj-parser makes them WEAK symbols in one `.bss`. Psylink placed each one globally in another order.
  So no single bss base solves. Give each bss global its own address with a hard ld assignment.
- Jump tables in shared rodata still reference the removed TU's `jlabel .L<addr>` labels: PROVIDE each at the address its name spells.
- A vendor TU may already be a `c` subsegment (`build/src/<p>/<tu>.c.o`), not only `.s.o`.
- Some stub sets are identical under the relocation mask: LIBCD S_003/4/5, S_008/12/13, S_009/15, S_021/22.
  A masked text compare cannot tell them apart. The relocated word (the retail reloc target) decides identity.
- psyq-obj-parser refuses expression type 12 (`sectstart`/`sectend`, crt0 2MBYTE.OBJ). It has no option around it.
- `psyk <OBJ>` dumps (no subcommand). `psyk dump` errors.
- Fix for type 12: in a scratch copy of the OBJ, rewrite each sectstart (0x0C) or sectend (0x16) node into a symbol reference (0x02).
  Point it at a new XREF `__sdk_<op>_<section>`. Both nodes are 3 bytes, so no record moves. The ld fragment PROVIDEs the symbol (T4.c2, sdk.py `lnk_symbolize`).
- Stub identity fix in practice: 8 LIBCD gap rows were misnamed. Each slot had exactly one stub whose relocs land on the retail targets.
