# C0104 — Callee declaration is a lever: arity, return type, prototype vs unprototyped
tags: lever,prototype,callee,arity,return-type,unprototyped,m2c,regalloc · date: 2026-10-02 · phase/task: 1.8/T9 · origin: mmx6 W0

1. **Residual (tell)**: The draft has an extra argument-register load before a call. Or it truncates a value (`andi`/shift pair) before a call that the target makes with the raw value. Or it uses a different base register for stores right after a call. The suspect is m2c's guessed prototype.
2. **Mechanism**: The callee's declaration shapes the caller's RTL. Arity: a guessed argument is a real load that occupies the register the target keeps a constant in. Parameter types: a prototype with a narrow parameter makes the caller truncate. An unprototyped declaration (`f()`) passes the promoted int untouched. Return type: a non-void return adds a return-value set. This set moves register allocation of the values live across the call.
3. **Lever**: Treat each callee declaration as a variable. Try the card's consensus prototype, `void` vs `s32` return, zero arguments, and the unprototyped `f()` form. Keep the one that matches. A declaration different from the program's prevailing one surfaces at bank time as an R2 stop (declsync/cast recovery, docs/ops/campaign.md ## Recovery).
4. **Byte proof**: Manual wave W0 (1.8/T9) has these cases. The first is rock_03:0x800EEDB8 (callee `s32` not `void`, 55→57, probe 67/67). Its bank stopped R2 on the TU declaration conflict. The others are rock_03:0x800EE9C4 (no-argument callee, 208→253), rock_06:0x800ECE74 (unprototyped callee, 138/138) and rock_03:0x800EF1E8 (2-arg m2c call → 1-arg consensus, 37/37).
