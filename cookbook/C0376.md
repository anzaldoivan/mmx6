# Overlay breakpoints armed only while the member is resident

Problem: a Redux Exec bp at an overlay address fires for whatever member sits at that vram, so hits from another member pollute the count.

Move (tools/mmx6/redux/boot.lua, 2.6 T19.c1):
- Put a bp on BinSeek 0x80016858: a0 is the member index and a1 the dest. A load with dest in [base, base+size) clears residency. A load of the wanted member to base marks it pending.
- Residency turns on in the ready callback once the remaining-bytes word reads 0 (as in loads.lua). At BinSeek entry the bytes are not there yet.
- Create the overlay bps once. Call `bp:enable()` or `bp:disable()` through pcall on each residency change, because the method may be absent. The callback also checks the flag.
- For a dispatch `jalr` in a loop function, put the bp on the jalr pc. The delay slot sets a0, so read its source register (C0350).
- The `ra` at entry of a task-started function is not a call site (seen 0x0 and junk). Do not read it as a caller.

Trap: zero hits in the overlay do not mean "not reached". First a positive control in the same address range must fire. Use an always-run function or a range bp over code that certainly runs.
