# C0320 — Struct grown past its source-game size: rewrite (&g)[1].m strides as tail members
tags: struct,sizeof,stride,homed,tail,player · date: 2026-11-01 · phase/task: 2.5/T6 · origin: 2.5 T6.c1

Context: a struct homed from the source game (mmx4) grows to the X6 size. PlayerObj grew from 0xE4 to 0x158 for
the bytes that X6 readers touch past mmx4's end (2.5 T6.c1, include/mmx6/player.h).

Trap: code that reaches past the object through the old size, as `(&g_Player)[1].active`, strides by sizeof.
Once the struct grows, the offset in the store changes (`sb zero,0xE4` became `sb zero,0x158`) and the unit
fails. Six such stores in rock_03 and rock_08 failed fleet-quick. Nothing else moved.

Move: rewrite each `(&g)[1].m` as the new tail member at that offset (`g_Player.unkE4 = 0;`). Bisect first:
remove the tail, fleet-quick green, so the growth is the cause. Then objdump-diff the failing unit's object to
list the stores that moved.

Check:
- `grep -rn '(&g_Player)\[1\]' src` is empty after the rewrite.
- fleet-quick is green.
- The typecheck self-test asserts the new sizeof.
