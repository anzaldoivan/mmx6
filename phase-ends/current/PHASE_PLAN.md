## Rationale
- Order: instruments first (T1-T5), then free lanes (T5 first cracks, T6-T8: zero or near-zero tokens, DK-40), then the paid manual wave that measures the cliff (T9), then four leverage-first waves (T10-T13), then the ledger closes (T14). Every wave is one task so the harvest gate (G45) is a task boundary the router cannot skip: T<n+1> deps T<n>, and draw.py refuses a draw without the previous wave's `HARVEST GATE OK` stamp.
- "Stub" (milestone) = an asm or include_asm function (report.py TODO states, report.py:16/:39) with no row in `campaign/ledger.tsv`. census.py gains one line `CENSUS stubs <s> of <a> asm functions (ledgered <l>)`; report.py's empty-body count keeps its name (renaming it would churn 1.5-1.7 records for nothing). Matched stays `c`/`c-empty`.
- Ledger (`campaign/ledger.tsv`, tracked; names, addresses, numbers, our draft paths only, never bytes, G12): one row per asm function `<prog> <vram> <func> <class> <closeness> <best draft> <blocker>`. class ∈ `dup:<key>` | `family:<key>` | `twin:<pv>` | `x4` | `vendor:<lib>/<obj>` | `unique`; closeness = masked `m/n` of the best draft (probe/permuter scorer) or `nocompile`; best draft = a tracked `drafts/<prog>/<func>.c` or `m2c` (regenerable by the pinned scaffold, never tracked); blocker = a named cause from a closed vocabulary written to docs/ops/campaign.md `## Ledger` by T5: `plateau:<label>` (plateau.py), `wall:<pass>` (walls.txt row), `vendor` (G56, lib object), `jtbl-uncarved`, `opt-mismatch`, `member-of:<pv>` (waits on its class exemplar), `undrawn` (never drafted by an agent; closeness from the scaffold lane). `ledger.py --check` refuses a row outside the vocabulary, a missing asm function, a C function on the ledger, a best draft that fails verbatim.py. `undrawn` is honest and counted on its own line (`LEDGER blockers … undrawn <u>`); whether 1.8 may close with u > 0 is the developer's (## Developer decides).
- Scaffold lane (T5) is the free first crack: decompile.py (m2c) every asm function, compile through the product rule, score masked; a score-0 scaffold goes to bank.py (G61: only the whole-binary hash banks), then propagate. It also gives every function a closeness for the ledger and the leverage rank. Detached run (`run.sh --bg`), resumable, one result row per function in `build/scaffold/scaffold.jsonl`; est. 8000 × ~1-2 s.
- Leverage-first (draw.py `--rank leverage`): targets ordered by payoff = words × (1 + gated-able members across the fleet via dup/family registry and exact twins), ties by closeness then (prog, vram); one member per twin component per wave (C0074). `--band <lo>-<hi>` filters by words once T9 records the routing set.
- Routing with one model tier: the card fixes Opus 5.5 for every coder, so the "routing set" is not a model ladder; it is (a) which word bands go to paid drafting, (b) the per-card turn/attempt cap by band (G39), (c) which bands go straight to the permuter lane or the ledger. T9 measures bank rate by instruction count on 12-16 targets spanning ≤16, 17-40, 41-80, 81-160, >160 words (C0006); the routing set is written to docs/ops/campaign.md `## Routing` with n per bin, and draw.py reads it from `config/routing.txt`.
- Wave size (Max 5x, G39): 16 cards, ≤ 4 coders concurrent, one coder run per card plus at most one retry inside the band cap; a harvest workflow counts against the 4. A wave ≈ 16-30 coder runs. Breadth fan-out is named here (card: welcome when the plan names it): the wave expert spawns coder-opus55 per card in the background and never drafts itself.
- Drafter contract (G47 inside the harness contract): the coder writes `draft.c` into its pack first, re-writes it on every improvement, writes `verdict.json` last (`{"pv","status","score","lever":"<diff path>|-","notes"}`); its harness return stays the coder contract. The gate scores the directory, never the returns (G50), so a dead coder's draft is still scored.
- Gate (T3): standalone masked probe per draft, verbatim check, then bank.py serially per binary (bank.py edits the tree and rebuilds the whole binary); different binaries gate concurrently in isolated container work dirs (worktrees, C0004) with a per-binary lock, ≤ 3 at once. Plumbing vs body (G50): probe MATCH but bank stop R1-R4 = plumbing → recovery re-runs the ladder with declsync/`--define` variants, no redraft; probe FAIL = body → plateau label + journal. A fleet run from a clean rebuild after every banked batch (milestone).
- Harvest (T4, G45): live/inert check by reverse-applying the coder's lever diff and recompiling (about one in three credited levers is inert); live levers → cookbook via cookbook_add.sh with a byte-proven pair (G108) or a journal note why not; a mechanical idiom becomes a sweep script `tools/mmx6/sweeps/<id>.py` run over ledger best drafts of the same plateau label; widening review = census/report/draw denominators before vs after, written to the wave's journal record. `harvest.py --gate W<n>` stamps `campaign/harvest/W<n>.ok` only when all three hold.
- Journal (`campaign/journal.jsonl`, tracked, append-only): one record per attempt `{wave, pv, func, words, band, runs, verdict, score, label, draft, lever, notes}`; notes are our prose (≤ 400 chars). Read side: cards.py puts a function's past records on its card (DK-32); `--rate` prints the bin table.
- Packs: `waves/W<n>/<prog>_<func>/` with card.md, scaffold, ctx header and the target asm (generated; asm is game-derived, never tracked, G12). T2 decides where packs and drafts live so both the Mac (coders edit) and the container (gate compiles) see them across `mx.sh sync` without a sync wiping a concurrent gate, verified by a control, recorded in docs/ops/campaign.md; `.gitignore` gains the pack path.
