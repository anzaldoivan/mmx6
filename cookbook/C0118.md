# C0118 — Struct-typed self/parent pointers let sched1 hoist global loads above self stores
tags: lever,sched1,alias,struct,self,mem · date: 2026-10-04 · phase/task: 1.8/T10 · origin: mmx6 W1

1. **Residual (tell)**: retail loads globals before the stores through `self`; the draft keeps them after the stores (length differs, wrong order).
2. **Mechanism**: observed. With `self`/`parent` typed as a struct pointer, the stores are in-struct MEMs that sched1 can prove do not alias the global loads, so it hoists the loads; through `void *`/byte offsets it cannot.
3. **Lever**: type `self` and `parent` as pointers to the object struct (field access, not M2C offsets). Related: C0105.
4. **Byte proof**: wave W1 (1.8/T10), rock_08:0x800F0BD4 362 → 442/448 words, length fixed (phase-ends/phase-1.8/tasks/T10.md:28).
