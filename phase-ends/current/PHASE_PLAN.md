## Rationale
- Order: T1 first — the rock_17/43/45 defect makes the first oracle blind on 163 functions; every count after it would carry the hole (G22: fix the instrument before trusting its measurement). T2 (corpus oracle) is the one function inventory every later tool derives from (G20); T3 retrofits the existing scanners against it; T4/T5 the second oracle; T6/T7 census and reports; T8 the harness and the schedule closes the phase.
- One inventory, many readers: corpus.py writes `build/corpus/functions.jsonl`; optscan, census, reports and the harness read it instead of re-parsing asm (G20). optscan keeps its own parser on purpose so harness pair P4 compares two independent counts.
- Denominator "from the build" = linked `.text` bytes per program read from the build outputs (`build/` ELF/map), never a typed number (G27, G31). Coverage assertion = function bytes + classified non-function text spans (jtbl, padding, lib gap, data-in-text) == text bytes, per program; a gap refuses (G19, G28).
- Phantom / truncation defined mechanically (T4): phantom = an inventory function whose start the second oracle places strictly inside another function, or that no second-oracle start, jal target or post-return boundary supports; truncation = any second-oracle function byte not covered by exactly one inventory function, or an inventory extent ending before the second oracle's trimmed end. Reaching 0 is by fixing the side the bytes prove wrong; an exception ledger row needs a closed-vocabulary basis class and byte evidence, and is counted and printed (never silent) — G35, never redefining the term to pass.
- T5 is `review: yes`: the ledger decides what "0 phantoms" means for 1.6's propagation and 1.8's routing; the developer sees the classes once before it binds. Every other task closes on its gate.
- Census measures: dup = sha1 of masked words (relocation fields masked exactly as probe.py does, C0038); families = sha1 of the opcode skeleton (registers, immediates, reloc targets masked); reach = number of programs holding a member of the class; size = instruction count; unique tail = functions in no dup class and no family of size ≥ 2. Known-true controls: the empty-body class (`jr ra; nop`) must equal the corpus empty-body count (282 today, a build-derived number), plus planted pairs in `--self-test`.
- Harness pairs (DK-9, chosen for 0%): P1 matched? (source scan vs object FUNC symbols, set equality); P2 compiles? (probe.py standalone vs linked-binary bytes for each non-empty banked function); P3 fleet green? (clean hashes vs incremental rebuild after touching one C and one asm unit); P4 coverage? (optscan per-program count vs corpus); P5 boundaries? (corpus vs bound2); P6 programs? (config/*.yaml vs loadmap N vs config/ghidra/*.jsonl); P7 stubs? (corpus empty-body count vs census empty class). `agent produced work?` is harness territory and `bankable?` is vacuous before a wall oracle — omitted. Each pair has a planted-disagreement self-test (G25).
- Schedule: `make fleet` runs the sampled `tools-health` inside `health` before fleet.sh prints `FLEET`, so every gate run is a scheduled harness run and leaves an evidence line in `build/harness/runs.log` (G30); `tools-health-full` is the exhaustive form behind its own name (docs/decomp-architect.md:204-206). P3 runs only in `-full` (cost).
- Coder tier opus55 everywhere (one tier). No `effort: high`: preset max5 has no hard rung; the judgment-heavy part (boundary adjudication) is split into T4 (tool, mechanical) and T5 (fixes + ledger, reviewed).
- Container work: every tool runs under `mx.sh run`; scratch in the container's `.run/` (skill container-scratch-not-synced); outputs return via `mx.sh pull`. Long gates via `run.sh --bg/--wait`.
