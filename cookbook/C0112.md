# C0112 — Volatile read on a join test keeps the reload and stops jump threading
tags: lever,volatile,cse,reload,jump-threading,join,flags · date: 2026-10-03 · phase/task: 1.8/T12 · origin: mmx6 W3

1. **Residual (tell)**: A flags test guards an optional call. After the call, retail reloads the flags at the join, and the branch keeps its delay-slot nop. The draft reuses the value loaded for the test (or threads the jump past the second test).
2. **Mechanism**: This is observed, not source-proven. If no store intervenes on the fall-through path, cse/gcse treats the second read as redundant with the first. Jump threading then merges the two tests. A volatile-qualified read on the first test is never a cse source. As a result, the join reload survives and jump threading does not thread the branch.
3. **Lever**: Read the flags through a volatile cast on the test before the optional call (`flags = FLAGS; ...; if (*(volatile u8 *)&FLAGS == 0) call(self); f = FLAGS;`). If a move/extend pair is still off, spell the reload as `s16 f = (u16 g = flags)`. Then test `g` (plain move, no extra extend). If the volatile read is a short, combine this lever with C0089.
4. **Byte proof**: In wave W3 (1.8/T12), rock_09:0x800EA178 is at 150/150 on attempt 1 (banked).
