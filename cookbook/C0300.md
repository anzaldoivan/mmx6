# splat writes nonmatchings asm only for INCLUDE_ASM in the unit file itself

- splat 0.50 (`segtypes/common/c.py`, scan :131-145, split :236-270) reads only `src/<prog>/<tu>.c`.
- It writes `asm/<prog>/nonmatchings/<tu>/<f>.s` only for INCLUDE_ASM lines in that one file. Lines in an included
  role file are invisible to it, and the build then fails with `can't open .../<f>.s`.
- Fix (2.4/T15.c1): `tools/mmx6/splat_closure.py split config/<p>.yaml`. It patches splat's three scanners to read
  the unit's `#include "*.c"` closure, then runs splat's own main. The Makefile split rule calls it.
- Rejected: `disassemble_all`, because it also writes `asm/<bin>/matchings/*.s`, which `O_FILES` links.
- Neutrality check: the linker inputs splat writes (`build/*.ld`, `undefined_*_auto`) are byte-identical to plain splat.
- A tool that treats every `src/<prog>/*.c` as a unit counts role files as units. Read `config/c_units.txt` instead.
