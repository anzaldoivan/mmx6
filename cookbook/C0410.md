# C0410 — A dead global read in retail: an if/else on it with equal arms, and an untyped store keeps order
tags: lever,dead-read,if-else,equal-arms,volatile,pc-port,union,store-order,sched · date: 2026-11-07 · phase/task: 2.7/T9 · origin: mmx6 T9.c4 func_8002234C

1. **Residual (tell)**: Retail reads a global (here `g_wide_mode`) and never uses the value. The read is a dead `lhu` into a hoisted reg. The draft has no such read, and its block start is several words off.
2. **Mechanism**: The source tests the global in an if/else. Both arms store the same constant. gcc 2.95 folds the arms into one store. The volatile or hoisted read of the test stays.
3. **Lever**: Write the equal-arm if/else that the PC port's /Od code shows. Both arms of the `g_wide_mode == 0` test store 0x1F00 to `unk40`. Do this in every block that has the dead read.
4. **Byte proof**: 2.7 T9.c4, func_8002234C. The block start became exact, and the T27 volatile hacks were dropped. Final MATCH 315/315 came after C0107 per-arm stores and an untyped `s32` store (item 5).
5. **Companion lever (same function)**: The draft stored through a union member (`obj->x_pos.val`) next to a direct global read. Sched then hoisted the load above the store. dbr then put the store in the delay slot, one word short. Storing through `*(s32 *)((u8 *)obj + 8)` kept retail's order: 60 -> 306.
6. **Related**: C0406 (PC pairing: the PC /Od shape keeps arms that gcc folds), C0107.
