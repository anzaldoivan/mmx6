# C0431 — Time make rungs as sub-make goals, because interleaved prerequisites ran out of order (make 4.3)
tags: make,timing,tools-health,fleet,wall,order · date: 2026-11-08 · phase/task: 3.0/T3 · origin: mmx6 T3 rung walls


Problem: to print a wall per tools-health rung, each rung r was interleaved with a marker target th-time-r
(`tools-health: th-time-start r1 th-time-r1 r2 th-time-r2 …`). The Makefile has `.SECONDEXPANSION:` (mmx6
Makefile:109) and the make is GNU make 4.3. Every rung ran first and every marker after the last rung. The first
marker got the whole 826 s, every other one 0.1 s. That was true both for an implicit `th-time-%: %` and for a static pattern rule.
`make -n` shows the same order, so it costs seconds to check.

Fix: give the timed list to a sub-make as goals. Make runs command-line goals in order, and each phony target still
runs once:
    tools-health:
    	@$(MAKE) --no-print-directory $(call th_timed,$(TOOLS_HEALTH_RUNGS))
Check with `make -n tools-health | grep -n "date +\|TH-WALL\|<first rung's tool>"`. The marker must come right
after its rung.

Do not instead run one sub-make per rung (`for r in …; do $(MAKE) $$r`): phony prerequisites like th-corpus would
re-run for every rung that depends on them.

Origin: mmx6 3.0 T3 (mk/tools-health.mk th-time-*, run logs t3-fleet1 vs t3-fleet2).
