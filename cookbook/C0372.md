# C0372 — permute.py target overshoots in a one-function C file: run the pinned original as a 0 control first
tags: permuter,probe,extent,control,find_extent · date: 2026-11-03 · phase/task: 2.6/T15 · origin: mmx6 T15.c1

`probe.find_extent` ends a C function at the next start among `asm/` labels and names defined in its own .c file. A one-function C file (e.g. cling/enter_wall_cling_8003B3B8.c) has no neighbour there. C neighbours in other files are not counted. The retail target then overshoots (603 words for a 33-word function). permute.py's score is then mostly the length difference. Address-named `func_*` functions not in config/symbols need build/corpus/functions.jsonl (built by th-corpus after a linked build) or probe fails `not found`.

Before trusting any permute.py base score, run the pinned, matching original as the draft for a few iterations: it must score 0. A nonzero control means the target, not the draft, is wrong.
