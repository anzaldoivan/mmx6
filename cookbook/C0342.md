# Fixing `LAYOUT CHECK cite-anchor` drift: map the line through git

Problem: a cite `<path>:N via=<a>` stays valid as a path, but line N no longer holds `<a>`.
Header and banner lines shift every later line of a file (2.5 T12 cleared 142 such defects).

Move: for each defect, find the newest git version of the cited file where line N still held `\b<a>\b`.
Take that line's text, then find the one current line with the same text that also holds the anchor.
Rewrite only N (and M of `:N-M`). A digit-stripped diff of the config files must then be empty.
When the text occurs more than once, keep the same occurrence only if all occurrences moved by one amount.

When the cited line is gone (the body was rewritten), pick the line of the function that now uses the anchor.
Example: `object_slot.c:9 via=arg0` became `:8`, the body's one use of arg0.

Check: `layout.py check` (no --prog) ends `LAYOUT CHECK 0 defects`, rc 0. There is no "LAYOUT OK" string.
See also C0310 (repoint a cite to a renamed file from the blame commit).
