# C0135 — Sweep statement order for L07 store-order and register-name residuals. Retail's order is not the answer
tags: lever,L07,sched,store-order,permutation,sweep,regalloc · date: 2026-10-04 · phase/task: 1.8.1/T5 · origin: mmx6 W5

Symptom: plateau gives `sched residual` (L07). The same-base stores are in a different order than retail, or an otherwise identical stream has a register-name mismatch. Examples: lui/addiu pairs that take v0/v1 in reverse, a0/a1 on a call arg, an s-register swap between long-lived locals.

Mechanism: gcc 2.95 sched1 tie-breaks independent same-base memory ops roughly inversely to source order. Statement order also changes insn luids and so global-alloc live lengths. The winning source order is often not retail's emitted order (m2c gives the emitted order).

Lever: sweep instead of reasoning. If two stores are swapped, swap the lines first. Otherwise, do an exhaustive permutation of the arm's 2-4 stores (≤ 24-36 variants, per arm independently). Then do single-line-move sweeps (one statement to every slot). These sweeps found orders that full permutations missed. The plateau.py script costs ~2 s per variant and no probe-cap runs.

Evidence (phase 1.8.1 T5): c15 c17 c36 c42 c54 c62 c65 c68 (logs/T5.c<k>.md). 1.8 T13 rock_11:0x800EAF90 (48-variant sweep).

Limit: order, volatile chains, struct typing or temps did not move a byte-constant store that landed one slot early (c44). For those cases, escalate (permuter).
