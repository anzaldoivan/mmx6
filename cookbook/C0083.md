# C0083 — Cross-jump: a fall-through arm ending in a call never merges. A store tail merges the call
tags: idiom,sym-cross-jump,G-jump,jump2,cross-jump,call · date: 2026-10-02 · phase/task: 1.7/T5 · origin: mmx6 repro

1. **Residual (tell)**: an if/else calls the same function in both arms with two `jal`. At that place, the target has one shared `jal`, and each arm sets only the argument (or the reverse). `sym-cross-jump`
2. **Mechanism**: jump2 (G-jump). Its cross-jumping walks back from the arm's jump and from its label while the insn codes match. The flow pass ends a block that ends in a call with `(use (const_int 0))`. Thus a fall-through arm ending in a call never matches. This is the call veto.
   - src:gcc-2.95.2/gcc/jump.c:1974 "find_cross_jump (insn, JUMP_LABEL (insn), 1,"
   - src:gcc-2.95.2/gcc/jump.c:2871 "GET_CODE (i1) != GET_CODE (i2))"
   - src:gcc-2.95.2/gcc/flow.c:605 "rtx nop = gen_rtx_USE (VOIDmode, const0_rtx);"
   - a-side `.jump2`: `(use (const_int 0 [0x0]))` is before the join label.
3. **Lever**: the place where you write the shared tail. `if (a) g(1); else g(2); G = 3;` gives two `jal`. With `if (a) { g(1); G = 3; } else { g(2); G = 3; }`, the store and the call merge, which gives one `jal`. A call-only shared tail (`g(3)` in both arms) never merges (observed, scratch).
