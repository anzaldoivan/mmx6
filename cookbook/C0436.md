# Feed a twin whose shared path is a multi-function role file or unit: extract, probe via the unit

Context: the registry shared path (col 3) is a role file `src/<prog>/<x>.c` that opens with INCLUDE_ASM before
`#include "common.h"`, or it is a whole unit. R1 standalone gives `parse error before string constant`. Feeding it
whole gives gas `symbol ... is already defined` (a same-program member, or the other program's `.L` asm labels).

Move (bank.py/propagate.py `--repair rolefeed`, 3.1 T4.c1):
- Extract the exemplar's layout.locate range to layout.new_body (src/shared/<prog>/<func>.c). `#include` it back at
  the same spot.
- Check every including unit's object text byte-equal before and after. Do not use xkey_guard here, because its
  registry filter skips planted paths.
- R1 runs through the including unit itself (its own CFLAGS), exemplar-name words against the member's retail words,
  relocs masked. No defines wrapper: a same-unit member's renamed definition collides with its own INCLUDE_ASM.
- First line of the body `// rolefeed (3.1 T4): <ex func> of <unit>` makes R1 probe via the unit even with the
  switch off, so a banked member re-gates without drift.
- R2 feeds the body only. Never run it on the exemplar's own re-gate, or every exemplar gets extracted.
- A new src/shared body needs no config/layout.tsv row (layout.py check is silent). An R2 block in a role file shifts
  lines and breaks config/ghidra cite anchors.

Result: rock_08 path 11 -> 0 (declaration 7: fed body lacks the role file's declarations, reloc 5).
