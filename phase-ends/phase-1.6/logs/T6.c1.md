## splat behaviour found
- Rodata pairing needs the dot type: `[off, .rodata, <tu>]`; plain `rodata` with a c sibling is a splat error (splat/segtypes/common/c.py:183-197). Brief wrote `rodata <tu>`; emitted `.rodata`.
- Linker script places `build/src/SLUS_013.95/32208.c.o(.rodata)` at the carve; 32208.c.o `.rodata` = 0x1c bytes (= table size); 120A0.c.o has no rodata.
- splat migrated jtbl_80011378 into `nonmatchings/32208/func_80033E00.s` (`.section .rodata` + dlabel, then `.section .text`), NOT func_800328B0: the boundaries.txt row's func column (0x800328b0) is not the referencing function (lui %hi(jtbl_80011378) at 0x80033E3C in func_80033E00). Both are in 32208, so the carve is right; but carve.py trusts the func column — gotcha generalizable: a jtbl carve whose func column names the wrong TU would fail only at the hash gate. Fix candidate: derive the dispatcher from the %hi/%lo reference, not the row.
- splat writes nonmatchings only for INCLUDE_ASM names in the c file (`global_asm_funcs`), so the folder rewrite in the moved tail is what makes 32208 .s files appear.
