# s-reg swap against a block-0 `%hi` pseudo is a local-alloc priority tie: move that global's first use in the store block
- Case T27.c3 func_8001AE44 (208 w). The pin-free draft was 195/208 with an s2/s3 swap: the arg1 copy against `%hi(D_800E2EC0)`. About 10 T26.c4 levers were inert (local copies, store order elsewhere, a pointer local, `u32`).
- Mechanism: local-alloc priority is refs/(death-birth). The `%hi` pseudo's birth is set by the first use of that global in the store block.
- Fix: move the two `D_800E2EC0[0..1]` stores up to just after `sp20 = 0x148`. Read the pseudos with alloc_table.py, then sweep the position of that one statement. MATCH with no pins (replaced 2 `register asm` pins).
- Trap after a probe MATCH: the in-place build stayed R5, 2 words off, because probe masks `%hi`/address halves (C0388). Two `sw zero` stores to different globals were in the wrong order. Swapping them (`D_800E2EB0 = 0` before `D_800E2F2C = 0`) gave the hash green.
