# Gate rodata recovery writes several carve files: pull all before sync
- A gate rodata recovery rewrites the carve record, the per-program config yaml, the carve txt and mk files, and the symbols file. The carve_files list of the gate spans all of them.
- Pull every file that the recovery wrote (from the journal or the registry) before any sync. Otherwise the next tree build is hash red for that program.
- Alternative: regenerate the program yaml from the pulled carve record with the segmenter.
- A jump-table carve row turned into a rodata row leaves the boundaries row looking uncarved to the carve self-test. Fix both rows in the same change.
