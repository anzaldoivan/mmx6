# C0202 — Dead store to the original keeps a loop base copy gcse would propagate

# A dead store keeps a separate copy of a loop base that gcse would otherwise propagate

Symptom: a later loop wants its own copy of a base pointer in a different register (retail re-copies the base). But gcse propagates the original pseudo and the copy disappears. The allocation of the earlier loop also differs (pseudo count).

Lever: copy the base to a new local (`q = flags;`) after the loop counter reset. Then add a dead store to the original (`flags = 0;`), so that the copy cannot be propagated away. Spell the indexed load as a byte offset, `*(s32 *)((u8 *)q + (i << 2))`, for retail's add operand order.

Seen: W25 rock_16 E99A4 (retry c59 of c26, 85/85).
