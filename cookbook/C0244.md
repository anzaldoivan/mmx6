# depin.py parallel throughput on the 8-CPU / 8 GB Docker VM

When: sizing a depin sweep (how many xargs workers, how many parallel coders/volumes).

Measured (1.10/T2.c1, 12 SLUS_013.95 functions, 45 pins, step logs .run/1.10/depin/measure/):
- One trial per pin. N=1 1.20 s/pin, N=2 0.77, N=4 0.54, N=6 0.48 (speed-up 1.56 / 2.23 / 2.49).
- One depin run uses ~1.5 cores (cpp|cc1|maspsx|as under amd64 emulation). CPU saturates ~900% at N=6. N=4 is the knee.
- memory ~60-80 MiB per worker (378 MiB peak at N=6): memory never limits W on 8 GB.
- Disk: the volume after extract+build+corpus is ~660 MB. Each concurrent depin snapshot adds ~38 MB real (du over-counts hardlinks) and self-cleans.

So: W=6 workers in ONE volume. A second coder/volume costs a full extract+build (~3+ min) for no CPU left to use.
Hundreds of pins are minutes of depin. The build and its hash check dominate a batch.

Driver: `xargs -P N -L1` over "prog:0xVRAM src" lines. One function per src file, so jobs never share a --src.
mx.sh sync ships only tracked/unignored files: pass a .run/ scratch script as `mx.sh run bash -c "$(cat script.sh)"`.
