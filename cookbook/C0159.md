# A field copy whose load precedes an unrelated store: read it into a local before that store

Symptom: the target loads a field before an unrelated store (the store fills the load delay). Our build loads after the store.

Lever: read the value into an s32 local before the intervening store. Then store the local where the copy happens. Through same-type char/void* views, gcc will not move the load past the store itself.

Evidence: W12 rock_15 EC478 (c54).
Related: C0139 (dead-store and alias ordering), C0142.
