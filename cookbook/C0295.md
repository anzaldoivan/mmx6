# C0295 — A file's program comes from all its including units (layout.includers), not the first or the path
tags: layout,includers,program,namesqueue,renamecov,role · date: 2026-10-31 · phase/task: 2.4/T6 · origin: mmx6 T6.c2

Problem: a tool that gets a file's program from its path (src/<prog>/…, src/shared/<prog>/…) must change once files sit
in role dirs. Taking the first including unit in c_units order is wrong for 17 shared files. The path names the program
that first matched the body, which is not always the first includer.

Move: use layout.includers(root) (file -> [(prog, tu)] over the units' include closure). Take the programs of all
includers as a set, or pick the includer whose symbols file holds the name. Files outside every closure keep the path rule.

Check: compare old vs new output on today's tree byte for byte (names-queue.tsv, renamecov collect()) before the change lands.
