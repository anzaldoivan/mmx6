# Header-level declaration of a function: one spelling for the symbol and its relocdef aliases, or none

Problem: a fed shared body declares the exemplar's name (func_800F82C0), relocdef renames it to the member's
(func_800F6FC8), and it conflicts with the member unit's line. A per-unit fix cannot cure that (C0434).

Recipe (3.3 T5.c1):
- The class is the symbol plus every name joined to it by `A=B` define tokens in config/dedup_registry.txt.
  Rewrite every declaration line of every name in the class to one spelling, homed in a header with its evidence.
- Params: unprototyped `()` fits every caller's arity (cures "too few arguments") and changed no bytes here.
- Return type steers the caller's register allocation after the call (void frees v0: `lbu v1` becomes `lbu v0`).
  Pick the return type that reddens the fewest functions, then restore each red caller with a function-pointer
  cast at the call: `((void (*)())f)(x)` or `((s32 (*)())f)(x)`. It still emits `jal f` (C0377, C0403).
  Find the red functions by comparing every object's sections against a green snapshot, not by the hash alone.
- No spelling exists when two definitions in the class disagree on return type (void in one unit, s32 in
  another). Either type gives `conflicting types` at one definition. The class waits for a definition-level decision.
- Results: g_Player (struct, no casts), func_8002F288+func_8002CB50 (s32, 4 void casts), move_object (void,
  1 s32 cast), func_80030ECC (s32, none) landed. func_800F6FC8, clear_object_slot, animate_object had no spelling.
- Each homed placeholder-named line adds 1 to placeholder-use. Rewritten local lines net 0.
