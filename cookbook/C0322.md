# C0322 — Prove a data block's extent from the asm: loads off one symbol's %lo base are its members
tags: struct,extent,bss,data,asm,base-register,members,homed · date: 2026-11-01 · phase/task: 2.5/T7 · origin: 2.5 T7 expert

Use: deciding where a BSS or data block starts and ends before homing a struct. It tells which D_ placeholders are members.

1. With `-G0`, gcc 2.95 addresses a global as `lui` plus `%lo(sym)`. It never reuses one symbol's `%lo` base for a
   different global. So `addiu $r, %lo(D_X)` and then `lb N($r)` (or any load or store) is a reach through D_X.
   The offset +N is a member of the block that D_X heads.
2. Scan the split asm. After each `addiu ... %lo(D_X)`, take the loads and stores off that register until it changes.
   Count the `op offset` pairs. Run the script as `mx.sh run bash -c "$(cat script.sh)"`. Stdin does not pass.
3. The largest offset reached bounds the block from inside. A placeholder never reached through the base is outside.
   This holds even when it sits next to the block. Placeholders below the head belong to the symbol before it.
   Check that symbol's start and size in the symbols file.
4. Example (2.5/T7): 24 functions reach +4, +6 and +7 off the D_80097420 base. The main loop increments the s32 at +0.
   So it is one 0xC block, the mmx4 MainBssState. D_800970A5..D_80097206 lie in g_Player and background_objects.
   Nothing reaches 0x8009742C or later through the base.
5. The asm proves membership, not names. The names come from the mmx4 layout at the pin and from our readers.
