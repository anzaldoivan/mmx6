# Fold the load into the compare: if (g < (t = tbl[i])), if (++field == 50)

Symptom: a global and a table byte in a compare take swapped registers (L07 sched), or an incremented u16 counter keeps an extra zero-extend before its store.
Cause: the compare's operand order and the expression tree decide load order and the mode of the stored value.
Lever: write the later-loaded value as an assignment inside the compare, `if (D_x < (t = tbl[idx]))`, so the global is the left operand and the byte is loaded last; spell a counter test as a pre-increment of the s16 field inside the compare, `if (++field == 50)`, instead of an m2c u16 temp.
Evidence: W16 rock_11 F95C4 (62/71 to match; a pointer local to the global also closed it), rock_09 F45C0.
Related: C0151 (compare operand order follows the spelling), C0146.
