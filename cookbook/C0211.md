# Three-temp register rotation that will not close: add a 4th coalescing block local

Symptom: inside one block, gcc 2.95 local-alloc sees exactly three quantities. It assigns them in a fixed exchange
sequence. The draft's three temps come out rotated against retail, each in the next one's register. No reordering of
the three statements changes it (18 probes in W45).

Lever: add a fourth block local of the narrow type. It takes the chained assignment and is then copied to the
existing temp: `{ u8 l; F0 = l = G; v = l; F2 = v; }` instead of `F0 = v = G; F2 = v;`. The extra quantity coalesces
away in the output but changes local-alloc's ordering, closing the rotation.

Related: C0179, C0209 (pinned block locals). Origin: W45 SLUS func_8001B984 (c34 narrowed retry after c23 23/32).
