# C0400 — Two hoisted %hi pseudos tie in greg: symbol names order them via the gcse hash
tags: regalloc,gcse,greg,hi-lo,hash,names,lever,dumps · date: 2026-11-07 · phase/task: 2.6/T30 · origin: mmx6 T30 func_80013DE8
Lever (mmx6 2.6/T30, func_80013DE8, 419 -> 421/421). gcc 2.95.2 -O2.
- Shape: two globals' `%hi` are partially redundant. Both arms store them and the join reloads them.
  gcse PRE hoists both `lui` above the branch into new pseudos, with equal refs.
- greg (global.c allocno_compare) orders them by refs/live-length, then by allocno number (= pseudo number).
  The first allocated takes the lower reg ($t0).
- gcse pre_delete creates the reaching regs walking the expr hash table bucket by bucket.
  A SYMBOL_REF hashes on its name's characters (`h += (h << 7) + *p`), table size n_insns/2.
  So the symbol NAMES decide which pseudo is numbered first, and who wins a live-length tie.
  Declaration order is inert, because the hash is not on the pointer.
- Find it: run `dumps.py --src` on both spellings. Grep `high:SI (symbol_ref` per pass.
  Compare the greg line `regs to allocate` and the lreg lines `Register N used R times across L insns`.
- Fix: spell the reloads in retail order so live lengths tie, then try the canonical names.
  Here `g_tilemap_width`/`g_tilemap_height` matched where `D_800CD338`/`D_800CD339` gave 415.
- Names are then byte-relevant. Re-probe after any rename, and gate packs carry the final names.
