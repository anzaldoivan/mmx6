# C0473 — sched1 boosts an insn that sets its pseudo once: give the local a second value to drop the boost
tags: lever,sched1,priority,birthing,local-reuse,reload,regalloc,v0,dumps · date: 2026-11-15 · phase/task: 3.2/T6 · origin: mmx6 T6.c9 func_8004A768, T6.c7 func_800404D8

Symptom: retail's reload or temp register avoids v0, but ours lands in v0.
Or a narrowing or constant insn sits just before a jump, far from where retail has it.

Mechanism (dumps, sched1): the old backward scheduler gives top priority to an insn that is the only set of its pseudo.
That "birthing" insn moves toward the block end, so v0 is already dead when reload runs, and reload picks it.

Lever: reuse one local for two values, for example one `s16 e` for both width differences instead of `d` and `e`.
With two sets the boost goes away, the insn stays in place, and the register choice follows retail.
The same move keeps a constant out of a merged store: `k = 7; ... field = k;` with `k` set elsewhere too (C0451).
The opposite case is C0471: a constant built as two sets of one pseudo gets no boost and drifts up.

Evidence: 3.2 T6.c9 func_8004A768 138/140 to 140/140 pin-free (probe 7).
3.2 T6.c7 func_800404D8 133/202 to 200/202 with a reused `k`, then 202/202 with C0404.
