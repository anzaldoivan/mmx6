# Re-split a carved function as data: drop its ledger row with ledger.py --drop-gone

When a "function" turns out to be data (C0228), it is re-split as a data subsegment.
The corpus then loses that address, and th-ledger fails `LEDGER BAD <prog:vram> not-in-corpus`.
No older mode repairs it. --drop-banked drops only `c-function` rows, and --reconcile only reports.
--build rewrites hundreds of lines and sets pins to `?`.

Path (T32.1, rock_55 0x800FA92C):
1. config/<prog>.yaml: add `- [0x<off>, data, <NAME>]` (C0494). Remove the INCLUDE_ASM and its clang-format off/on from src.
2. `mx.sh sync && mx.sh run make fleet`: the fleet goes red on th-ledger alone, with `not-in-corpus` (expected).
3. `mx.sh run python3 tools/mmx6/ledger.py --drop-gone`: it prints `LEDGER DROP-GONE <prog:vram>` for each row,
   then `LEDGER DROP-GONE <k> rows dropped, <n> kept`. Every other line stays byte-identical. It refuses on an empty corpus.
4. `mx.sh pull campaign/ledger.tsv`. `git diff --stat` shows exactly k deletions, and `ledger.py --check` gives LEDGER OK.
5. Run the fleet again, then commit before any shards. A yaml edit is an ALL trigger (R250).
Run --drop-gone only after a fresh fleet, because a stale corpus would drop live rows.
