# Proto-only functions: census the build side, pair in order between held anchors

Problem: a retail-indexed proto oracle (retail fn -> proto addr, masked match) never lists what the proto has that retail lacks.

Move (tools/mmx6/protodiff.py, 2.2 T6.c1):
- Proto starts = jal targets, post-`jr ra` starts with a stack prologue or a pointer word/lui pair, held anchors, and the word after each held body.
- Window = retail's text range, carried over by the outermost anchors. On retail this rule finds 8433 of 8534 starts, 140 extra.
- Every oracle row with an address is an anchor, `run` rows with places>1 too.
- An unheld retail fn whose masked body occurs once in its gap becomes an extra anchor.
- These two took the near-identical build (10-30) from 979 false rows to 8.
- Per gap: order-preserving DP on masked difflib ratio, threshold 0.6. Paired = changed (size delta), unpaired = absent.
- Threshold evidence: non-corresponding same-unit pairs reach p99 0.611. Chosen pairs: p1 0.619, p50 0.885.
Traps:
- "absent" = no in-order counterpart in the same unit: ~10% have an exact twin in another unit (members moved).
- Leaf fns reached only by jalr merge into the previous fn (positive deltas).
- About 1.6% false starts give negative deltas and tiny absent rows.
- `callers` misses object dispatch tables: overlay `no-callers` is weak evidence of unreachable code.
- Debug hints by printf caller land mostly in the PSY-Q library range. Filter by the lib range before calling a function game debug.
- Proto 09-21 lib sits about 0x9E8 higher than retail's 0x80054AD0.
- Constant-compare leads (e.g. TCRF "threshold 5000 vs 3000"): scan changed pairs for an immediate in proto absent in retail (.run scratch, 1 hit for 5000/3000).
