# Table base into a local before a call keeps it callee-saved

Symptom: a table base computed after a call takes a scratch register, or the callee-saved registers come out shifted by one. In the second case, the parameter is in the wrong saved register.

Cause: a value live across a call needs a callee-saved register. Taking it before the call makes it the first saved pseudo, so the parameter copy moves to the next one.

Lever: read the table base into a pointer local (block scope is fine) before the call. Then index it after the call. Add the index to the local, not to the global.

Evidence: W16 SLUS 4CD3C (base before the random call), rock_03 F1A3C (block-scope pointer local before adding the index).
Related: C0147 (shared block-scope scratchpad pointer), C0171 (parameter copied to a plain local).
