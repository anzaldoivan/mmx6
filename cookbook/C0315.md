# C0315 — SDK header prototype vs retail call: retail's spelling in the header, RETAIL override in psyqnames
tags: psyq,header,prototype,arity,signed-char,psyqnames,retail-call · date: 2026-11-01 · phase/task: 2.5/T4 · origin: mmx6 T4.c1

When: a caller kept its own declaration of a PsyQ function. The shared header (`include/psyq/*.h`) refuses to
compile in it, or moves its bytes. The header comes from SDK headers via `tools/mmx6/psyqnames.py` and `config/psyq/protos.tsv`.

Move:
- Find the spelling retail's calls need, one TU at a time, by .o compare against a clean baseline (C0276).
- Check arity first. A refused `too many arguments` means the SDK form is wrong for this build. Then check param widths, then the return.
- Write it into the header with a trailing comment giving the SDK form and the reason.
- Add the name to the `RETAIL` override dict in psyqnames (basis `retail-call`), so a regeneration keeps it.
- Rerun `psyqnames.py --sdk /sdk`. Check that only those rows changed in protos.tsv.

Traps seen (2.5/T4):
- `char` is unsigned in gcc2.95.2-psx. A `char` param gives `andi 0xff`. Retail's `sll/sra 24` wants `signed char`.
- `void *memset(...)` changed v0/v1 liveness after the call. `void memset(void *, int, int)` matched.
- Return width of a callee-extended return is not observable. `short` and `long TestEvent` were both identical: keep the SDK type.
- A header prototype is TU-wide. One mismatching caller blocks the whole (TU, library) unit.
- So a fix outside the task's names can be needed (ExitCriticalSection int, SsIsEos short(long, short), SsSepSetVol signed char).
