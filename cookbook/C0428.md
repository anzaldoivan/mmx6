# Loop pass 1 hoists an invariant too early: lift the loop's insn count so it moves in the rerun pass

Problem: preheader order of hoisted invariants is off (a division magic constant lands before the link masks).
`-dL` dump shows the magic moved in loop pass 1, since 4*n_moves >= insn count (58 moves vs 212 insns).

Lever: grow the loop's insn count past the pass-1 threshold with code flow later deletes:
- s16 locals for the narrow fields (adds extend insns),
- dead sets of a loop slot variable (14 here). Flow removes them later, after the count is taken.
Pass 1 then leaves the magic. The rerun loop pass hoists it after the masks, in the retail order.
- The count is a window, not a minimum: it depends on the base draft. 3.1 T14.c3 (same function, renamed globals):
  14 no effect, 30 stopped the hoist entirely (2/323), 21 matched. Bisect the count by probe (4 probes there).

Check: compare the `-dL` dump before and after. The dead sets must not survive (the probe match is the proof).
