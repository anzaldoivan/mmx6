# Mid-file R4 foreign-rodata: carve the whole role file into its own unit
- In place, a body in the middle of a role file stops at R4 `foreign-rodata`, and carve.py refuses a mid-file cut for it alone (C0360).
- Move: `carve.py opt <prog> <tu> <file start>`, then `carve.py opt <prog> <newtu> <next file start>`, so the role file is one unit. Then the gate's rodata step places the table and the body banks (T26.c2: func_80040FB4 in 80040388.c, func_80050670 in 8004FF7C.c, 204 rodata bytes).
- After a rodata-step bank, the next `propagate.py --check` shows `drift` and `not in class` for rows whose key moved with the carve. Re-key them to the built key (campaign.md T44 binding).
- SLUS unit 120A0 is the exception: see C0385.
- 3.2 T16.c1: the same drift follows a plain bank.py R5 of a function that owns a jump table. It drifted where the tables sit at a nonzero offset in the unit's .rodata (0x800315CC, 0x800319EC, 0x8004E26C). 0x8003AAD0, at offset 0, did not drift, and fleet th-remap fails `REMAP SELF-TEST FAIL 2`, and `propagate.py --check` gives `REGISTRY refused drift` and `not in class`. Fix: rewrite the banked row's key to the live census key (a singleton class, so nothing else moves). Then `REGISTRY OK`, and the fleet is green. The mechanism is unverified (likely a section-relative reloc addend the mask keeps).
