# Repin swaps only the body, so a changed upstream preamble needs a hand port

`x4port.py --repin` replaces a held file's function body with the new pin's body but keeps the file's preamble
(externs, prototypes, #defines) from the old pin.

Symptom: after un-holding, cc1 fails with errors that trace to declarations, not the body:
- `request for member 'transition' in something not a structure or union` (global newly typed upstream)
- `too few arguments to function 'func_X'` (callee prototype changed upstream)
- `conflicting types for 'func_X'` vs a decl in another file, and `void value not ignored` (retyped return)

Fix: not an adapter mapping. Either hand-port the preamble (and the other file's decl) or keep the file held,
with the exact cc1 error as the blocker (`compile: @<pin> <error>`).

Also: repin output is not clang-formatted (braces on their own line). Run `clang-format -i` on the
rewritten files before `make format-check`, then rebuild (C0063: format before hashing).

Triage loop that worked (2.1 T4.c1): un-hold all candidates → `--repin` → clean `make -k build` → re-hold
only the files whose objects fail → clean build 57/57 → `--credits` for THIRD_PARTY.md.
