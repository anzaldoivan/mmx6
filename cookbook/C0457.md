# C0457 — Stop orphan docker run containers: --init, name, trap kill, stale list
tags: docker,mx.sh,orphan,containers · date: 2026-11-13 · phase/task: 3.1/T23 · origin: T23.c1 mx.sh

Symptom: `docker run --rm` containers keep running after their client dies (agent tool timeout, kill -9). They hold CPU and the /work volume.

Move: `--init` (PID 1 forwards signals), a per-run `--name` and labels `mx6.run=1 mx6.client=<pid>`. Docker runs in the background under `trap 'docker kill <name>' EXIT INT TERM HUP; wait`, which keeps rc and stdout. A SIGKILLed wrapper skips the trap. So `mx.sh stale` lists running labelled containers whose client pid is gone (`MX-STALE <n> orphans`), and every run warns on stderr.

Evidence: 3.1 T23.c1: planted orphan (kill -9 of mx.sh) listed, TERM to mx.sh killed its container, `run cat` stdout byte-identical, rc 3 passed through.
