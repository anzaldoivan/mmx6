# A new body under L-B: stage it at layout.new_body, the next apply folds it in

Symptom: a doc or a tool treats the per-function shared path as the home of a body.
After 2.4 most bodies sit inside role files.

Mechanism: the gate and propagate write a new draft at `layout.new_body(prog, func)`.
That path is `src/shared/<prog>/<func>.c`, a staging place.
bank puts its include where `layout.find_asm` finds the INCLUDE_ASM line, in the unit or in a role file.
`layout.py apply --prog <p>` reads an include with one includer as a body entry and inlines it into its role file.
A body that more than one unit includes gets its owner under `src/shared/<system>/`.

Lever: find a body with `layout.locate(prog, func)`, never a path pattern.
Treat the staged path as temporary, and run `layout.py apply` then `layout.py repoint` to fold new banks in.
Bank an open function into its own unit first (`carve.py opt ... --gate`, C0288).

Proof: see `new_body` and the apply entry logic in `tools/mmx6/layout.py`.
The convention is in `docs/layout.md`, and the bank route in `docs/ops/decomp-environment.md` (2.4 T19).
