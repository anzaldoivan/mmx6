# Upstream retyped a global that sibling TU files declare differently: alias it locally

- Symptom: an x4 repin body uses a newly typed global (`D_80097420.transition.active`, `D_800E4478` as a byte). Sibling src/shared files #included in the same TU declare it as `s32`, `u8[0x10]` or another struct, so taking upstream's extern gives `conflicting types`.
- Fix (2.3/T1.c1): keep the siblings' extern. In the ported file only, add a self-referential alias: `#define D_80097420 (*(struct X4_MainBssState*)&D_80097420)`. For an array used as a scalar: `#define D_800E4478 (*D_800E4478)`. `#undef` it at the end of the file.
- The body keeps upstream's spelling and the bytes stay identical, because the access is the same load or store.
- Retyped return (func_8001B6D0 `s32` vs sibling `void` decls): keep the old signature and add a `// !` note. The next repin reports `at pin, port differs`, which is expected.
- Prerequisite: after `mx.sh sync`, `x4port --repin` and `--self-test` need one container state with `make -s extract && make -s build && corpus.py --all && census.py --all && sig.py --all && x4share.py --triple gcc2.95.2-psx-aspsx2.86 --partners`. Without it they stop with `functions.jsonl missing` or `sigs.jsonl missing`.
