# refusecause on a volume with no fresh fleet: false `R5 link: undefined reference to .L<addr>` rows

Problem: refusecause --prog P ran on a bank volume after its paste (mmx6-w309, no fleet since its shards).
It gave 225 `declaration` rows over 15 programs, each `R5 link: undefined reference to .L800EDFE0`.
The 3.1 table had no such row (rock_26's were stale, gated).

Check (3.3 T5): the same HEAD tree on another volume, with `make fleet` first, ran the same 28 programs.
It gave 0 `.L` rows, and all 225 were stale. Mechanism not proven (likely stale generated label files, C0452, C0433).

Recipe: run `make fleet` on the volume right before a refusecause series, and count `.L` link rows in the output.
Any `.L` link row is a sign to rebuild and rerun, not a refusal cause.
