# C0456 — Verify a derived input set with a Python open audit hook
tags: propagate,propsince,audit-hook,triggers · date: 2026-11-13 · phase/task: 3.1/T23 · origin: T23.c1 audit run

Symptom: a static input set built from imports and path literals can miss a file the tool reads. It can also hold files the tool never reads. A missed file gives a false green.

Move: run the real tool once under a Python audit hook (`sys.addaudithook`, event "open"). Install the hook with a scratch `sitecustomize.py` on PYTHONPATH, so every child python inherits it. List the opened paths under the trigger dirs and compare them with the derived set. A file that is only copied into a worker tree is opened too, so drop the copies first.

Evidence: 3.1 T23.c1 ran a propagate dry run on 3 equiv keys. It saw 42208 opens and 18 relevant files, with 0 gaps. Imported code names config/methods-arm.tsv (cards.py) and config/debt-baseline.txt (psxd_floor.py), but the run only copies them. So propsince lists them in TRIGGER_NOT.

Limit: the hook sees Python opens only. Reads by make and gcc come from the config literals in the build rules.
