# C0076 — &local cached in $s0 via a named pointer vs per-site addiu (call args)
tags: idiom,sym-phantom-callee-saved,G-expr,rtl,callee-saved,address · date: 2026-10-01 · phase/task: 1.7/T4 · origin: mmx6 repro

1. **Residual (tell)**: `&local` held in a callee-saved `$s0` (`addiu $16,$29,K`, then `move $4,$16` before each call) vs `addiu $4,$29,K` at every call site. `sym-phantom-callee-saved`
2. **Mechanism**: rtl expand (G-expr). A register argument goes through a pseudo only when it costs > 2 and small-register-classes or inside a loop; `&buf` is cheap, so it is expanded straight into `$a0` per site. A named pointer variable is a user pseudo (`reg/v`) that lives across the calls and gets a callee-saved register.
   - src:gcc-2.95.2/gcc/calls.c:662 "&& rtx_cost (args[i].value, SET) > 2"
   - src:gcc-2.95.2/gcc/calls.c:664 "preserve_subexpressions_p ()"
   - a-side `.rtl`: `(set (reg:SI 4 a0)` / `(reg/v:SI 81)) -1 (nil)` per call.
   - BFM X2 (2.7.2 cached per &local by default) changed: 2.95.2 is per-site unless a variable holds the address.
3. **Lever**: `void *q = buf; h(q); h(q);` caches the address in `$s0`; `h(buf); h(buf);` gives per-site `addiu`. No asm fence needed. Inertness checked: b differs (2 instructions shorter).
