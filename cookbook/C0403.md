# C0403 — A $2 pin after a call: call through a void cast to free v0
tags: lever,pin,depin,call,cast,void,v0,return · date: 2026-11-07 · phase/task: 2.6/T32 · origin: mmx6 T32.c2 wait_for_file_load

Lever (mmx6 2.6/T32.c2, wait_for_file_load, `t` pin on `$2` removed).
- Shape: a call to a function declared with a return value, then `x++` on a global. Retail does the increment in v0.
  The draft needed `register s32 t asm("$2")`.
- Fix: call it through a void cast, `((void (*)(s32))func_800139A0)(8);`. v0 is then free after the call and the increment takes it.
- Check the other callers first. The rock_18 and rock_20 callers already used the void-cast form.
- Related: C0104 (the callee declaration is a lever), C0377 (void casts at call sites).
- Result 2.7 T9.c3 (update_text_box): no pin involved. `load_palette` (void in graphics/palette.c) was called through an `M2C_UNK` prototype, so the call set v0 just before a `D_800E33C6` reload and the constant took v0. A void-cast call (prototype kept, C0391 style) moved 432 -> 441 and fixed both `== 2` tests. Check the callee's real return type whenever a value loaded right after a call misses v0.
