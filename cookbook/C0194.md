# Epilogue restores interleaved with the tail: empty barrier before the previous store, tail unbarriered

Symptom: retail's tail statement (e.g. a byte `++`) shares a block with the epilogue (`lbu; lw ra; lw s1; lw s0; addiu; sb`). Ours restores the callee-saved registers after the store, or only `ra` interleaves.

Lever: compute the previous store's value into an s32 block local. Then write `do { } while (0);`, then the store, then the tail statement with no barrier. A do-while(0) around the tail itself keeps the restores out. No barrier at all lets the tail load hoist into earlier gaps.

Keep calls outside the empty barrier. A do-while(0) whose body holds a call stops the preceding arg move from filling the earlier call's delay slot.

Cases: W22 rock_11 0x800F8130 (43 → 50/50, attempt 2) (T22.c63).

See also: C0136, C0162, C0172.
