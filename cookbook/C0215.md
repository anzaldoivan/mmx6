# Rodata carve or banking moves a census dup key: re-key the registry row
- A gate rodata carve, or a banking that carves, can change the census dup key of the carved exemplar or a sibling row.
- Symptoms: REGISTRY refused drift / not in class / missing member, while the binary hash stays green.
- Fix: re-key the exemplar row to the built key. Then run propagate (or propagate.py <key>) so that the class members are recorded. Re-check REGISTRY after every wave with a rodata recovery.
- Refusal counts are per refusal line, not per row: one drifted exemplar-only row can print two lines.
- Key moves are relocation-masked: a C object and its asm object can hash differently for the same bytes.
