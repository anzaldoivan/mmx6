# Carved jump table overruns its bank by an alignment pad
- After a merged rodata carve, a bank can still overrun by a few bytes (seen as +4).
- Cause: the compiler aligns each jump table in the C object, while the original layout packs migrated tables without pad.
- A second carved table in a unit that already has .rodata gets the same padding in the unit's growth.
- The carve step accepts it. Only the exact byte check against the bank refuses it.
