# Overlay trailing data goes after the END marker.

The segment tool regenerates the block between its BEGIN and END markers.
The th-carve check in the fleet compares that block against a fresh regeneration.
segment.py cannot carve an overlay's trailing data.
A hand-added `- [0x92C, data, FA92C]` inside the block fails the fleet with
`CARVE CHECK FAIL rock_55: config/rock_55.yaml block != segment.py regeneration`.
Put the line just after the END marker, with a comment saying it is hand-kept.
The result is `CARVE CHECK OK`, and a segment.py rerun leaves it alone.
The lasting fix is an overlay data carve in segment.py (a tool trigger, so not during the freeze).
