# C0290 — Units carry cpp -MMD deps. A make -n recipe splice must drop -MMD/-MP/-MT/-MF
tags: make,dependencies,include,rebuild,dumps,cpp · date: 2026-10-31 · phase/task: 2.4/T4 · origin: mmx6 T4, T4.c1

Since 2.4 T4 the Makefile C rule runs cpp with `-MMD -MP -MT $@ -MF build/$*.c.d`, and `-include`s every
`build/src/**/*.c.d`. A touched body, role file or shared include rebuilds the units that include it. This supersedes
C0232's "touch the TU", which is still needed once: a unit has no .d until its first build after 0a989d6c.

Trap: a tool that splices the C rule's recipe from `make -n -B` (C0092, dumps.recipe, permute.cpp_argv) now gets
`-MF build/<x>.c.d`. A dry run never ran the rule's `mkdir -p`, so cpp fails with "opening dependency file ...: No such
file or directory" on a scratch input. Fix: drop `-MMD -MP` and `-MT/-MF <arg>` from the cpp stage
(`tools/mmx6/dumps.py strip_depflags`). The deps flags do not change the preprocessed text.

Check: `touch src/shared/rock_16/<body>.c; make -n build/src/rock_16/E9860.c.o` prints the recipe, and a sibling
program's unit stays up to date.
