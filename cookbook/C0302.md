# Compile a role file through its including unit, never as a unit

Context: after an L-B regroup, `config/dedup_registry.txt` rows point at role files (`src/<prog>/<system>/<role>.c`), which carry no unit preamble and are `#include`d by a unit `src/<prog>/<tu>.c`.

Wall: any tool that compiles a registry body path as-is breaks:
- `make build/src/<prog>/<role>.c.o` fails (no preamble).
- a define row's wrapper `#include`s the whole role file under `#define old new` -> redefinition (the role file already holds the instantiated body).

Move (tools/mmx6/harness.py p2_gather, T15.c3):
- body under `src/<prog>/`, listed by `layout.includers(root)`, not itself a unit -> compile the including unit (prefer the row's prog).
- a define row whose body resolves to a role file -> compile the unit, no wrapper.
- compile each distinct source once (dict by src): rows of one unit racing `make -B` on one `.o` give spurious NotRun.
- `src/shared/`, units, wrappers, probes unchanged.

Check: full `make fleet` (th-harness needs the census build): HARNESS CONTROL OK, P2 AGREE all rows. Running harness.py directly after `mx.sh sync` lacks build/ inputs -> spurious NotRun. Use the make target.
