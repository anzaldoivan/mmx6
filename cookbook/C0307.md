# C0307 — Self-test split/plant targets: pick via the layout, never fixed vrams or unit paths
tags: self-test,layout,carve,role,health,control · date: 2026-10-31 · phase/task: 2.4/T16 · origin: mmx6 T16.c4

Context: some self-test controls split or plant at a fixed address or file. Examples: carve's opt-rodata-follow at
rock_04 0x800ED3A4, and no-rodata-block planting into src/rock_01/1EA000.c. A regroup moves that code into role files.
The split then lands mid role file and carve answers `CARVE REFUSE role-split` (correct). The control goes red
(health th-carve).

Move:
- Pick the split target by walking layout units in `layout.Tree` c_units order. Take the first chunk start (a C def or
  a role file's first function, via anchors) that meets the control's precondition. Here that is a start inside
  (min, max] of the unit's carved rodata owners: carve.py `follow_target()` beside `plant_target()`.
- Pick the plant file with `layout.find_asm(prog, line, SCRATCH)`, never a hardcoded unit path.
- Generalize the control's expectations: only rows of the chosen unit move, and offsets derive from the pick.

Check: build first, because sync wipes build/ and health needs a build. Then `mx.sh run make -k health` and `make fleet`.
