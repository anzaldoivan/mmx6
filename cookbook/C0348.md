# Renaming a struct member tree-wide: compile-error-driven, by declared type, re-check code refs after format

When: a header member is renamed (e.g. family `unk5` -> `action`) and every user must follow.
Move:
- Rename in the header, build (`make fleet-quick`), rename the users on the error lines only. With parallel make
  some `has no member` lines interleave and get lost: rebuild until none remain.
- A line can mix two structs (`arg0->unk15 = player->unk15`): rename the side whose variable's declared type is the
  renamed struct only. Generated X4_ structs that repeat the prefix keep their names.
- clang-format reflows renamed lines. The `code:<path>:<line>` refs below them in fields.tsv and basis.tsv shift.
  Re-check the refs (namesqueue check) after every `make format`.
- Re-run format-check after `mx.sh pull`. One pull silently did not apply.
- objfields census does not follow `void* arg0` bases. A member read only that way notes `raw read by F`.
  After lifting, rewrite the note `read by F`.
- namesqueue check misses a fields.tsv ref whose line moved. For each `code:<path>:<line> via=<tok>`, check that
  `<tok>` is on that line. A 10-line script does it. In 2.6 T5 the facing refs were one line off.
- After a lift, a ref `via=0xNN` becomes `via=<field>`, because the offset is no longer in the source.
- A union pad (`unk88 {value; bytes}`) can split into typed members. This keeps the types when each byte has one
  view and no code reads `.value`. Take each new member's DC7 reader from `objfields.py --census`.
Evidence: 2.6 T5.c1 (fdc3b199c over 130 files, then 3f612c93f..4e545fa0c), fleet-quick 57 of 57 each commit.
