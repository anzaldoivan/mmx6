# C0480 — Wall: cse puts a register equal to a symbol address second in a commutative add
tags: wall,operand-order,add,cse,fold_rtx,lo_sum,local-alloc,tie,regalloc,index,base · date: 2026-11-15 · phase/task: 3.2/T6 · origin: mmx6 T6.c4 func_800192CC, T6.c13 func_80019C84

Symptom: retail adds base + index (base = a global's address), and ours adds index + base in every spelling.
Unlike C0146, the source spelling does not decide it.

Mechanism: the cse pass moves an operand with a constant equivalent to second place. Here that is a lo_sum of a symbol.
Source: fold_rtx at line 5585 of the cse source in gcc 2-95-2, seen in the rtl and cse dumps.
Then local-alloc ties the sum to operand 1, so the index shares the sum's register.
Three spellings of the index gave identical asm.

Partial lever: a base pointer set before the loop gets base-first order (func_800192CC, probe 13).
But PRE then reuses the high-half load across loops, so the score dropped (445 to 338 of 453).

Lever (T6.c15 func_800192CC, 445 to 449 of 453): write the add as a subtraction, which cse does not swap.
Per loop body: `s32 ni = -i; u8 *p0 = (u8 *)&D_800CF810; u8 *xb = p0 + 0x16; u8 *fp = xb - ni;`.
loop.c leaves `xb` in the loop, so `fp` is no induction variable, and combine folds it to a base-first add.
A plain `&D - ni` is strength-reduced to a pointer increment instead (90/453).

Arm against join (T6.c20 func_8004B634): the swap happens only where the register is known to hold the symbol.
In an if arm the add comes out symbol second. After the join, with two possible values, source order holds.
So two adds of the same pair in opposite orders mean the first sat in an arm and the second after the join.
A late retail copy `t = e` survives if `e = 0;` follows it and its use sits in identical if/else arms that jump2 merges.

Outside loops too (T6.c22 func_80019C84, 353 to 375 of 381): `s8 *xb = (s8 *)&g; s32 nc = -c; v = (xb - nc)[0x5B];`.
Keep the field offset outside the subtraction, or it folds into the address low half (31/381).
Set `xb` before `nc` so the high-half loads come in the target order.
A plain byte-array giv `D[i]` has benefit 4, equal to the add cost, so loop.c never strength-reduces it.
