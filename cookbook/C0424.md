# C0424 — gcc 2.95 compile errors have no error: tag, so classify path:line non-warning lines

# Reading a gcc 2.95 (cc1 psx) compile failure from its log
- cc1 2.95 prints errors as `path:line: <text>` with no `error:` tag. Warnings carry `warning:`, and notes are context lines.
- Classify: an error = a `path:line:` diagnostic that is neither `warning:` nor a note. A note such as "this is the location of the previous definition" (macro or decl context) is not the error. Match only the error line.
- Declaration-shaped errors: conflicting types, previous declaration/definition (as error), redefinition, implicit declaration, undeclared, too few/many arguments, incompatible type.
- Make deletes a target whose recipe ends in a failed sha check (C0029 .DELETE_ON_ERROR). To diff a hash-red rock bin, re-objcopy it from build/rock_NN.elf.
- gas errors carry the prefix `{standard input}:<line>:`, which a `^\S+:\d+:` pattern misses because of the space. Match that prefix too, or an assembler `already defined` reads as no error at all (3.1 T3.c3, 46 rows went to body).
