# lift.py traps: a built tree first, and shared fragments need their header

## When
Running `tools/mmx6/lift.py` (C0324) over programs, or retyping a base by hand in `src/shared/**`.

## Traps
- Built tree: lift gates each unit on its alloc sections/relocations from `asm/` + `build/`. Right after `mx.sh sync`
  (wipes /work) every unit reverts ("all reverted"). Run `mx.sh run make fleet-quick` first, then lift in the same
  container state. `lift.py --help` does not say this.
- Shared fragments: a `src/shared/**` file is `#include`d into program TUs, but th-harness P2 (`compiles?`) also
  compiles it standalone (`.run/harness/p2/<prog>.<func>.c` -> `#include "../../../src/shared/..."`). Retyping a
  param to `struct ObjectHeader*` etc. passes fleet-quick yet fails P2 with "declared inside parameter list /
  dereferencing pointer to incomplete type". Add `#include "mmx6/object.h"` (the struct's header) after `common.h`
  in the fragment. The header is guarded, so no byte changes.
- Only `make fleet` (tools-health) catches the second trap. fleet-quick does not.
