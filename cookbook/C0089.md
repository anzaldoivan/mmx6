# C0089 — Volatile short read: lhu + sll/sra instead of lh (combine skips volatile)
tags: idiom,sym-narrow-load,G-combine,combine,volatile,short · date: 2026-10-02 · phase/task: 1.7/T6 · origin: BFM §345 re-proven

1. **Residual (tell)**: `lhu` + `nop` + `sll 16` + `sra 16` where the target has one `lh` (or the reverse); 3 insns. `sym-narrow-load`
2. **Mechanism**: combine (G-combine). The `short` read is a volatile MEM; combine refuses to move an insn with a volatile reference into its user, so the HImode load (`lhu`, movhi) stays apart from the sign extend, which becomes a shift pair.
   - src:gcc-2.95.2/gcc/combine.c:1047 "volatile_refs_p (src))"
   - a-side `.combine`: `(mem/v:HI (reg/v:SI 81) 0)) 256 {movhi_internal2}`.
3. **Lever**: `volatile short *p` -> lhu + sll + sra; plain `short *p` -> one `lh`. a 6 insns, b 3.
4. **Byte proof**: repro/G-combine/volatile.{a,b}.c; `repro.py --lever L15` -> `LEVER L15 OK`; standalone compile under the pin. Retail anchor: none yet. Map row L15. BFM §345 (gcc 2.7.2) title re-proven under 2.95.2.
