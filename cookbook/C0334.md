# A sign-split range test as one ternary compare removes the C0144 goto

Problem: m2c (and C0144) write a sign-split range test as nested ifs with a `goto` into the else-if body:
`if (d >= 0) { if (d < N) goto hit; } else if (rev < N) { hit: ... }`.

Move: one ternary as the condition: `if (d >= 0 ? d < N : rev < N) { ... }`. gcc 2.95 emits the same two
compare branches into one body block. The goto is gone and the bytes are identical.

Not: `(d >= 0 && d < N) || (d < 0 && rev < N)`. gcc folds that range into `sltiu` and the bytes move. It matched
only for `!= 4` style tests (rock_10 ECD40, rock_22 F1E2C). When the ternary fails too, keep the goto. Mark it
with a `// !FAKE:` that names the block order (rock_10 F50A0, rock_22 F28AC far/near).

Evidence: 2.5/T11.c4. rock_11 EF0EC, EF408, F65D8, F77A8, F73B0 (inc). rock_10 ECC74, F6D58. rock_22 EC93C
case 2, F28AC call0/call1. Each is byte-identical per rock sha.
