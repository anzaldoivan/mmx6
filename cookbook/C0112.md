# C0112 — Volatile read on a join test keeps the reload and stops jump threading
tags: lever,volatile,cse,reload,jump-threading,join,flags · date: 2026-10-03 · phase/task: 1.8/T12 · origin: mmx6 W3

1. **Residual (tell)**: after an optional call guarded by a flags test, retail reloads the flags at the join and the branch keeps its delay-slot nop; the draft reuses the value loaded for the test (or threads the jump past the second test).
2. **Mechanism**: observed, not source-proven. cse/gcse treats the second read as redundant with the first when no store intervenes on the fall-through path, and jump threading then merges the two tests. A volatile-qualified read on the first test is never a cse source, so the join reload survives and the branch is not threaded.
3. **Lever**: read the flags through a volatile cast on the test before the optional call (`flags = FLAGS; ...; if (*(volatile u8 *)&FLAGS == 0) call(self); f = FLAGS;`); if a move/extend pair is still off, spell the reload as `s16 f = (u16 g = flags)` and test `g` (plain move, no extra extend). Combine with C0089 when the volatile read is a short.
