# C0341 — Address debt on a lui/ori-built literal: macro in include/addr.h, not a linked symbol
tags: address,debt,psxd_floor,lui-ori,symbol,addr.h · date: 2026-11-02 · phase/task: 2.5/T12 · origin: T12.c1 task_yield/task_slot

# Clearing `address` debt for a literal the code builds with lui/ori

Problem: psxd_floor counts a console-range literal (`0x801F8100`) as `address` debt.
A linked data symbol for it moves bytes, even with `// absolute:True` in symbols.txt.
The compiler emits `lui/addiu %hi/%lo` where the original has `lui/ori`.
It may also drop a pointer reload (task_yield lost 12 bytes).

Move: keep the literal, named once as a macro in `include/addr.h`.
Example: `#define g_task_slots ((struct TaskSlot*)0x801F8100)`.
The psxd_floor rule `address_header` does not count address literals in that header.
The C file then has no debt, and its bytes stay identical.

Include addr.h from the system header (mmx6/task.h).
Magic values in the same range (thread id 0xFF000000) go there too, as named constants.
Still add the basis.tsv row for the name.

Check: make fleet-quick, then make fleet. `psxd_floor debt --files` shows the file `finished`.
See also C0134 (#define for absolute addresses, gate-tool-safe spellings).
