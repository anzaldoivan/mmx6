# Operand order of an add follows the source spelling: `e -= -x`, `(x << 3)` not `* 8`

Symptom: the right instructions are in the right places. But the two source operands of one add are swapped
(base second where retail has it first). Or an indexed address sums the scaled index before the base.

Lever: spell the expression so gcc's canonical order lands where retail's does.
- For a subtraction that retail compiled with the base first, write `e -= -x` (or `e = e - -x`) instead of `e += x`.
- For an index scaled by 8, write `(i << 3)` instead of `i * 8`. In the sum, gcc puts a multiplied term first
  and a shifted one after the base.
Try both before a register-pin sweep. They change no instruction count.

Cases: W8 SLUS_013.95:0x80032DF0 (T8.c64, 265/265) and rock_40:0x800FB378 (T8.c68, 155/155, plus a
register-pinned index byte). Related: C0103, C0135.
