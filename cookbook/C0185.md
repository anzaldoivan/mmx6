# Retail void return: an int return keeps the return register live at the exit join

Case: W19 rock_11:0x800F9F7C (logs/T19.c26.md); banked via gate rung tusync.
- Symptom: the delay slot of the exit branch holds a different insn than retail; retail fills it with the first constant load.
- Cause: an `int`/`M2C_UNK` return keeps v0 live at the exit join, so the delay-slot filler cannot take a load into it.
- Lever: define the function `void`. If the TU prototypes it `M2C_UNK`, the bank stops R2 (conflicting types); the gate's tusync rung rewrites the TU prototype. Same shape: rock_07:0x800F4144 void(void*) vs a TU `void(void)` prototype (tusync; logs/T19.c34.md).
