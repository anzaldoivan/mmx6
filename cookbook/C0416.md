# Loop-invariant prim constants: hoist them with more literal sites, never with variables
- Symptom: retail keeps prim codes and masks (0x7D, 1, 0xFFFFFF, 0xFF000000, 0x2D) in s-regs in the loop preheader. Our draft either rematerializes them in the loop or loses the tbase/pal spills.
- Mechanism (cc1 `-dLlg` dumps): loop.c moves a literal set only when `threshold*savings*life >= insn_count`. Sets of the same literal value combine, so their savings add up. With 2 sites in a ~330-insn loop the move is "not desirable".
- A constant in a variable set once gets REG_EQUIV, so lreg doubles its live length. It then loses global allocation to the spilled locals. That is why no placement of variable constants gets both the hoist and the spill.
- Move: write the literals at more sites. Use PsyQ macro forms (`setcode(p, 0x7C)`, `|= 1`, setSemiTrans as `(c) ? (code |= 2) : (code &= ~2)`) and copy the draw tails into each arm (vertex code, link tail).
