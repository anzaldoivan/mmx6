# C0317 — Homing a struct out of a generated header: emit its alias before every use
tags: x4,x4port,homed,alias,incomplete-tag,struct,generated-header · date: 2026-11-01 · phase/task: 2.5/T5 · origin: 2.5 T5.c3

Context: a struct moves out of a generated header (x4.h) into a hand-written home. The generated header keeps a
`#define X4_T T` alias for the old users (2.5 T5, config/x4/homed.tsv, tools/mmx6/x4port.py x4h()).

Trap: the generator must emit the alias before the first `struct X4_T` in the header. Pointer uses count too, such
as `struct X4_MainObj* p;` in an earlier block. An alias at the old block's place comes too late. The earlier
pointer use then makes a second, incomplete tag silently. The error shows only later, as "dereferencing pointer to
incomplete type" or as conflicting types.

Move: emit every homed alias first among the generated types. Include the home once at the end of the header. The
home includes the generated header for its own member types (X4_f32, the unions).

Check:
- `grep -c 'struct X4_<T> {' include/mmx6/x4.h` = 0.
- typecheck `duplicates 0`.
- x4port `--repin --dry-run` prints `0 would change; homed <k> kept out`.
- fleet-quick is green.
