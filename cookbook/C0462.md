# C0462 — Check the Docker VM disk before parallel coder volumes: ENOSPC shows as fleet health rc 2
tags: docker,disk,volume,parallel,fleet,health,enospc · date: 2026-11-14 · phase/task: 3.2/T3 · origin: mmx6 T3.c1-c3

## Problem
Parallel coders each get a new MX6_VOLUME. The Docker VM disk is fixed (31.3G here). Every volume, image and build cache shares it, so the host free space says nothing about it. 3.2 T3: three new volumes filled it to 0 free.

## Symptom
The build passes (`FLEET 57 of 57` printed), then `fleet: make health rc 2`, make rc 1. With `-Otarget` the failing rung's message is lost. `make health JOBS=1` shows `OSError: [Errno 28] No space left on device` (sig.py write_sigs, dumps.py). Later runs fail mid-build (`can't write ... .o`, `FLEET 0 of 57`), and every container start can fail on mount.

## Move
- Before spawning k coders on new volumes, check the VM: `docker run --rm alpine df -h /` (free space) and `docker system df` (a fleet volume is about 0.8 to 1.9 GB). Plan k times about 2 GB of headroom.
- Short on room: reuse the volume of a finished task instead of a new one, or run the coders serially. Sync keeps its generated dirs, and the fleet cleans itself.
- Freeing space (a builder prune, removing a volume) is the developer's decision: return a question with the reclaimable figures.
