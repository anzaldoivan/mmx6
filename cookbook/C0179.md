# C0179 — Byte-field increment temp in the wrong register: pinned s32 block local = f + 1
tags: lever,increment,register-pin,regalloc,byte · date: 2026-10-10 · phase/task: 1.8.1/T17 · origin: mmx6 W17 rock_02 F7570, rock_15 ECC78

Symptom: a byte-field increment whose temp lands in the wrong scratch register; `++`, `+=` and plain-local spellings all give the same wrong register.
Cause: local-alloc picks the temp's hard register by priority; spelling does not change the pseudo.
Lever: a numerically pinned block-scope s32 local holding the sum, stored back: `register s32 t asm("$2") = p[6] + 1; p[6] = t;` (numeric pins only, verbatim.py counts them).
Evidence: W17 rock_02 F7570 (45/45 banked); W17 rock_15 ECC78 matched with the same lever (gate stop R2, not a drafting fail).
Related: C0161 (pinned constants), C0103 (void cast for a post-call temp; try first).
