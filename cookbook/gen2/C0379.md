# Jtbl carve blocked by a same-unit const initializer between tables

Symptom: `carve.py jtbl <prog> <lo>` refuses `non-contiguous`, and `carve.py rodata <prog> <func>` refuses
`foreign-rodata`, for a table whose unit already owns a later rodata range.

Cause: the gap between the two tables is the unit's own const data, not a table.
Example: the local-array initializer (`__builtin_memcpy` from `D_<addr>`) of a later function in the same TU.
The jtbl rows of one unit must be contiguous.
The rodata merge accepts only tables (words inside the function) and pad below the alignment.
So neither subcommand absorbs the gap.

Effect: m2c (`decompile.py`) stops at the `jr` with "jump table is not provided".
The table stays out of the INCLUDE_ASM `.s`, so there is no draft, no ladder and no permuter run.
Re-ledger the function as `jtbl-uncarved` with both refusals.

Check before you plan a jtbl task: read the rodata between the new table's hi and the unit's next carved lo.
The source is `asm/<prog>/data/*.rodata.s`.
If that rodata is a symbol that only the same unit uses, the route is a carve.py change (a same-unit data row).
A carve run alone cannot pass.
