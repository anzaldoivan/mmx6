# Lifting a void* param: typed local, keep the prototype

When: a function to lift takes `void* arg0` and its file is #included into a unit (e.g. 32208.c) beside other
files that declare it with a `void*` prototype.
- Typing the param (`struct X4_PlayerObj* arg0`) fails the unit build: "conflicting types".
- Keep `void* arg0`, add the local `struct X4_PlayerObj* self = arg0` and read `self->m`. Byte-identical in 6
  functions (weapon/ giga_attack, weapon, special_weapon, weapon_energy_cost, weapon_switch, weapon_energy, 2.5 T9.c2).
- Width view and the floor: write `9 + *(u8*)&p->m`, not `*(u8*)&p->m + 9`. The second matches the debt
  floor's `(u8*)OPND + N` offset pattern and still counts as an offset read. Same bytes here (C0326 for views).
- Array-of-member reads: `((s16*)g_Player.weapon_energy)[kind]` matched in guard_shell. In yammar_option the
  same form swapped the addu operands (1 line) and stayed an offset read (docs/types/lift.md).
- A read that will not lift: keep it, list it in docs/types/lift.md with each lever tried.
