# C0404 — local-alloc stretches lifetimes by one insn: read sched1 order, not source order
tags: regalloc,lreg,local-alloc,sched1,dumps,asm-differ,r5,in-place · date: 2026-11-07 · phase/task: 2.6/T32 · origin: mmx6 T32.c1-c2 func_800144DC, wait_for_file_load

Finding (mmx6 2.6/T32.c1-c2, func_800144DC 98/100, wait_for_file_load). gcc 2.95.2 -O2.
- With INSN_SCHEDULING, local-alloc (lreg) stretches each pseudo's lifetime by one insn on each side.
  A pseudo born right after another dies cannot reuse that register.
- So the order that counts is sched1's, not the source order. Read `.sched` in the dumps (dumps.py --src).
- sched1 gives an insn that births a pseudo top priority (0x7f000001), so it moves right after the last use.
- Example: insn 192 (`sh 0x12`) frees v1, insn 200 (`m = prim & 0xFFFFFF`) follows it, and m takes a0, not v1.
- Spellings that move the birth (an early 0xFF000000 local) also reorder the masks (C0380) and score worse.
- In-place scoring loop for a gate R5 residual (C0388): after a sync run `make build expected` once (about 2.5 min).
  Then per draft run `make build` (5 s, the sha check fails), objcopy the elf, and `diff.sh <func> --no-pager`.
  The container has no `less`, so asm-differ fails without `--no-pager`.
