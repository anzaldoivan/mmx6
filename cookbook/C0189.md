# One constant address shared across calls: spell the second read through a different base

Symptom: two reads of the same global/scratchpad address in one block, separated by calls; ours keeps the address in one callee-saved register (frame grows, length residual); retail rebuilds it from a fresh high half.
Lever: spell the later read through a different constant base so cse cannot see one address: a struct-member view off the scratchpad base; the separate TU symbol (`D_800F5F04`, not `D_800F4BF0 + 0x1314`); offsets of a blob as their own `D_<addr>` externs (TU spelling).
Cases: W20 SLUS_013.95 0x8003C4EC, rock_09 0x800EC6C4, rock_43 0x800FBB70 (T20).
See also: C0117 (one extern per field), C0109 (per-branch pointer).
