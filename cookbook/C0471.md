# C0471 — A 24-bit mask whose high-half load floats to the block top: read it as a u32 :24 bitfield
tags: lever,mask,bitfield,sched1,constant,regalloc,pin,depin,dumps · date: 2026-11-15 · phase/task: 3.2/T6 · origin: mmx6 T6.c2 func_8001717C

Symptom: a word is read as `x & 0xFFFFFF` beside `x >> 24`, and the draft scores a few words short.
The register choice of the whole block is shifted.
The constant's high-half load sits at the top of the block, far from its use.

Mechanism (dumps, sched1): cc1 builds the 0xFFFFFF constant as two insns that set the same pseudo.
So sched1 never gives the high-half load the new-value priority boost, and the load drifts upward.

Lever: declare the header as `struct { u32 ofs:24; u32 mode:8; ... }` and read `ofs` through the bitfield.
The mask is then built next to its use.
Keep `mode` as a whole-word `>> 24`, because a `mode:8` field read becomes a byte load.
Then order the field reads before the unrelated address computation.

Also: a stale callee prototype with a wrong argument count costs whole blocks.
Fix the callee from its real header (psyq/libsnd.h) before reading any wall.
The W21 draft's 2 register pins had only compensated for one such prototype.

Evidence: 3.2 T6.c2 func_8001717C went from 93/104 unpinned to 104/104 pin-free in 6 probes and 1 dumps run.

Use it the other way (3.2 T6.c19 func_80017630, 182 to 192 of 221): a two-insn constant gets no boost, so its place follows source order.
Put the statement that uses it first to move it to the top of the block.
A value built in one statement is set once and sinks: build it in two statements to keep it in place (C0473).
