# A per-row repair dry run: refusecause.py --prog with the switches, not propagate.py --dry-run --keys-from

Problem: you want to know whether one refused dedup member gates with repair switches on, without writing src.
`propagate.py --dry-run --keys-from` looks cheaper, but it gives a different verdict.
- refusecause re-gates the refused registry row's own shared path. propagate gates from the exemplar row's path,
  and the two paths can differ.
- propagate gates whole dup classes in a grouped R5 with bisect and writes no cause column.

Method: `mx.sh run python3 tools/mmx6/refusecause.py --prog P --repair A --repair B ...` on a building volume
(own MX6_VOLUME, build at HEAD), one program per command. Pick the rows by prog, vram and key from its output.
It edits only scratch trees under .run/propagate/tree/rc_P and deletes them, so src stays clean.
A row that gates prints cause `stale`, detail `rerun gated, R5 green [via ...]`.
Cost: no row filter, so each program reruns in full. 14 programs took 8169 s with all four switches (rock_23 1857 s).

Related: C0438 (relocdef), C0439 (unitcut), C0437 (rolefeed).
Origin: 3.1 T14.c1, the 20 pilot refusal rows of config/methods-sample.tsv (6 gate, all with relocdef+unitcut).
