# C0427 — Freeze a derived sample against input blob ids, and let --check rebuild via git cat-file
tags: sample,holdout,frozen,determinism,blob,check,stratum · date: 2026-11-09 · phase/task: 3.0/T12 · origin: mmx6 T12 methodsample.py

Problem: a frozen sample is built from tracked inputs that keep changing (ledger, cause tables). Once those inputs move, it cannot be re-checked. A `--check` against the working tree goes STALE on the next bank.

Technique (mmx6 3.0 T12, tools/mmx6/methodsample.py):
- `--build` refuses unless each input equals HEAD (`git hash-object <p>` == `git rev-parse HEAD:<p>`), then writes the input blob ids into the output header (`# inputs (blob ids): path@<blob12> ...`).
- `--check` reads the blob ids from the header, feeds `git cat-file -p <blob>` to the same build function, compares byte for byte. Green forever, whatever the working tree holds.
- Selection is deterministic. Collapse dup clusters to one member first. Use fixed quotas per stratum and a stable sort whose tie-break ends in (prog bytes, vram int).
- Pick evenly spaced rows, index floor((2i+1)N/(2k)). A cell then spans the sort key instead of giving only its top.
- Holdout split alternates in file order (even pilot, odd holdout) so both halves carry the same strata within one row.
