# C0412 — Retail reloads a pointer field after an if/else: write the field path at every use, no local
tags: lever,reload,pointer,field,cse,length,index-loop,pc-port · date: 2026-11-08 · phase/task: 2.7/T9 · origin: mmx6 T9.c6 func_8002E84C

1. **Residual (tell)**: Retail tests a struct's pointer field. After an if/else, it reloads that field into a second register. The draft keeps one pointer local, so it is shorter (a length plateau).
2. **Mechanism**: A local lets cse carry the pointer across the join. A field path written at every use, such as `slots[i].hitbox->w`, is a fresh memory read. After the if/else stores, cse does not keep it.
3. **Lever**: Drop the pointer local. Write `base[i].ptr->field` at every use, with an index loop, not a row pointer. This is the inverse of C0086.
4. **Byte proof**: 2.7 T9.c6, func_8002E84C, from its PC port shape (C0406). The draft went from 26 to 69/74. Writing `w + x - 1` for the bound sums then gave MATCH 74/74.
5. **Related**: C0086 (the inverse case), C0145 (re-read a field at each use), C0107.
