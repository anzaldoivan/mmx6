# C0443 — x4port self-test red after 6 fleets: shared waves/.probes counter hits the probe cap
tags: x4port,self-test,probe-cap,probes,fleet,th-selftests-cheap · date: 2026-11-10 · phase/task: 3.1/T12 · origin: mmx6 T12.c1 fleet.log

Symptom: fleet prints `FLEET 57 of 57` but `make health rc 2`. th-selftests-cheap is red, with `X4PORT CONTROL FAIL positive` and `PACK SLUS_013.95:0x8001E78C refused probe-cap a1 6/6`.

Cause: the x4port self-test probes its planted pack through the shared probe counter in /work/waves/.probes (one log per pack path), which `mx.sh sync` never wipes. Each fleet adds one line. After 6 the enforced probe cap refuses the plant. Seen in t9c1-fleet-pre, t9c2-fleet, fleet-t11c1, T12.c1 fleet.log.

Workaround: delete that one counter in the container (`mx.sh run rm waves/.probes/.run__x4port-selftest__W-x4__SLUS_013.95_func_8001E78C.log`) and rerun the fleet. The file is untracked, so this is safe.

Fix: x4port.py self-test (~:1319) passes `probes=` under its own self-test folder so the counter is wiped with the plant.
