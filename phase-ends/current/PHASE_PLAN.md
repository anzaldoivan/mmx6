## Rationale
- Order: T1 stages the source and the citation auditor first, because every map citation is checked against it (DK-52, G51). T2 (dumps) is the evidence instrument G52 needs; T3 (allocation reader + reproducer runner) is the per-mechanism instrument G55 needs; T4 and T5 write the map on those instruments; T6 seeds and checks the cookbook keyed by the triage table's tells (needs T5's table); T7 (permuter) is independent of the map but its stored draft is the plateau classifier's real input; T8 classifies and carries the milestone.
- Source = vanilla GNU 2.95.2 plus old-gcc's psx patches at the commit that produced release 0.17, staged in the image at `/opt/gcc-2.95.2-src` by a Dockerfile layer with our own sha256 pin, never in git (19 MB of third-party source; GPL, not game-derived, but no reason to track it). "Pinned version" is proven, not asserted: a throwaway build stage rebuilds cc1 from the staged tree the way old-gcc's Dockerfile does; pass = sha256 equal to 932ed366…; fallback when the build is not bit-reproducible = the rebuilt cc1 compiles every C unit of the fleet to identical objects (`make fleet` with `CC1=` on the command line; CC1 is `:=` so a command-line value wins, Makefile:54) — recorded in compiler-pin.md as which proof held. A source that fails both is the wrong source: `blocked`.
- Citation format, tracked in map files: `src:gcc-2.95.2/<path>:<line> "<≤80-char verbatim fragment>"`. `gccsrc.py --check` resolves every citation in `docs/codegen-map/*.md` and `cookbook/C*.md`, refuses missing file, line out of range, fragment not on that line (line drift reports the nearest line holding it, DK-52's 40 drifts).
- Pass groups (six, keyed to cc1 2.95.2 dump suffixes; T2 confirms the suffixes): G-expr (rtl/expand, cse, cse2, gcse, addressof), G-loop (loop), G-combine (combine, regmove), G-alloc (lreg, greg, reload as seen in greg/flow2), G-sched (sched, sched2, dbr, maspsx reorder/nops), G-jump (jump, jump2, cross-jumping). BFM had four; jump and combine get their own because C0002's branch-polarity and cross-jump rows and BFM's combine idioms do not fit cse/expr, and a group with no lever is visible rather than hidden.
- "Byte-proven" (milestone): a lever row carries a reproducer pair `repro/<group>/<id>.a.c` (shape without the lever) and `.b.c` (with it), compiled through the product C rule (G103) under the pin; `repro.py --lever <id>` asserts the masked words of a and b differ exactly in the row's stated tell (e.g. `$s0↔$s1` swap, the two instructions reordered, a branch polarity) and that the quoted dump line is present in a's dump of the named pass (G52). Retail anchoring is optional this phase (`retail: <prog:vram>` column) because no real draft exists before T7; 1.8 lands retail proofs as waves bank. This is the strongest proof available without a draft and it is mechanical, so it lives in a rung.
- Reproducer battery shape: `repro/<group>/<id>.c` ≤ ~15 lines each with a header comment `// tell: … // pass: … // expect: <regex over the asm>`; `repro.py --all` compiles each through the product rule (via `probe.compile_obj`), with dumps, and checks `expect`; runtime budget ≈1 s per reproducer (G55). Reproducers are our own C, not game-derived; tracked.
- Allocation reader (`alloc_table.py`): reads `.lreg` + `.greg` of one compile (reproducer or real TU), prints every pseudo (refs, live length, block, preference, priority by 2.95's own formula, cited from global.c/local-alloc.c in the source), and the `;; N regs to allocate:` order; rc≠0 if the order line names a pseudo missing from the table (the BFM empty-table incident). Hard register comes from `.greg`'s register-assignment lines if 2.95 prints them, else `-` (T3 records which).
- Dumps: `dumps.py` produces per-pass dumps for a standalone C file or for a real TU (the spliced unit — BFM's standalone compile was unfaithful, 427 vs 518 instructions) by running the product rule's own `$(CPP) $(CPPFLAGS)` output into `$(CC1)` with the unit's flags plus `-da` (all dumps) in `build/dumps/<prog>/<tu>/`; refuses an empty cpp output (`DUMPS CPP-EMPTY`, rc 3). `make dumps PROG= TU=` is the entry point so the flags never fork from the rule (G103). walls.py PASSES is reconciled to the observed suffix set + `maspsx` (walls.txt is empty, so the change is free) and `walls.py --check` additionally refuses a pass name not in the suffix set.
- Permuter: decomp-permuter pinned by commit in the image (`/opt/decomp-permuter`); our scorer in `tools/mmx6/permuter/masked_scorer.py`, bound by a wrapper `permute.py` without editing upstream (upstream PR #213 was never merged). Masking per R-pending-1 rules bought with byte evidence: objdump `-drz`; HI16/LO16/PC16 keep opcode+rs+rt and mask the low 16; R_MIPS_26 keeps opcode; internal `j` targets relative to function start; score = masked word mismatches + |length difference|; 0 means the masked words equal retail (`probe.retail_words`). `compile.sh` calls the product rule (as `probe.compile_obj` does). Iteration cap = the wrapper counts `iteration N` lines and stops the process at `--iterations`; "proves it iterated" = n ≥ requested and ≥2 distinct candidate sources scored. Guards from DK-15: hide `register … __asm__` pins before each cycle and restore after; refuse K&R seeds; any refused or zero-iteration cycle aborts rc≠0; a score-0 candidate is printed as a candidate, never banked (only bank.py banks, G61).
- Stored draft: `drafts/<prog>/<func>.c` (tracked, our C, never in a default build — G4), one real function, picked by rule: the first `draw` verdict in `build/draw/draw.jsonl` rank order with 12-40 words, no jtbl, in the exe; scaffolded by `decompile.py`, hand-made to compile, kept non-matching (if it matches outright, it banks through bank.py and the next one by the rule is drafted — a bank is never thrown away). A draft is stored because the milestone runs it again from a clean tree.
- Plateau = a permuter run whose best score did not improve over its last W=100 iterations (and > 0). `plateau.py` labels the masked residual of a draft (or the permuter's best) against retail by diff shape, first rule that holds: `length` (word counts differ), `isel` (opcode multiset differs) → G-expr/G-combine, `sched` (same multiset, different order) → G-sched, `regalloc` (same opcodes in order, only register fields differ) → G-alloc, `branch` (only branch polarity/target structure) → G-jump; each label prints the triage-table row ids to try. The R-pending-3 finding (no published taxonomy) makes this our own convention; the planted controls arbitrate it.
- Cookbook seeding (DK-14, G67): BFM's 1176 sections are read through its symptom index by a retriever, never whole; each inherited idiom whose symptom maps to a triage row becomes a line in `docs/codegen-map/inherited.md` (`symptom | BFM section | BFM pass | our pass group | status lead|re-proven C<nnnn>`). Only re-proven ones (a reproducer under our pin) become cookbook entries; leads stay leads. DC2 and mmx4 contribute nothing because neither has an idiom cookbook (measured above); inherited.md records that with its evidence rather than inventing entries.
- Cookbook index check is product (`tools/mmx6/cookbook_check.py`): every `cookbook/C*.md` has exactly one INDEX row with the same id and title as its `# C<nnnn> — <title>` line; every row resolves to a file; every entry tagged `idiom` carries ≥1 symptom tag from the vocabulary in C0002's tell column (tags `sym-<slug>`); C0002 has 0 `TODO`. `cookbook_add.sh` (harness) stays the only writer of INDEX rows; the check only reads.
- Coder tier: opus55 everywhere (one tier). Effort: medium everywhere — preset max5 has no hard rung, so the judgment-heavy map is split in two tasks (T4 front-end groups, T5 back-end groups) instead of marked high.
- Breadth: none; the map is serial judgment, ~6-12 levers. Est-ctx is driven by dump reading; dumps are grepped, never read whole.
