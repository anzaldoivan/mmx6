# C0487 — Too few arguments after relocdef: unprototype the earlier shared body's declaration line
tags: declaration,too-few-arguments,relocdef,shared-body,clear_object_slot,prototype,refusecause · date: 2026-11-16 · phase/task: 3.3/T3 · origin: mmx6 3.3 T3.c1 W309

Symptom: a dup member refuses at R2 with "too few arguments to function `clear_object_slot'" [relocdef func_8002CA14=clear_object_slot]. A sibling member in the same unit gates.

Cause: the exemplar calls the callee with no arguments. A shared body included earlier in the member's unit declares it with params, e.g. `M2C_UNK clear_object_slot(void*, void*);` (src/shared/rock_18/func_800EFADC.c:6). Members placed after that include see the prototype. Members placed before it do not, so they gate.

Move: change only that body's declaration line to the header spelling `s32 clear_object_slot();` (pilot_globals.h:15, C0434). Its calls with arguments compile to the same bytes. Check every includer's hash, and compare refusecause counts before and after over the programs that hold the symbol's rows.

Evidence (3.3 T3.c1): with that one line changed, 7 rows gate (rock_18 F00F4, F03C4, F0870, and rock_20 F2E94, F3164, F3610). Over 8 programs and 150 rows, 0 gated rows were lost. All 57 sha checks were OK. 9 other src/shared bodies declare clear_object_slot with params, so the same move may apply to them.
