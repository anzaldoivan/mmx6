# C0085 — Spill slots swapped: reload assigns slots in pseudo (declaration) order
tags: idiom,sym-spill-slot,G-alloc,greg,spill,decl-order · date: 2026-10-02 · phase/task: 1.7/T5 · origin: mmx6 repro

1. **Residual (tell)**: a temporary is in a spill slot at the wrong offset. The `sw $2,<off>($sp)`/`lw` slots of two spilled values are swapped against the target. The length is the same. `sym-spill-slot`
2. **Mechanism**: greg (G-alloc). After global-alloc, reload walks the pseudos in regno order. It gives the next stack slot to each pseudo left without a hard register. The regno order is the creation order of expand, that is, the declaration order.
   - src:gcc-2.95.2/gcc/reload1.c:797 "alter_reg (i, -1);"
   - src:gcc-2.95.2/gcc/reload1.c:2422 "x = assign_stack_local (GET_MODE (regno_reg_rtx[i]), total_size,"
   - a-side `.greg`: spilled 82 84 85 at 48 52 56 (`(const_int 52 [0x34])) 0)`).
3. **Lever**: swap the declarations of the spilled values. `int v2, v3;` gives v2 52, v3 56. `int v3, v2;` gives v3 52, v2 56. The priority of global-alloc decides which values spill (L05/L06). A spill that should not exist is a register-pressure lead (shorten a live range) or `sym-register-pressure`. Inertness checked: b has the same length, and the bytes differ.
4. **Byte proof**: repro/G-alloc/slot.{a,b}.c. `repro.py --lever L11` gives `LEVER L11 OK`. The compile is standalone under the pin. Retail anchor: none yet. Map row L11.
