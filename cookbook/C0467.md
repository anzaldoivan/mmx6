# C0467 — R4 rodata from a local fn-pointer table initializer: read it as an extern struct copied to the stack
tags: bank,r4,rodata,fn-ptr,table,extern,struct-copy,typecheck · date: 2026-11-14 · phase/task: 3.2/T4 · origin: 3.2 T4.c17 func_80040290

When: a draft's only rodata is a C-initialized local function-pointer table. The bank then stops at R4 with
`rodata needs placement (+n bytes)`, and `carve.py rodata` refuses `no-table`. A `carve.py data` row can also leave
the bytes unplaced and the hash red.

Move: read the table as an extern struct object and copy it to the stack. Write `extern FnTbl7 D_<addr>;`, then
`FnTbl7 t = D_<addr>;` and call through `t.fn[i]`. The struct copy gives the same bytes and leaves no rodata to place.
Put the typedef in a header under include/mmx6/, because typecheck refuses a type that the draft defines itself.

Evidence: 3.2 T4.c17, SLUS func_80040290 (29 words, R4 +28). The form came from the X5 twin func_80044BD8. With the
typedef in include/mmx6/types.h, the bank reached R5 with no carve row. T4.c2's carve.py data try left the hash red.
