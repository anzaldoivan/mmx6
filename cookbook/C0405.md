# C0405 — sched1 hazard tie: stores beat arg copies, so call args need pins
tags: regalloc,sched1,sched,hazard,call,argument,pin,dumps · date: 2026-11-07 · phase/task: 2.6/T32 · origin: mmx6 T32.c3 func_8001494C

Finding (mmx6 2.6/T32.c3, func_8001494C, pin-free 79/139 vs pinned 134/139). gcc 2.95.2 -O2, sched.c (sched1).
- Shape: values loaded, stored to globals, then passed to a call. Retail has them in a0/a1 with no copy.
  The draft needs `register asm("$4")`/`("$5")` pins for this.
- Mechanism: after regmove the copies `a0 = v` come after the stores. Each copy is its value's last use.
  The sched1 pass gives the stores and the copies the same priority.
- A tie goes to the larger `potential_hazard`. Stores use the memory unit and copies use none.
  So the stores move next to the call.
- MIPS `ADJUST_COST` makes anti and output dependences cost 0. So no source order lifts a copy above a store.
  The values stay live past the copies, local-alloc cannot tie them, and greg sees conflicts with a0/a1.
- See it in the `.sched` dump: "insn N has a greater potential hazard".
- Inert here: 11 spellings (store order, chained stores, folding into args, void cast, callee forms, volatile) scored 53-79.
- Route: keep the pinned form as `!FAKE: depin` and fix its remaining swap, or leave the function at its plateau.
  Its banked sibling func_80014B78 keeps the same two pins.
