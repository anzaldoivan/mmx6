# Key an overlay string to its function: own range first, then the exe, then other bases

Problem: mmx6 ROCK_X6.BIN overlays share load bases (30 at 0x800E9860, 24 at 0x800FA000, 2 at 0x801EA000). A lui+addiu
constant matched against "any program whose range holds the address" keys one overlay's code to another overlay's strings.

Move (`tools/mmx6/imgadapter.py strings`, 2.2 T2.c1): resolve an address constant in the program's own range first.
Then try the exe, which is always resident. Then try only programs at a different base.
Exe strings referenced from overlays are keyed this way (e.g. SLUS 0x8007693C from rock_00:0x801EE34C).

Check an "unreferenced" verdict: count raw pointer words equal to the address and I-type words whose low 16 bits match
it. 0 and 0 means truly unreferenced. Most overlay hits are unaligned 6+ printable-byte runs inside data, not text.
