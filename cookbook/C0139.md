# C0139 — Load/store order across bases: dead-store deletion, char aliasing, symbol bases decide what the scheduler moves
tags: lever,dead-store,flow,alias,char,sched,store-order · date: 2026-10-04 · phase/task: 1.8.1/T5 · origin: mmx6 W5

Memory-op ordering facts seen in gcc 2.95 PSX drafts:
- flow deletes an earlier same-address store when a later store overwrites it with no intervening aliasing read; if retail keeps both, put a char-typed global read (assigned to a local) between them (c45).
- a store sunk below a global load in retail hints the source statement reading that global came first: the scheduler cannot move a pointer-param store above a possibly-aliasing global load (c45).
- loads do not rise above char (u8/s8) stores through `self` (char aliases everything) (c4 c18 c21 c26 c61); sched1 hoists a load above stores when both have a known symbol base (c67).
Use: for load/store order residuals across different bases, change source statement order, the access type (char vs wider) or the base spelling (symbol vs pointer) before anything heavier.
