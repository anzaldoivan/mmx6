# C0105 — Typed struct/array global instead of M2C_FIELD byte offsets
tags: idiom,sym-global-reload,global,struct,M2C_FIELD,m2c,cse,base-register · date: 2026-10-02 · phase/task: 1.8/T9 · origin: mmx6 W0

1. **Residual (tell)**: The draft addresses a global through m2c's `M2C_FIELD(D_x, T*, off)` / byte-pointer arithmetic. It loses words to address recomputation or a different base register. The target uses one base plus constant offsets.
2. **Mechanism**: This is observed, not source-proven. A typed struct (or array-of-struct) global gives expand a single symbol plus constant offset per access. As a result, cse shares one base. A cast byte pointer builds a fresh address per access. Related: C0075, C0086.
3. **Lever**: Declare the global with a struct type (fields at the accessed offsets, padding elsewhere). Or declare it as an array subscripted by the index (`D_x[i].f`). Write field accesses instead of `M2C_FIELD`.
4. **Byte proof**: Manual wave W0 (1.8/T9) has these cases. SLUS_013.95:0x80042F20 went 3/12 → 12/12 (struct-typed global + array subscript). This closes triage P1.7-1 without L05/L06/L11 or the permuter. Also, rock_03:0x800EEDB8 went 22→50 (typed engine-object struct), and 67/67 after C-callee-decl.
