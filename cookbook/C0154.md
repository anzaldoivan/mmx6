# C0154 — Copy loops: base pointers and offset local declared inside each loop body, and an aligned tail via __builtin_memcpy
tags: lever,loop,preheader,gcse,hoist,base-pointer,block-scope,memcpy · date: 2026-10-06 · phase/task: 1.8.1/T11 · origin: mmx6 W11 SLUS 1BA1C

Symptom: a copy routine of several loops (save block, state copy) scores a fixed isel/length residual in each loop preheader. Retail holds a copy of each hoisted base address per loop. The draft with bases declared before the loop (or hand-hoisted, or pinned) has one shared copy or none.

Lever: declare the base pointers of each loop (`u8 *d = base + K; u8 *s = …;`) as block-scope locals inside the loop body. Declare the index offset local (`s32 o = i << k;`) there too. For nested loops, use the inner body. Use no register pins and no `do { } while (0)`. Then gcse hoists the base expressions and loop.c drops the per-loop copies into each preheader, as retail. A large aligned tail copy is `__builtin_memcpy` with s32 operands (aligned block-move loop, not the unaligned lwl/lwr form).

Case: W11 SLUS_013.95:0x8001BA1C (T11.c63, 192 → 201/201), rock_18:0x800ECE54 (T11.c64, 205/205), rock_20:0x800EE19C (T11.c68, 201/201, 0x3BC memcpy).
Related: C0109 (per-branch block pointer), C0114 (unaligned copy = __builtin_memcpy).
