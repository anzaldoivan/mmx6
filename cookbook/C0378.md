# C0378 — Two-global %hi reload after a join: first-reloaded takes first %hi reg, ladder inert
tags: regalloc,plateau,hi-lo,permuter,wall · date: 2026-11-03 · phase/task: 2.6/T21 · origin: mmx6 T21



Wall (mmx6 2.6/T21, func_80013DE8, 419/421).
- Shape: two arms each store byte globals A, B (`sb ..,%lo(A)($t1)`, `sb ..,%lo(B)($t0)`), join, then `A * B` reloads both.
- gcc 2.95.2 (-O2 -G0): whichever global is reloaded first after the join gets the `$t0` %hi pseudo, regardless of
  C spelling. `B * A` gives retail %hi regs but the wrong reload order. `A * B` fixes the order and swaps the %hi regs.
- Store order sweeps (C0135) score worse. Any arm store swap breaks the cross-jump.
- Also inert or worse: reg-pinned locals (C0141, C0182), address locals (C0079), an extra ref (C0080).
- Same for a shared base pointer (C0106), an arm block local (C0122) and the callee type (C0104).
- Permuter: 50 seeds x 100 iterations, all stuck at residual 2.
- Untried next: RTL dumps (`dumps.py` .lreg/.greg) to find the pass that orders the two %hi pseudos.
  Likely CSE of the reload addresses, not global-alloc priority.

Closed (2.6/T30, 421/421, C0400). The RTL dumps showed the order is not set by the reload, CSE or gcse spelling.
- gcse numbers the hoisted pseudos the same in both spellings (640 width, 641 height).
- greg decides. In `B * A`, height dies first (live 82 vs 86) and wins `$t0`. In `A * B` both are 84, and the tie goes to the lower pseudo.
- The pseudo order comes from the gcse hash of the symbol names. `A * B` with the names `g_tilemap_width`/`g_tilemap_height` matched.
