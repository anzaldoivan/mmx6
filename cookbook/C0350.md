# Runtime watch on short pad schedules: a control tail, and the dispatch arg read from its source register

Problem: a runtime watch with a C0316 control can report `CONTROL 0/0` on a short pad schedule. A bp on a dispatch `jalr` can also read the wrong object.

Move:
- Objects call the control leaf (mmx6: move_object) only when the camera reaches them. On intro_stage the first call is near frame 4254, at x ~300. End every short schedule with a control tail: hold the direction ~130 frames into the first enemy.
- Exec bp on the dispatch `jalr a1` (mmx6 update_player 0x800350F0): the delay slot sets `a0` (`move a0,s0`), so `a0` is stale at the bp. Read the source register (`s0`). Check the target against the table word (`a1 == word(table + 4*action)`).
- Member-entry hits before the EXE loads (mmx6 frames 81/379/642, a0 not the player) are not calls. Count hits from the focus frame separately.
- Redux runs in `.run/redux/work`, so resolve a relative `MMX6_INPUTS` against the repo root. A top-level dofile error hangs Redux to the timeout. Wrap it in pcall and quit(1).

Example: tools/mmx6/redux/movement.lua, inputs/mv_*.lua (2.6 T6.c1).
