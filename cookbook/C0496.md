# Repair-lane exemplar check: grep goto as well as asm(, or a twin gates live but cannot bank goto-free

Symptom: in 3.3 T7.c1 (W310), rock_23 0x800F128C, rock_44 0x800FAEAC (key 9561efb3) and rock_36 0x800FD39C (f52c9ed3)
gated live. But the shared body that the live run cut from the exemplar holds a `!FAKE` goto
(src/shared/rock_02/func_800F2584.c:67, src/shared/rock_07/func_800F50EC.c:39). A member that includes it would add a goto
(M27, cap 355).

Cause: T6's list builder (.run/3.3/t6/waves.py) marked pinned exemplars by `asm(` only (C0448), so goto exemplars
stayed in the wave lists.

Move: check each key's exemplar body when you build a repair wave list. That body is its src/shared file, or its
function's body in its unit. If it has `asm(` or `goto`, mark the key as pinned.
Ledger its members `member-of:<exemplar prog:vram>`, like C0448.

A key of this kind may
already have run live. Then revert the member units to their HEAD INCLUDE_ASM lines and set the registry rows to `refused M27`.
The exemplar cut can stay, because the goto only moves and the count stays the same.

Evidence: 3.3 T7.c1 walls.tsv/rows.tsv (.run/3.3/t7/c1/), 3 of 125 W310 rows.
