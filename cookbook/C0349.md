# Typing player-state bases in batch: one unit, one fleet-quick, diff.sh only on red

When: many functions of one unit (SLUS 32208.c holds the movement folder files) read `M2C_FIELD(arg0, T*, N)`.
Move:
- Type each base, lift every read, then run one `make fleet-quick` for the whole batch.
  Run `diff.sh` only when the build is red, to find the function that moved.
- A `void* arg0` with a prototype elsewhere keeps its parameter. Add `struct X4_PlayerObj* self = arg0` (C0327).
- An `s32 arg0` declared `s32` in other files keeps it. Add `self = (struct X4_PlayerObj*)arg0`.
  The call-site cast moves into the local.
- A parameter whose only other prototype is unprototyped (`f()`) can be typed in place.
- Byte-wide increments of an s8 member keep their bytes as views (`*(u8*)&self->action_phase`, C0326).
Traps:
- `diff.sh` needs git's `--no-pager` in the image (no `less`).
- `mx.sh push` takes only `waves/` paths. A host edit needs a full `mx.sh sync`, then fleet-quick (~50 s).
- A decrement view `self->m = -1 + *(u8*)&self->m` emits `addiu 0xff` (1 line). Write `--*(u8*)&self->m;` (0 lines).
- Inside an expression, `-1 + *(u8*)&x` and `*(u8*)&x + -1` also emit `addiu 0xff`. `*(u8*)&x - 1` matches but the
  floor counts it as an offset. `(u8)self->m - 1` matches and is not counted (T5.c4).
- objfields census does not see reads inside a function-like macro body. Take a DC7 `read by` from `--census`.
  A base retyped away from PlayerObj leaves that member's `read by` note bad: re-point it.
- `make expected` depends on `build`, so it fails on a red tree. Build expected from HEAD sources first and copy it
  under `/work/.run/` (sync keeps it). Then restore the edits.
- A failed sha check deletes `build/SLUS_013.95`. Rebuild it with `mipsel-linux-gnu-objcopy -O binary` from the elf.
- Container scripts go under `waves/` and travel with `mx.sh push`. The host's `.run/` is never synced.
- zsh does not word-split `$(cat list)` in a variable. Run batch lists through `bash -c`.
