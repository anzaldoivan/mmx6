# sym+K row base: compute the scaled index into an s32 local after the base copy, add +K last

Symptom: the row address is `base + idx*K + F`. Retail issues another global's high half between the base's hi and lo.
Every single-expression spelling (`(u8*)(idx*K) + (s32)(t + F)`) keeps the hi/lo pair together or folds +F early.

Lever: split the address into locals. Copy the base pointer first, then write `o = idx * K;` into an s32 local.
Then write `q = t + F;`. Clear or reuse the copy if the source does. Only then form `p = (T*)(o + q);`.
This statement order sets when the multiply and the +F add issue, relative to the other global's load.

Related: C0180 (sym+K row base kept split by an s32 offset local). C0202 and C0206 (s32 locals before the store that
fixes load order). Origin: W45 SLUS func_80016704 (c33 narrowed retry, after c8 plateaued at 23/31 sched across ~95 variants).
