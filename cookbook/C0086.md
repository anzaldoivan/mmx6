# C0086 — Struct base reloaded per member store: name the pointer-derived base in a local
tags: idiom,sym-global-reload,G-expr,cse,alias,struct · date: 2026-10-02 · phase/task: 1.7/T6 · origin: BFM §193-H re-proven

1. **Residual (tell)**: the code loads a pointer from a struct (`lw $5,0($4)` for `p->a`) again after each member store through it. At that place, the target loads it once (or the reverse). `sym-global-reload`
2. **Mechanism**: cse (G-expr). A member store through the loaded base and the base load itself are both varying-address /s MEMs. Thus the store may alias the base. The cse pass drops the cached load, and the re-read of expand stays.
   - src:gcc-2.95.2/gcc/cse.c:1832 "true_dependence (x, full_mode, p->exp, cse_rtx_varies_p)"
   - src:gcc-2.95.2/gcc/alias.c:1269 "return !fixed_scalar_and_varying_struct_p (mem, x, varies);"
   - a-side `.cse`: the third store goes through the fresh pseudo 84 (`(set (mem/s:SI (plus:SI (reg:SI 84)`).
3. **Lever**: for one load, name the base in a local (`struct S2 *q = p->a; q->x = 1; q->y = 2; q->z = 3;`). To reload it each time, spell `p->a->` per store. The a-side has 10 insns, and the b-side has 8.
4. **Byte proof**: repro/G-expr/baseload.{a,b}.c. `repro.py --lever L12` gives `LEVER L12 OK`. The compile is standalone under the pin. Retail anchor: none yet. Map row L12. The BFM §193-H (gcc 2.7.2) title is re-proven under 2.95.2.
