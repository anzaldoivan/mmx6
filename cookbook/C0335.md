# Copy a short shared tail instead of a goto: jump2 cross-jumps the copies back

Problem: a `goto tail;` to a short shared tail (one store plus `return`/`break`) is unmarked goto debt.

Move: write the tail out in each arm: the store and the return or break. The jump2 pass of gcc 2.95
merges the identical copies back into one block. The bytes stay the same and the goto is gone.
Related: some gotos all jump to one final test. An else-if chain of the sign tests ending in `else return;` replaces them.

Limits: the copies may differ in register use, or the tail may be long. Then cross-jump does not merge them, or it
merges a different block. Keep the goto, marked (rock_10 FA128, FA2B0, rock_11 F04E0, rock_22 F8BAC).
C0115 is the reverse lever: a goto that stops cross-jumping.

Evidence: 2.5/T11.c4. Copied tail: rock_11 EED14, rock_22 EC670, F3444, F5F50, EBA8C. Else-if chain with else
return: rock_22 F9B30, F9C98, F9E74, F7850. Each is byte-identical per rock sha.

Exception (2.5/T11.c2): copying a one-store clear arm (`v = 0`) is not merged back. gcc emits a set-on-compare
sequence instead and the bytes move. Eight `goto clear` sites in shared files failed this way (EFC4C, F011C, F036C).
Copies of stores with side effects did merge (F0794, F1AEC, EFDB0, F0258, F5378, F6484).
A copy that duplicates a register pin raises `pin`, a `down` kind, and commit_task refuses it (shared F1B50, T11.c1).
A copied block may match without the register pin the original needs: try the copy without the pin first
(rock_07 func_800EAE90, T11.c9).
