# C0383 — x4port types a base from body declarations only, and a repin line shift breaks code anchors
tags: x4,x4port,repin,homed,anchor,namesqueue · date: 2026-11-06 · phase/task: 2.6/T31 · origin: 2.6 T31.c2

When: an x4port port() rewrite reads declarations to type a base (2.6 T31.c2 homed member map).

- The draft's extern text holds callee prototypes with parameter names. Those must not type a body's base.
  The first try typed `self` as `X4_ObjectHeader` from a prototype and made 3 false refusals.
- Type a base only from declarations in the body, and from top-level declarations that are not prototypes.
- A repin that shifts lines in a file breaks `code:` anchors in config/symbols/basis.tsv and names-verdicts.tsv.
  The fleet's namesqueue rung catches it as `code-anchor-missing`. Repoint the line digits per C0345.
- The homed map (`homed_members()`): `v->unkNN` on a `struct X4_T` that is homed, with no member of that name, becomes the one member at +0xNN.
  The offset comes from config/types/fields.tsv, else from the home header's `// +0xNN` comments. None or two members: held with `member:`.
  It un-held 53 of 54 units at 807a01b -> 4e16dfc.
