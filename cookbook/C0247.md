# Re-port an upstream lane at a new pin: compare definitions, hold the header

When: a set of src files was ported from a sibling repo at commit A and must move to commit B (x4port --repin, T4 1.10).

- Compare per function *definition* only (cards.body_of, comments and whitespace dropped), never the whole file.
- A whole-file re-port pulls upstream prototype retypes. These collide with sibling ported files in the same TU.
  They also collide with the declarations that declsync wrote. In 1.10/T4 round 1 this gave 226 `conflicting types`.
- Definition same -> header-only rewrite (pin line). Definition changed -> replace the definition.
  Keep the file's own declarations and `// !` marks.
- Hold the shared header (x4.h) at A when B renames struct members. Our non-adapted files use the old names (`structure has no
  member`, ~35 files). Bodies that need B's new macros/members then fail and stay at A too.
- Gate each changed body three ways: compile, link, then masked object compare against a `make expected` baseline. Most hash
  breaks were upstream dropping the bank's `((void (*)())f)(...)` unprototyped-call casts.
- A port() that preprocesses when the body holds `#ifdef` emits macro-expanded text (FIXED(8) -> `((s32)((8) * 0x10000))`):
  it matches but reads worse. Check changed bodies for it.
- After editing included .c/.h: clean rebuild (C0232), a plain `make build` says Nothing to be done.
- Re-running the repin with no hold list re-ports the holdouts: restore them (git checkout) after each run.
