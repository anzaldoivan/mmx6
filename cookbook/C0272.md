# Classify a refused name lead: object start, inside an object, or out of image

Use when a community address lead has no symbol and you must decide whether it may take one byte-neutrally.
- Text: object start iff splat glabel | jal target | Ghidra func | config/boundaries.txt fstart. Otherwise it is a mid-function
  site (patch address). Its container is the preceding start. A spot after `jr ra` can still be a branch target inside the function.
- Data/bss: object start iff a splat dlabel that code references (lui %hi/addiu %lo or a data .word).
  It must not sit inside a known named object. Else it is inside-object, container = nearest preceding dlabel.
  Bss extents are as-disassembled, not proven.
- Out of image: scratchpad 0x1F800000-0x1F8003FF, or at or past the exe bss end (overlay/heap).
- Adding `D_<VRAM>` to config/symbols for an existing splat dlabel is byte-neutral, because splat already emits the label.
  Confirm with a clean rebuild hash and `make fleet`.
- A dlabel in a run of odd-address byte-field labels is likely a struct field, not an array: mark ambiguous, add nothing.
Inside-object leads become field items keyed to the container symbol (struct work), never symbols of their own.
