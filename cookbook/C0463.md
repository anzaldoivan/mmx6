# C0463 — A v0 pin on constants after a call: one multi-set local, read the rival into a function-scope local
tags: lever,pin,v0,call,local-alloc,global-alloc,regalloc,sched1 · date: 2026-11-14 · phase/task: 3.2/T3 · origin: mmx6 T3.c5 check_giga_attack

## Problem
A `$2` (v0) pin holds a value set right after a call (3.2 T3.c5, check_giga_attack 0x8003E344 `c` $2). Unpinned, 19 lines differ.

## Mechanism
- Local-alloc never gives v0 to the first pseudo born right after a call, because the call's REG_UNUSED v0 is still live there.
- sched1 sinks a load that only feeds a branch down to the branch.

## Move
- Put the constants in one multi-set local (C0451 reuse).
- Read the competing value into a function-scope local first: `k = self->facing; if (k != 0)`.
- Both then go to global-alloc, where ref density (docs/codegen-map/G-alloc.md L06) decides who gets v0. Verify by the SLUS hash (C0367).
