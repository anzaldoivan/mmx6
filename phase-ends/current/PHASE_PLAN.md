## Rationale
- Manifest location: `purge: extracted/` + `glob: extracted/**` (firewall.txt:20-21) make any tracked file under `extracted/` an offender (`under_rules` audit_public.py:75-82, applied to every tracked path in `main` :163-167); `audit_public.py` is harness and cannot gain an exception; fnmatch has no negation, so carving `extracted/retail/manifest.jsonl` out takes a chain of ~20 character-class globs that weakens G13's derived-list discipline. The constitution's layout already names `manifest/` (:249). So the committed manifest is `manifest/retail.jsonl`; `extracted/` stays a whole purge path; `.gitignore:19-23` collapses to `/extracted/`. Developer decided at approval: the manifest is committed at `manifest/retail.jsonl`.
- Extractor runs natively on the Mac (PY, stdlib only) as the canonical command, because 1.2's Ghidra is native on the Mac and needs the bytes, and `mx.sh pull` refuses `extracted/`. The same code also runs in the container (python 3.12, Linux) for the third determinism datapoint and for the dumpsxiso comparison: two interpreters and two OSes agreeing is stronger than two identical runs (G21 spirit, M6). One command: `make extract` (Makefile var `PYTHON ?= python3`, `CUE ?=` the `/disc` path), overridden on the Mac.
- Manifest shape: one JSON object per file written under `extracted/retail/`, keys sorted, records sorted by `path`, no timestamps, `\n` endings, so the file hash is the manifest hash. Coverage is asserted (G19): line count == files written; every member index 0..58 present. Compressed members write both the stored and the decompressed payload, each with its own line, so both forms become forbidden hashes.
- XA/STR are written raw at 2336 B/sector for Form-2 sectors (subheader + data + EDC), matching dumpsxiso (C0007), so the reference comparison is byte-direct; demuxing XA channels / STR frames is not needed (never part of N) and is not done.
- `ROCK_X6.DAT` (50.9 MB) is extracted and hashed as an ISO file; its internal structure is not in the milestone and is left for the phase that needs it (formats.md marks it unknown).
- Reference comparison: dumpsxiso covers all 9 ISO files (so "sampled" = all 9); no reference exists for `ROCK_X6.BIN` members, so their check is the length cross-check (descriptor size vs extent; decompressed size vs the format's declared size) plus the game's own loader semantics from T2; formats.md states "no reference extractor exists" rather than claiming one (G35).
- Dumpsxiso is built from a pinned commit inside the image (Dockerfile edit; product file), not installed on the Mac: one pinned toolchain place, no new Mac dependency. Three lines: dumpsxiso extracts ISO9660 files incl. XA form-2; our toolset has no independent ISO reader; delta = an independent oracle for the 9 files.
- Scratch cap: `make scratch-check` (`tools/mmx6/scratch.py`) sums `.run/`, warns at ≥ 20 GB (rc 0, `WARN` line), fails above 25 GB (rc 1); `extract` depends on it; values as Makefile vars. `.run/README.md:5` records them. No hook, no harness key.
- Split: T1 ISO extractor + manifest + scratch (the core every other task uses); T2 the `ROCK_X6.BIN` format probe (evidence → formats.md, expert alone, no coder: reading disassembly is the work); T3 member extraction + decompression; T4 reference comparison (independent of T2/T3, runs after T1); T5 promotion, determinism, commit of the manifest. T2 and T4 can run in either order after T1.
- Coders: T1, T3, T4 multi-file code → `coder: opus55`. T2 probe + one doc → `coder: none`. T5 config edits + checks → `coder: none`.
- Effort: all medium; preset max5 has no hard rung. The one judgment-heavy step (compression semantics from the loader) is split out as T2, whose done-when is testable: the decoder spec yields, for every member, an output whose length equals the declared size (T3's verify).
