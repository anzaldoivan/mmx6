# C0282 — Tie a boss update function to its stage: type-id link, state-table reach, health word

Use: a community or objects row says "function F is boss B's update". You need a code basis, not a vote.

1. Type-id link: the object type id (objects.tsv `temp#1:0xNN`) indexes the overlay's ObjectTempTable.
   That slot holds the linked function L, the entry of the object.
2. Reach: from L, follow its own state table to F. L reads a label-bounded pointer table.
   F sits at `[0]` or a few hops away (jal, hi/lo refs, pointer-table words).
   Check that no other object of the same overlay reaches F.
3. Identity word: F or a callee reads the boss-health word for B. Match the cited word against our overlay bytes.
4. Basis row: `code:<path>:<line> via=<anchor>`. The line is in tracked C.
   It holds the anchor as a whole word.
   namesqueue `check` refuses a row whose line lacks the anchor (`code-anchor-missing`).

Traps:
- Several overlays can share one body through `#define`. Admit per overlay only when each overlay has its own table entry.
  The shape is in src/rock_08/E9860.c:374-376. A shared body with no per-overlay tie stays held.
- Renames shift lines, and a header adds 3. Re-point code refs after a rename.
  Skip `//` lines: the header names the same anchor.
- A basis.tsv `code` row carries only the code ref. The check reads every `;` part.
  So a trailing `; objects.tsv:N` is refused as code-no-via.
