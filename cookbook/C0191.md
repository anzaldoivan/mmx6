# Retail narrows a parameter at entry: declare it narrow, fix the TU prototype

Symptom: the body matches only with a `u8` (or `s16`) parameter, or with an `s32` return, while the TU's prototype says `s32` / `void`.
Lever: keep the draft's narrow parameter / real return type; the gate's tusync (or a hand edit of the TU prototype) makes the TU agree. Callers pass constants, so they are unaffected.
Cases: W20 rock_07 0x800F6B94 (u8 arg, TU proto s32 → tusync), SLUS_013.95 0x80018290 (s32 return, TU void → tusync) (T20).
See also: C0124 (TU consensus declaration), C0185 (void return).
