# C0478 — Stack-pointer and trap stubs: what C can and cannot produce (sp as a value, sp load, break code)
tags: stack-pointer,sp,hand-asm,not-c,break,trap,volatile,lui-ori,length,plateau · date: 2026-11-15 · phase/task: 3.2/T6 · origin: mmx6 T6.c1, T6.c18 func_80013AE0, func_80013B04, func_80013BE4

Can: in a frameless leaf, a zero-size local array has the stack pointer itself as its address, pin-free.
Can: storing through a volatile cast of a constant address can give the lui/ori address form, not a folded hi/lo.
Cannot: set the stack pointer to a constant, or load it from memory and return.
Only alloca and frame setup move it, and `__builtin_longjmp` builds a frame and jumps (11 words, not 6).
Cannot: an unguarded `break` with a chosen code. gcc 2.95 has no trap builtin.
A divide by constant zero is deleted when unused, and gives a guarded break with code 7 when stored.

Verdict: such stubs stay INCLUDE_ASM with a Blockers row naming the mechanism, as X5 keeps its twin in hand asm.
