# C0141 — Numeric register pins on constants decide which constant loads early when order sweeps cannot
tags: lever,register-pin,regalloc,constant,store-order · date: 2026-10-05 · phase/task: 1.8.1/T6 · origin: mmx6 W6

Symptom: two constants stored back to back load in the wrong order or into each other's register. Examples are hp/damage bytes and a shared 1 for several byte stores. Every statement-order permutation gives the first-written constant the early register.

Lever: hold each constant in a block-scope register local with a numeric pin (`register s32 a asm("$2") = 8; register s32 b asm("$3") = 4;`). Assign them where retail loads them. Then store. Allocation, not statement order, decides which constant loads early. The lever also works for an address local pinned so that its store lands right after a byte load (prologue order).

Evidence: phase 1.8.1 T6 rock_24:0x800F0B90, rock_10:0x800EAF28, rock_09:0x800EBFA4, rock_15:0x800EA770, rock_38:0x800FA54C, rock_22:0x800EFAEC, rock_02:0x800F4620 (logs/T6.c<k>.md, waves notes).

Check: spell the pin numerically (C0134). Use the lever only after order sweeps (C0135) stall on a register swap.
