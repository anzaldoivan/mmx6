# C0116 — Hold an index sub-expression in a local to stop constant reassociation
tags: lever,reassociation,index,pseudo,local,lui-order · date: 2026-10-03 · phase/task: 1.8/T13 · origin: mmx6 W4

1. **Residual (tell)**: Retail evaluates a computed index such as `a + (b*4 - 1)` in written order. But the draft folds the constant onto the other operand (`(a-1) + b*4`). This shifts an add and a register.
2. **Mechanism**: This is observed. The compiler gcc 2.95 reassociates constant terms of an inline index expression. A value held in a named local is a separate pseudo. The compiler does not reassociate it across the assignment.
3. **Lever**: Hold the sub-expression in a local (`t = b*4 - 1; x = T[a + t];`). Related: a local reused for two disjoint ranges stays one pseudo. To free the register, use a second local. An assignment of the index local inside an outer subscript (`T[(i = U[k])]`) sets which table's high-half address loads first.
4. **Byte proof**: In wave W4 (1.8/T13), rock_08:0x800EBEA0 went 228 → 276/276 (banked at the W4 regate).
