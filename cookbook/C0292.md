# C0292 — Self-test a role-file layout before any file moves: the role_tree plant (unit -> wrapper + subdir role)
tags: layout,role,self-test,plant,bank,include · date: 2026-10-31 · phase/task: 2.4/T5 · origin: mmx6 T5.c1

Problem: tools must handle bodies and INCLUDE_ASM lines in role files (`src/<prog>/<sub>/*.c`, included by a thin
unit). No such file exists yet, so build-based self-tests only exercise the flat layout.

Move: `layout.role_tree(prog, tu, root)` (tools/mmx6/layout.py) is a context manager.
- The unit `src/<prog>/<tu>.c` becomes a thin wrapper `#include "selftest_role/<tu>.c"`.
- The role file holds the unit text verbatim. Its relative `.c` includes are re-pointed from the subdir.
- Put the role in a SUBDIR. A same-dir role never tests "include relative to the found file".
- Token check old vs new via the Makefile cpp (C0291). The binary is unchanged by construction.
- On exit it restores the unit bytes and deletes the role file (and an empty dir). It refuses when the role text
  was left edited or the unit sha1 differs.
- Each tool's self-test runs its controls twice: `controls(role=False)`, then inside `role_tree` on its own unit.

Traps:
- Some tools restore `src/` from a snapshot at teardown. Take that snapshot AFTER entering role_tree. Otherwise the
  teardown deletes the role file and the role_tree exit check fails.
- The Makefile `build/%.c.o` pattern would compile a role file standalone, without common.h. Recompile only files
  that are `segment.c_units` rows. Role files have no .o.
