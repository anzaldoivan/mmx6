# Parallel naming drafts: read-only drafters, one proposal TSV each, one checker

Problem: several coders naming symbols at once collide when each also edits headers (T7 pass 1: refs shifted, races on the same files).

Move (2.6 T14.c1-c5):
- Split tokens by owning file group. Each drafter gets `tokens.<G>.tsv` + `files.<G>.txt`. It writes only `logs/T14.props.<G>.tsv`, 10 columns: token verdict name basis-kind basis-ref relation neighbour evidence clause prior.
- Drafters edit no source, so every `code:<path>:<line> via=<anchor>` ref stays valid until the single apply step, which refreshes refs after its own header inserts (C0286).
- One checker: `.run/2.6/T14/props_check.py <props> <tokens>`. It wants one row per token and a basis on every admit row. Each anchor must be a whole word on the cited line. Names must be snake_case, unique in the merged set, and unused in src/include. Run it per group and on the concatenation (catches cross-group name clashes).
- Fields go to a separate drafter (struct consistency): one row per (struct, offset) in fields.tsv's columns plus verdict/clause/sites.

Result: 5 drafters in parallel, 0 collisions, merged `PROPS OK 148` first try.
