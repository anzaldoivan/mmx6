# C0136 — do { call(); } while (0) is a haifa-sched barrier that keeps a call's arg move in its delay slot
tags: lever,sched,delay-slot,call,barrier,do-while · date: 2026-10-04 · phase/task: 1.8.1/T5 · origin: mmx6 W5

Symptom: a call's argument move is hoisted above the preceding independent stores, so a store lands in the call's delay slot where retail has the move.
Lever: wrap the call statement in `do { f(x); } while (0);`. The loop note is a scheduling barrier for gcc 2.95 haifa-sched: the move stays next to the call and fills the delay slot as retail. A dead label/goto does not work (jump deletes it).
Evidence: phase 1.8.1 T5 c72 (retry of c43, 118/121 -> 121/121), logs/T5.c72.md.
Check: probe with plateau; if the residual is store order rather than the delay slot, see the L07 sweep entry.
Second case: phase 1.8.1 T5 c74 rock_09:0x800ECD20 (108/117 -> 117/117): tail stores wrapped in `do { ... } while (0)` with a constant held in an s32 local assigned just before the `do`; logs/T5.c74.md.
