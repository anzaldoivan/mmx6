# A multiply by 48 (0x30) of a call result: `m = f() * 0x10; x = m * 2 + m;`

Symptom: the code sets a field to a call result times 0x30. Our shift/add expansion orders differently or adds a register copy, and the argument moves of the next call land late.

Cause: gcc expands a plain `* 0x30` (and `(m << 5) + (m << 4)`) through a different shift-add sequence than the retail source spelling.

Lever: split the product. Write `m = f() * 16;`, then `field = m * 2 + m;` (or `m * 3`). The intermediate local carries the x16 result.

Evidence: W14 rock_08 F15E8 (46 → 64/80, then 80/80), rock_03 ED2F4 (77/77), rock_11 EA84C (44 → 52/54). The gate R2 of rock_11 EA84C is for a TU clash, not the lever. Three cases.
Related: C0146 (`(x << 3)` not `* 8`).
