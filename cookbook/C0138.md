# C0138 — A value-in-register shared tail across arms = per-arm constant stores merged by cross-jump, not a shared local
tags: lever,cross-jump,jump2,if-else,tail,store,constant · date: 2026-10-04 · phase/task: 1.8.1/T5 · origin: mmx6 W5

Symptom: retail has a value-in-register shared tail (`sb v0,X(v1); sb v0,Y(v1)`) reached by several arms setting different constants; a draft with one shared value local stored after the join does not match.
Mechanism: the source had each arm write its own constant stores; jump2 cross-jumped the identical store tails into one. Modelling it with a shared value local gives different allocation/order.
Lever: write the stores directly in each arm with that arm's constant; let cross-jumping merge them. Per-arm calls or stores also keep arms apart where retail keeps them separate (c20, c52).
Evidence: phase 1.8.1 T5 c31 (logs/T5.c31.md), c20, c52. Related: C0083, C0103, C0111, C0115.
