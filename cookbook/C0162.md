# A callee-saved swap between two pseudos close in priority: wrap one use of the winner in `do { … } while (0)`

Symptom: two values live across calls get each other's callee-saved registers; the rest of the body matches.
Cause: global-alloc orders pseudos by refs weighted by loop depth over live length; the two are within a hair.
Lever: wrap one store of the pseudo that should win (here the selected index written inside the search loop) in `do { sel = i; } while (0);`. The loop notes the wrapper emits raise that pseudo's loop-weighted ref count, so it is allocated first.
Evidence: W13 rock_18 EA0E8 (c2 185/194 -> c59 194/194, 1 probe).
Related: C0136 (do-while(0) around a call), C0160 (copies through an s32 local raise insn count), C0147.
