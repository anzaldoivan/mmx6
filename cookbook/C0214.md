# Table+index sum in a fresh pointer local, empty `do {} while (0);` after the base copy, mask after the sum

Symptom: a byte table indexed by a computed row (`t = table; i = sub + stage * 2; t += i; v = base[*t]`) with a
bit mask `b = (1 << arg) & 0xFFFF` tested against the result. The draft sits at 17/19: the table+index sum lands
in the table base's register and the mask is scheduled too early.

```c
u8 *p; u8 *t = D_tbl; s32 b; s32 i;
do {} while (0);
i = E.substage;
i += E.stage * 2;
p = i + t;
b = (1 << arg0) & 0xFFFF;
return ((((u16 *)&E) + *p)[K] & b) != 0;
```

Lever, all three together:
- The sum goes into a fresh pointer local `p = i + t`, not `t += i` (new pseudo, own register).
- An empty `do {} while (0);` right after the table base copy splits the block so the copy is not merged with the index work.
- The mask is computed after the sum, not in the declaration.

Operand order alone (C0212 negated subtract) stayed 17/19.

Related: C0212, C0210, C0116. Origin: W50 SLUS func_800533F4 (c33 narrowed retry after c18 17/19).
