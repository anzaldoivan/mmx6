# C0109 — Pointer to a global declared per branch block stops one address being reused across arms
tags: lever,cse,global,pointer,block-scope,length · date: 2026-10-03 · phase/task: 1.8/T11 · origin: mmx6 W2

1. **Residual (tell)**: The draft is one instruction short (a length plateau) where two branches each address the same global object. The draft computes the address once and reuses it across both arms.
2. **Mechanism**: A pointer to the global hoisted to function scope lets cse/loop keep its `%hi/%lo` sum live across the branch. Retail recomputes it in each arm.
3. **Lever**: Declare the pointer to the global inside each branch block (`{ struct X4_PlayerObj *p = &D_…; … }`), not once at function scope. In a multi-block body, declare it only in the blocks that address it.
4. **Byte proof**: In wave W2 (1.8/T11), rock_06:0x800EA9E0 went 67 → 123/123 (with the else compare written `self > player`), banked. Also, rock_06:0x800F1EC4 340/340 used the same block-scoped player pointer, banked after a plumbing re-gate. Both levers are live by `harvest.py --inert-wave W2`.
