# Host function-start census from tracked files only

Use: a host tool (no container, no ignored `.run/`) that must decide "is this vram a function start / data symbol" per prog.

- `config/ghidra/<prog>.jsonl`: first record `k=program` (name, image_base). `k=func` addr = function starts. `k=data` and `k=label` = data symbols.
- Keep only addrs inside the prog's memory blocks. The exe names them `RAM`/`CODE`, overlays `ram`. Match the name case-insensitively, or every exe record drops silently. This excludes GTE 0x20000000 and scratchpad/IO 0x1F80xxxx.
- Add the splat names our src defines: `INCLUDE_ASM(..., func_X)` and C definitions `^type func_X(...` per `src/<prog>/` (shared: `src/shared/<prog>/`). Ghidra misses some (e.g. small handlers at 0x80054290).
- Regex trap: with `re.M`, a tail like `\([^;]*$` crosses newlines, so findall swallows the next definitions (43 of 313 found). Use `[^;\n]*$`.
- `config/oracle.proto-*.functions.tsv` and `config/symbols.*.txt` add a few. Overlay load groups by image_base (C0267). Resolve `ovl_<base>` to the single member holding the address. Several members holding it means ambiguous.
- Ref: tools/mmx6/namesqueue.py `sets()`.
