# C0399 — OT link words: P_TAG bitfield setaddr fixes the 0xFFFFFF/0xFF000000 hoist order
tags: lever,bitfield,setaddr,P_TAG,ordering-table,mask,hoist,loop · date: 2026-11-07 · phase/task: 2.6/T29 · origin: mmx6 T29.c1

Lever (mmx6 2.6/T29, func_80013530 147 -> 150, func_80013788 131 -> 134, no pins).
- Shape: ordering-table link words written by hand, `x = (x & 0xFF000000) | ((u32)p & 0xFFFFFF)`, in a loop.
- Residual: hoist order of the two masks (C0380). Retail does `lui 0xFFFFFF` first.
- Fix: PsyQ `setaddr`/`getaddr` through the `X4_P_TAG` bitfield (`addr:24, len:8`, include/mmx6/psyq_api.h:70):
  `#define SETADDR(p,a) (((X4_P_TAG*)(p))->addr = (u32)(a))`, `#define GETADDR(p) (((X4_P_TAG*)(p))->addr)`, then
  `SETADDR(mode, tile); SETADDR(tile, GETADDR(ot)); SETADDR(ot, mode);` (precedent src/SLUS_013.95/80022928.c:161,199).
- Mechanism: gcc 2.95 `store_fixed_bit_field` masks the value with 0xFFFFFF first.
  It clears the field with 0xFF000000 after that, so 0xFFFFFF is hoisted first.
  The target word's load stays at the store, which keeps the `lw` placement.
- Tell: `sb 3(p)` byte stores beside the masked words are the matching `setlen`.
- Hand-masked temps that only reorder (`lo = p & 0xFFFFFF` early) fix the masks but sink the `lw` (132-138).
- Limit (2.6/T32.c1, func_800144DC): all three links as SETADDR gave 90, down from 98.
  Retail masks one pointer early, with `and rX,p,0xFFFFFF` before the target `lw`.
  Keep that hand `& 0xFFFFFF` temp, and use SETADDR only where the mask sits at the store.
  Check the `and` vs `lw` order in retail before converting each link.
