# C0482 — Declaration conflict in one unit: keep the type the harder body needs, cast in the other user
tags: declaration,conflicting-types,extern,cast,bank,codegen · date: 2026-11-15 · phase/task: 3.2/T7 · origin: mmx6 3.2 T7.c2 W307

Problem: a bank's draft needs symbol X declared as `s32 X[]`. Another user in the same unit declares it u8, and the bank refuses the conflict (R2 conflicting types).

Recipe (3.2 T7.c2, func_8001717C, D_800E1550):
- cc1 computes addresses from the declared type. A u8 declaration plus casts gives 83/104, not 104/104. So does a u8[] declaration with an s32 array #define alias.
- So change the other user instead: declare `extern s32 X[];` there and cast at its access (`*(u8*)X = 0;`), then re-probe that function (func_80016950 stayed MATCH 63/63).
- Settle a declaration conflict inside one unit on the type the harder function needs, once the other user's probe stays green.
