## Rationale
- Order: T1 makes the boundary oracle honest about merges before anything reads dup classes (a merged function is a wrong census member; G22: instrument before measurement). T2 (signatures + twin band) is the measurement every later multiplier keys on. T3 (type file + check) exists before the first new bank (inversion 3, G62). T4 (reconcile ladder) is the bank path; T5 propagates through it; T6 (carves) is what T5's overlay units and later jtbl banks need; T7 (family remap) reuses T4/T5; T8 (X4) needs only T2; T9 (wall oracle, draw filter, P8) consumes every verdict layer, so it is last and carries the milestone run.
- I4/P1.5-1 → T1, measured not re-derived: merge = an inventory function holding ≥1 B2 start strictly inside it, each classified `multi-return` (C0049: interior `jr $ra` reached by a branch past it, keep merged) or `over-merge` (no branch crosses it, split via config/symbols). Independence = per declared start, a basis outside bound2's rules: a Ghidra `k=func` entry or a pointer to it stored as a data word in the image (T5 observed most declared starts are pointer-referenced); `BOUND2 INDEPENDENT <i> of <S>` printed, starts with no outside basis listed by program (a measure, not a gate; 0-merge is the gate).
- Exemplar choice (T4): the highest-payoff dup class in `build/reports/dup.json` with a member in exe TU 120A0, size 9-32 words, no jtbl, reach ≥ 2 programs; fallback the highest-payoff class ≤ 32 words without jtbl. Small and wide: proves fleet-wide propagation at minimum draft risk; the exe member lets the first bank land in an existing C unit, so the ladder is tested apart from the new-overlay-unit question (T5).
- Shared bodies (G7, DK-64): one C file per body under `src/shared/<system>/<name>.c`, `#include`d by each member TU; never a macro body. Member symbol names stay as the corpus names them (overlays link separately); a program with two members of one class gets the body twice under its two names via a one-line `#define` of the function name before the include — the only macro allowed, named in the registry row.
- Registry `config/dedup_registry.txt` (tracked, hand-readable, line-preserving writes — DK-77 lost 47 comment lines to a serializer): `<dup key> <exemplar prog:vram> <shared path> <member prog:vram> <state gated|pending|refused> <reason>`. Fail-closed: `propagate.py` recomputes each member's dup key from the build (census.dup_key) and refuses (rc≠0) on drift, a missing member, or a member in the registry but absent from the class; the dry run builds every member and byte-gates it without committing the change, printing one line per member.
- Overlay C units (I3 → T5): propagating into an overlay turns its one asm TU into a `c` unit (config/c_units.txt row + segment.py) with INCLUDE_ASM for every other function; the clean fleet must stay byte-identical with the unit converted before any body lands (isolate the variable, §5). A mismatch on the first non-120A0 unit opens the triple ladder for that unit (`probe.py --ladder` on that member), per I3.
- Twin band (DK-10): tier exact = census dup key; tier near = relocation-normalised words, prefilter by length ±25% and opcode-histogram L1, then normalised edit distance ≤ 0.3 (the record's lookalike ratio; tuned in T2 with the old value kept in a comment). Controls: every exact pair (all pairs within each dup class ≥ 2) lands in band — "known exact pairs" — and a random-pair base rate is printed (record: 1.17%). Twin rescan runs after every bank (G46) as part of `bank.py`.
- Reconcile ladder (G10, DK-7, DK-41): rungs in order — R1 standalone masked match (probe.py); R2 placed into the real TU replacing its INCLUDE_ASM, unit compiles; R3 declaration sync (callers' prototypes moved to the definition's signature when width-compatible; callee casts) and type check; R4 rodata/jtbl placement; R5 whole-binary hash from a clean rebuild. A rung failure prints the rung and never asks for a redraft of a body that matched at R1. "Without a redraft": the body file is byte-identical between R1 and R5 (sha1 recorded).
- Carves: jtbl carve = move a jump table's rodata from the program's data asm into the dispatcher's unit rodata segment so a banked dispatcher's compiler-emitted table links in place; proven on one real exe table (game TU) with fleet green and a planted wrong-table control refused. Opt-level carve = split one unit at a function boundary into two units, with a per-unit `CFLAGS` override hook in the Makefile; proven on a real O2 cut (fleet green) plus a planted cut at a non-function boundary refused. G43: carve state (yaml, c_units, Makefile fragment) is per binary.
- Verdict layers (DK-24, defined here; source record names none): L1 structural (lib region whose triple is unproven, uncarved jtbl, opt mismatch); L2 registry/twin (already banked, propagated, or member of an open twin cluster, G46); L3 wall ledger (a recorded wall verdict naming pass and dump line, G52); L4 staleness (exclude rows whose reason no longer holds, DK-70). Draw filter consumes all four, cheapest first, and counts each refusal by layer; the wall oracle owns L3 and answers "bankable?" independently; harness P8 `bankable?` compares them over the difficulty list.
- X4 (T8): mmx4 cloned into container `.run/mmx4/` (never tracked; G102 facts only), its C compiled per file with INCLUDE_ASM stubbed under `cc1 2.6.3 + maspsx --aspsx-version=2.63`; per-function signatures from T2's tool; number = X6 functions with an exact (and separately near) X4 partner, over the X6 denominator, plus the X4 denominator (functions that compiled). A file that will not compile is counted, not fixed (proportionality). No X4 byte, object or signature file is committed; only counts go to docs/prior-art.md (G12).
