# C0333 — Byte evidence for a global's access width: objdump -dr the built objects, read the LO16 reloc insns
tags: globtypes,conflict,objdump,reloc,width,evidence · date: 2026-11-02 · phase/task: 2.5/T10 · origin: mmx6 T10.c5

## Problem
Settling a global's type conflict needs byte evidence of its access width, but matched functions have no asm in `asm/` (splat keeps nonmatchings only).
## Mechanism
The built object still holds every access: each load/store of the global carries a relocation against its symbol.
The instruction at a LO16 reloc gives the width and signedness (lb/lbu/lh/lhu/lw, sb/sh/sw).
An `addiu` at the LO16 means the code takes its address (array or struct base).
## Fix
In the container, after a build: `objdump -dr build/<prog>/<obj>.o`, grep the LO16 relocs naming the symbol, count instructions by opcode across every object that touches it.
Type the global by the majority width in its canonical header. A minority access keeps a self-view (C0270), and the evidence goes in docs/types/globals.md.
Fleet byte-identical after the retype is the gate (T10.c5: 0x800741FC, 0x80097244, 0x800B91B8, 0x800C4570).
