# After a second mx.sh sync, regenerate include/ by re-running the split stamp

Symptom: after `mx.sh sync`, then `make extract build`, rebuilding any C object makes the link fail with `undefined reference to .L<addr>` from a `*.rodata.s.o` (3.1 T2.c1: 4228C.c.o, `.L8004D9E8` from 11614.rodata.s.o).

Cause: sync keeps asm/, build/, expected/ and extracted/ (R120), but it mirrors include/ from the host. That deletes the generated, gitignored `include/labels.inc`, `include/include_asm.h` and `include/gte_macros.inc`. `build/split/<prog>.stamp` survives the sync, so make never reruns the split that writes those files.

Fix: `rm build/split/<prog>.stamp; make build/split/<prog>.stamp`, then remove the program's C objects and run `make build/<prog>`, which should print OK. After that, re-measure anything measured while the tree was broken.

Also: when a program's linked bytes change, `make build/<prog>` fails its `sha1sum -c` and make deletes the binary. Read the after-state bytes from `build/<prog>.elf` (objcopy it to a .run/ scratch file).
