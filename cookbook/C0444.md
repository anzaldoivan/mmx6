# Unmerged table-address adds (regalloc): type the byte table as a struct array, index with an s32 temp

Problem: a 2-field read from a byte table (`extern u8 T[]`, stride 6) leaves two address adds unmerged. Their
operands come in the wrong order (regalloc plateau 41/43). Pointer locals load the base after the multiply. Casts to struct or 2D
arrays keep the operand order wrong or fold the +2 field offset into the address constant.

Lever: declare the table as an array of its element struct and index it directly with an s32 temp:
- `typedef struct { s16 unk0, unk2, unk4; } T_Elem; extern T_Elem T[];`
- `s32 i = arg0->unk2; f(T[i].unk2, T[i].unk4);`
One shared address add, base and offset in retail order.

Check: the table's other users (the card's count of users). Retyping a shared global changes every user's
spelling, so confirm the count before the bank.
Related: C0214 (table+index pointer local), C0193 (fn-table operand order), C0411 (sched1 tie on a table address).
Origin: 3.1 T14.c5, rock_08 func_800EA328 (plateau:regalloc 41/43 in two attempts in 3.0 T13 -> 43/43 pin-free, probe 12).
