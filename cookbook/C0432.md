# C0432 — An equivalence sample needs members of each verdict, not exemplar-only keys
tags: propagate,equiv,sample,stratum,exemplar,verification · date: 2026-11-08 · phase/task: 3.0/T3 · origin: mmx6 T3.c1 vacuous gated stratum

Problem: the first EQUIV key sample took, per stratum, the smallest keys by registry row count. Every "gated" key
it took had one row, the `gated exemplar` row. The exemplar is never dry-run, so the sample compared no gated member.
The grouped R5 group path never ran either. Yet the result still printed `EQUIV identical 24 keys 33 members`.

Check: count the sampled keys' registry rows by state and reason (awk over config/dedup_registry.txt) before you
trust an equivalence line. Each stratum needs member rows of its own state that are not `exemplar`.

Fix: the pick filters keys to those with at least one non-exemplar row of the stratum's state, then sorts stably.

Origin: mmx6 3.0 T3.c1 (commit f6f00e72), found by the expert's check of the registry rows.
