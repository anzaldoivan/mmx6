# C0253 — campaign/ is never public. check-public DIR needs its own git repo
tags: split-mode,public,projection,check-public,style · date: 2026-10-25 · phase/task: 1.10/T12 · origin: mmx6 T12

Context: a split-mode repo (config/public-paths.txt, default deny). A task wants files under an agent path made
public, or wants to prove the projection with `psxd_publish.py check-public DIR`.

Wall: listing a file under `campaign/` does nothing. The kit keeps a fixed never-public prefix list
(tools/psxd_publish.py:172: `.claude/`, `phase-ends/`, `campaign/`, `rules/`, `templates/` and more). `list` drops
those files without a word. `check-public` only WARNs that the entry matches no tracked file. A projected copy of
such a file FAILs as an agent file.

Trap: `check-public DIR` reads `git ls-files` in DIR. A plain folder makes git walk up to the parent repo, so the run
checks the dev tree (about 11k files and thousands of FAILs). Run `git init` and one commit in DIR first.

Move: build the projection from `psxd_publish.py list` (drop its `LIST` line) with `rsync --files-from`, then
`git init`, add, commit, and run `check-public <absolute DIR>`. A file that must be public lives outside the agent
prefixes, for example under config/.

Second wall: a newly listed prose file enters the style ratchet at 0 findings, so the commit gate refuses it. A
generator-written file takes a `skip` line in config/style-ratchet.txt. That file is guard-denied to agents, so the
developer adds the line.
