# Switch case-tree pivot: an empty `case 0: break;` moves gcc's binary-tree pivot

Symptom: the compare tree of a small switch has one node too few or the wrong pivot value (length or jump residual). For example, the target splits at 1 and our build splits at 2.

Cause: gcc 2.95 builds the case tree from the case set. An extra empty case changes the set, and so the pivot and the node count.

Lever: add `case 0: break;` (an empty case that falls out) to the switch. It costs no code but reshapes the tree (3 → 4 nodes here). Apply it to every switch of the same shape in the body.

Evidence: W14 rock_15 F0A78 (24 → 161/164). A mod-4 spelled `t - (t / 4) * 4` on a block-local s32 then gives 164/164.
Related: C0156 (`switch ((u32)x)`), C0157 (case bodies in block order), C0113.
