# C0178 — Explicit byte offset, not a cast view, keeps an offset shared across same-shape arrays
tags: lever,array,offset,cse,cast,view-macro · date: 2026-10-10 · phase/task: 1.8.1/T17 · origin: mmx6 W17 SLUS 26ECC

Symptom: two same-shape global arrays indexed with the same (i, layer, buf) where retail reuses one computed offset for both; the draft recomputes it or associates it differently.
Cause: a cast view macro on one array, `(*(T (*)[2][6][17])&X)`, associates the offset as buf+layer+i, while a declared array gives (i*4 + l*68) + buf*408; cse shares only identical trees.
Lever: when the TU fixes one array's declared shape (no free re-declaration), spell its access as an explicit byte offset in the declared array's order, `(u8*)X + i*4 + l*68 + b*408`, instead of a cast view.
Evidence: W17 SLUS 26ECC (length 129 to 33 with this lever, then loop-local placement; banked 129/129).
Related: C0117 (one extern per field), C0124 (TU consensus declaration).
