# C0086 — Struct base reloaded per member store: name the pointer-derived base in a local
tags: idiom,sym-global-reload,G-expr,cse,alias,struct · date: 2026-10-02 · phase/task: 1.7/T6 · origin: BFM §193-H re-proven

1. **Residual (tell)**: a pointer loaded out of a struct (`lw $5,0($4)` for `p->a`) again after each member store through it, where the target loads it once (or the reverse). `sym-global-reload`
2. **Mechanism**: cse (G-expr). A member store through the loaded base and the base load itself are both varying-address /s MEMs, so the store may alias the base; cse drops the cached load and expand's re-read stays.
   - src:gcc-2.95.2/gcc/cse.c:1832 "true_dependence (x, full_mode, p->exp, cse_rtx_varies_p)"
   - src:gcc-2.95.2/gcc/alias.c:1269 "return !fixed_scalar_and_varying_struct_p (mem, x, varies);"
   - a-side `.cse`: third store through fresh pseudo 84 (`(set (mem/s:SI (plus:SI (reg:SI 84)`).
3. **Lever**: name the base in a local (`struct S2 *q = p->a; q->x = 1; q->y = 2; q->z = 3;`) for one load; spell `p->a->` per store to reload it each time. a 10 insns, b 8.
4. **Byte proof**: repro/G-expr/baseload.{a,b}.c; `repro.py --lever L12` -> `LEVER L12 OK`; standalone compile under the pin. Retail anchor: none yet. Map row L12. BFM §193-H (gcc 2.7.2) title re-proven under 2.95.2.
