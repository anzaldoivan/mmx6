## Rationale
- Order: image (T1) → C build path with all-stub C unit (T2) → probe harness (T3) → scaffold + differ (T4) → per-module census (T5) → probes and ladder run (T6) → pin record (T7) → first banks (T8). The C path is proven compiler-independent (all-stub unit, fleet unchanged) before any probe, so a ladder failure can never be a build-integration failure (G26: exonerate the instrument first).
- T1 installs a broad ladder in one image change (cc1 builds are a few MB each, maspsx versions are one flag): rebuilding the image per rung costs more than installing ten rungs once. Candidates: 2.7.2 (old-gcc 0.9, mmx4's exact build), 2.7.2-psx, 2.7.2-cdk, 2.6.3-psx, 2.8.0-psx, 2.8.1-psx, 2.91.66-psx, 2.95.2-psx from one pinned old-gcc tag (plus 0.9 for the mmx4 build); maspsx pinned by commit; aspsx versions are a per-triple flag, not an install.
- T3 builds the ladder runner as a tool, not as a scratch loop: the milestone's verified-by needs a repeatable `make probe-ladder`, and phases 1.6-1.8 reuse `probe.py` as the standalone probe (G10). It carries its own negative control (G25): a deliberately mutated probe must FAIL under every triple, and an INCLUDE_ASM-verbatim probe must MATCH (known-true case, G32), so a vacuous "match" is impossible.
- T4 separate from T3: scaffold and differ are developer-workflow tools with their own checks; T3's milestone path must not wait on m2c packaging issues.
- T5 before probe choice: the census (prologue `$fp` tell, `%gp_rel` count, `nop`-after-load density, div-expansion presence) per function across all 57 programs decides which modules need their own probe, so probes span every detected class; "per-module variation detected" is a milestone clause and needs a fleet-wide instrument, not a sample.
- T6 is one task: probes are small (the source project's lesson), and choosing, drafting and laddering them is one evidence loop. If two triples stay indistinguishable on all probes, T6 adds a discriminating probe (sltu+$at, div-expansion specifics, `-G` use) rather than declaring a pin; the k ≤ 5 bound allows that.
- T7 `review: yes`, `coder: none`: the constitution (PROJECT_CONTEXT.md:160,532) routes the compiler pin to `/discuss max`; the preset has no hard rung, so the plan splits it: T6 produces the byte evidence, T7 writes the dossier, and the developer ratifies at the review pause (opening `/discuss max` there if they want). T8 waits for T7 so no bank rests on an unratified pin.
- T8 banks the probe functions into their real TUs (G10: standalone → real TU → whole binary). Probes chosen in T6 prefer TUs without jump tables or migrated rodata (kit: a jr-table function needs a per-function carve, a 1.6 tool), so the first banks test the compiler, not the carve.
- `config/c_units.txt` (tracked list read by `segment.py`) instead of hand-editing yaml: keeps the 1.3 binding that the subsegment block is generated.
- All tasks `effort: medium`: preset `hard rung: none`; the one judgment (the pin) is split into evidence (T6) and a developer-ratified record (T7).
- Fan-out: not used; the ladder is CPU work inside one `make` target, not agent breadth.

## Risks
- old-gcc linux cc1 binaries may be 32-bit or need old glibc; under amd64 emulation on the Mac they may fail or crawl. T1 checks `file` and installs i386 runtime if needed; if a rung cannot run, it is recorded as `not judged` (G35), never as a FAIL.
- psx-vs-cdk cc1 and nearby aspsx versions are byte-equivalent on most code (kit): "exactly one triple" may need a discriminating probe; if the fleet offers none, the honest outcome is an equivalence class, and T7's review is where the developer accepts a representative. That would change the milestone wording, so it goes through the critic.
- The real compiler may be outside the ladder (a Capcom in-house cc1 or PsyQ 4.7's own CCPSX build). Then `PIN NONE`: T6 returns blocked with the closest rung's diff classes, and the plan widens the ladder (2.91.66/2.95.2 already installed; aspsx up to 2.86).
- Nonzero gp (0x8008EAA4) means some code uses `%gp_rel`: probes using small globals need `-G<n>` and the matching `maspsx -G`/`--dont-force-G0`; the standalone probe must mask gp offsets or it reports false FAILs.
- INCLUDE_ASM via cc1 + maspsx may alter alignment/padding around stub bodies, or maspsx may rewrite `.include`d asm; T2 proves the all-stub unit byte-identical before any probe; a mismatch there stops the phase at T2.
- Jump-table and rodata migration: a C unit whose functions own `.rodata` needs a carve (1.6). Probes and first banks avoid them; if every candidate TU has rodata, T8 returns blocked with a recommendation.
- Kit tools assume the source project's paths; adapting them may surface undocumented assumptions (G66). Reading the kit copy is allowed; copying it verbatim is not.
