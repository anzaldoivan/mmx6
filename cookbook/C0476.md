# C0476 — gcse vs loop hoists: a cast compare re-creates a folded copy, a pointer set after a break hoists later
tags: lever,gcse,copy-propagation,loop,hoist,combine,preheader,pin,depin,goto,slt,s8 · date: 2026-11-15 · phase/task: 3.2/T6 · origin: mmx6 T6.c6 func_80033214

Copy fold: gcse copy propagation folds any `old = cur` copy back into `cur`, so retail's register copy is lost.
Re-reading the byte, an s16 local, a reused local and an s16 cast all fail.
Compare `(s8)old == i` inside the loop instead.
The loop pass hoists the sign extension, and combine, which runs after gcse, turns it into the copy.

Hoist order: gcse hoists a pointer set on every path into the loop to the preheader first.
The loop pass hoists its own invariants after it, and sched1 does not swap them (all priority 1).
To get the pointer after the loop-hoisted insns, set it in the body after a conditional break.
It is then not anticipatable at loop entry, so the loop pass hoists it, after the copy.

slt pin in a goto loop: when the label sits between an s8 truncation and the slt, the slt gets its own block.
Move the label before the truncation with a fresh s32: `n = i + 1; test: i = n;`.
The truncation and the slt then share a block, and C0404's one-insn stretch puts the slt in place.

Evidence: 3.2 T6.c6 func_80033214, W12's 4 pins all dropped at the same 185/187 (unpinned 81/187).
Resolved in the retry (T6.c17, 187/187 pin-free, 6 probes): set the invariant load and the pointer in source before the loop.
Source order then fixes the preheader, whichever pass would hoist first.
Peel the first test by hand into a goto loop, so the loop pass does not strength-reduce the s8 index.
Put `do { } while (0);` where the removed loop's depth mattered: the jump rotation and greg's loop-depth weights.
