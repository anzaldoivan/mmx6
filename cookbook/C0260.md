# C0260 — Struct field offsets via an offsetof table compiled by the pinned cc1

# Struct field offsets from the pinned compiler, not a Python layout engine

Problem: compare two header sets (x4.h vs mmx4 at the pin) field by field by offset. Neither side carries offset comments. A hand-written layout engine would be a second, unverified oracle.

Move:
- Append a table to each preprocessed TU: `int t[] = { (int)&((T *)0)->f + 1, ... };` per field. The `+ 1` keeps the table out of bss so the values appear as `.word` lines.
- Compile with the triple's cc1 (`-S`), read the `.word` values back in order, subtract 1.
- Bitfields cannot be addressed: give them offset `-` and pair them by ordinal.
- Preprocess our side with the Makefile's cpp (`mipsel-linux-gnu-cpp -nostdinc -undef -D__GNUC__=2 -DPSX -Iinclude`). The host cpp injects `stdc-predef.h`, which cc1 2.95 rejects.
- x4port.top_split ignores braces: nested members need a brace-aware `;` splitter. x4port.unattr knows only `__attribute__`, so normalize `__attribute` first.

Example: tools/mmx6/x4names.py `--compare` (docs/x4-compare.md), 262 structs.
