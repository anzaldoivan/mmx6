# Repoint a cite to a file renamed long ago

- Context: a `path:N` cite points at a body that 2.3 rename.py renamed. The cite was never rewritten, and no layout move row maps it.
- Move: read the old line text at the commit that last touched the cite line. Take it from `git blame` of the citing file, or from that commit's parent.
- Then find that text inside the range of `layout.locate(prog, func)`, together with the via anchor. Fall back to the last commit where the path existed.
- Why: the cited file kept changing after the cite was written. Its last version has a different line N.
- Example: the assets.tsv cite `func_80014F70(0x58)` landed on `0x5E == 3`.
- Anchor trap: 2.3 renamed some `via=func_/D_<hex>` anchors, so a correct line N fails the anchor check. Rewrite the anchor to the current name only where line N holds that name.
- Ghidra trap: `make ghidra-mirror` (x4adapter --mirror) appends to plate comments and never replaces them. A fixed `// basis:` cite does not clear the old line from config/ghidra/*.jsonl.
- Source: 2.4 T17.c1 (layout.py stale_of).
