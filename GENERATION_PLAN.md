Goal: every code binary on the Mega Man X6 USA v1.1 disc (SLUS-01395) rebuilds byte-identical from readable, evidenced C, the hash check inside `make build`, reproducible by a stranger from their own dump and the README alone.
Done-criteria: the clean fleet check (`clean → extract → build`) prints N of N and exits 0, N fixed by 1.2's load map; the census reads 0 stubs and every function not in C is on a named, published ledger (vendor objects, genuine hand-written asm); the recorded contract run (both SDK legs, every oracle green) and the fresh-clone proof pass; every published number is generated with a freshness check; the census reads 0 unmarked pins, 0 macro bodies, 0 raw address casts and `make format-check` passes; `PY tools/audit_public.py` exits 0 on the tree and 1 on the planted fixture throughout. The union of the eleven milestones below, each run by `PY tools/phaseend_index.py verify`.

## Ordering rationale

- Numbering follows the constitution's ladder (1.0–1.10) unchanged: `PROJECT_CONTEXT.md`, `rules/` and the kernels cite these ids ("rules from Phase 1.4"); renumbering would mislead every agent that reads them.
- 1.0 first: the firewall is a t=0 decision (DK-1) and the Mac↔Docker arrangement decides where every later build runs. Most of 1.0's tooling arrived with the install (audit, fixture, `no-rom.yml`, 67 rules); the phase verifies it and closes the two real gaps (tree arrangement, formatter). Its CI clause waits on the developer's push, the only developer action in the generation's gates.
- Data before processing: 1.1's extraction and manifest feed every oracle; 1.2's load map fixes N and the forced boundaries that 1.3's segmentation needs before any C exists (DK-12).
- 1.3 before 1.4: the all-assembly baseline is the harness the probes run in; a pin proven outside the real build is a claim, not a gate (G3, G61).
- 1.4 before 1.5: the census counts against the real toolchain; scanners built before the pin would be re-validated.
- 1.5 is its own validation phase at 0%: almost every recorded wall was an instrument (DK-9, DK-17); the honest denominators are what 1.6's propagation and 1.8's routing read.
- 1.6 before 1.7 before 1.8: the multipliers make the cheap half free and the codegen map makes the residuals steerable; the campaign banks at the rate these allow (calibration: the source project's map arrived 17 phases late).
- 1.8 stays one phase with waves as task groups, each closed by the harvest gate. Whether the campaign needs splitting into further phases depends on 1.5's census (corpus size, unique tail) and 1.8's measured routing cliff, both unknown today; the 1.8 planner-phase decides with those numbers, through a `## Changes` line here.
- 1.9 before 1.10: publication proves reproducibility of the matched tree; 1.10 is short by design because readability is enforced at bank time from 1.4 (the six inversions) and must not change N of N.

## Standing constraints

- The byte gate is the only claim: whole-binary hash from a clean rebuild, inside `make build` (G3, G61); no unmatched C in a default build (G4).
- No game-derived byte in git, ever; the audit runs locally and in CI; never `git clean -x` (G12–G18). Dump and BIOS stay in `/Users/ThinkPad/GameInputs/megaman-x6/`.
- Prior art is a lead until our own bytes prove it (G101); nothing copied from Kuumba123 or MegaManX6Recomp; mmx4 C only for proven-shared functions, attributed in `THIRD_PARTY.md` (G102). `docs/prior-art.md` is the status record; its Corrections supersede the constitution's compiler wording.
- Names only with recorded evidence; unnamed beats wrong (G62). Outward text by a person; no automated traffic against community infrastructure (G63–G65).
- The six readability inversions hold from the first C file (1.4 on).
- Builds run in the amd64 Docker host; oracles run native on the Mac. Never probe the Docker VM with `--privileged` or `--pid=host` (skill `docker-vm-no-privileged`).
- `verified by:` clauses written `python3 …` in the constitution run as `PY` (`/opt/homebrew/opt/python@3.14/bin/python3.14`); each phase plan pins the exact spelling of commands it builds.
- Models: Opus 5.5 for experts and coders, never Fable; the compiler pin, every load-address derivation, the segmentation decision and every wall verdict go to `/discuss max` or are split until routine.
- Free, local, deterministic work before paid work (DK-40); waves sized to Max 5x (G39).
- The harness is not the product: `tools/` PA3 scripts, `.claude/`, hooks and templates are never edited by this project's tasks; defects become `harness:` gotchas. Project tools (extractor, oracles bridges, campaign tools) are new files under `tools/` and are product.
- Out of scope this generation: other versions (JP, v1.0, prototype), a shiftable build, assets, ports, randomizers (Generation 2+, Parking Lot).
