1. Cards and packs (DK-39, G44). Card = deterministic zero-token bundle per target: destination file, banked twin found over the WHOLE world (banked beats open; seed), file's declarations, per-callee declaration consensus, past-attempt history, atlas lever + where to read, same-unit neighbours' declarations of shared globals. Card names only levers present in the knowledge base. Pack must sit where the agent is told to read. Done-when: card build is a script; a control card for a known-banked target carries its twin. Earned: twin field took a wave 0 to 51 banked; laws file one dir off for weeks; 108 transcripts searched a word the base lacked. Control: banked-twin-on-card 4 of 4. Generic; twin graph and paths project-specific (C0074 draw filter from 1.6 caps one member per component).
2. Lanes (DK-40, G48). Drafter, gater, maintenance, watchdog, distiller, one per excluded population, each restartable with own cadence; free work (twins, remaps, propagation) first when paid lane idle; one card per skeleton, siblings via free remap. Never stop the drafter to ship a change; ship at wave boundary. Earned: 139 of 162 idle minutes. Done-when: lanes start/stop independently; a code change ships with drafter untouched. Sizing: on one Mac a lane is a script, not a daemon fleet.
3. Wave procedure (DK-41, DK-36, DK-42, G45, G50). Census drafts first (DK-31: join manifests, filesystem, oracle; classes: match->gate, compile fail->ladder, near->permuter, far->redraft; classify at the shipped opt level). Draw (concentrate targets per binary to cut rebuilds; judge by instructions banked, not heads). Draft, gate the DIRECTORY, assert banked+failed+no-verdict==drafts, reconcile per gate group before rebuild, ONE build as batch verdict (hash, commit on green only), recover, then record yield, then harvest gate. Control: a planted byte-identical draft must bank even if verdict says nothing. Earned: 579-instr match reported as nothing; 5/8 at gate became 8/8 after recovery; batch failed twice with 11/12 drafts correct; 16/16 heads (7,200 instr) vs 7/16 heads (10,616). Rows: yield recorded only after recovery.
4. Journal read side (DK-32). Hand each item's prior agent notes to the next agent via the card. Earned: 896 index-gap reports unread 30 phases; with notes 38/39 matched on hardest frontier. Done-when: a target with a stored journal shows it on its card (known-true: item with a prior note). Project-specific: journal schema; none exist yet in mmx6 (1.7 permuter stored drafts are the nearest).
5. Target validator (G49, DK-19c). Gate before a wave: real function boundary, asm on disk, inside binary range, not already banked; an empty tier ends a cascade. Earned: 87 of 119 agents proved phantoms absent. Control: planted phantom, out-of-range address, and banked function each rejected. Generic.
6. Exclude-list audit (G38, DK-19). Audit before every draw; stale list refused (list records tooling limits on the day written). Re-probe each entry from bytes, at the object's own opt level. Earned: 79 draws of 11 unbankable; 88 of 107 entries stale next day; wrong opt level looked like model failure. Control: an entry known now bankable gets dropped; an entry with an old date fails the draw.
7. Gates in worktrees (C0004, DK-21, DK-33, DK-54, DK-28). Each binary gates in its own worktree under a per-binary lock, build with -j, processes not threads. Negative-control the worktree with a known-good item; assert inputs (gitignored files absent in worktrees give false verdicts, report MISSING). Reap worktrees (12 forgotten ones pinned 12 GB). Assert produced-adopted-refused=0. Sizing: one Mac, arm64 host with amd64 Docker (PROJECT_CONTEXT:88); keep concurrent gates small, 2-3. Project-specific: gate command, lock path.
8. Recovery ladder (G50, DK-41, C0003). Bank.py reconcile ladder (built 1.6): body vs plumbing rejects; plumbing banks with zero tokens, snapshot-restore on undo. Keep deterministic recovery separate from permuter search (1.7). Done-when: recovered rows counted before close rate quoted. Earned: 5/8 to 8/8; 26 of 27 rejections byte-perfect.
9. Harvest tools (G45, DK-16). Hard gate: no new wave until last wave's idioms are in cookbook+index, mechanical idioms became sweeps that bank free functions, widening review asked "which scanner's denominator widened". Harvest only byte-proven; strip credited lever, recompile before entering base (about 1 in 3 inert; 4/8, 6/19). Also G47/DK-34: draft file first, verdict last, final message exactly one JSON line, dead sessions recovered by transcript tool (22 stranded verdicts, 724 instr). DK-35: per-item work dirs keyed by binary+address, deliverables dir no agent cleans. Earned DK-16: 10 functions/1,027 instr in an afternoon.
10. Verbatim check (DK-29). Strict check in per-bank close that the body is C, not an inline-asm pasted body (byte gate is null oracle). Control: planted asm-body must fail. Ledger best draft never an asm body. Also DK-36 verbatim grep precedes real-TU probe.
11. First cracks / manual wave / routing cliff (DK-43, G39, C0006). Small manual wave (hand-routed), measure bank rate by instruction count; first guess was off 2x. Output: routing set (tier by size band). Source numbers (not mmx6): cheap tier 86% to 20% across 50-120 instr; cheap == strong under ~50 instr at 4.8x lower cost; 63 claimed = 63 real. Done-when: table of rate by instruction bin with n per bin, and a routing file. Strongest model only for new wall classes (DK-43, DK-51: frontier banked 9/12 at ~325k tokens/row).
12. Named ledger (DK-66, DK-20, G53, G54, G56, DK-50, DK-51). Every remaining function: class, closeness, best draft, named blocker. Rows name the compilation tier they survived (DK-20); "PROVED" names its producer list (G53); wall verdict names pass + dump line (G52); ledger tie-break is part of the instrument (DK-66); partition invariant: ledger partitions live work. Before a wall verdict: provenance/vendor check (G56), port banked sibling spelling before dials (G54, 0.55 score after ~1M tokens). Milestone check: census 0 stubs, all remaining on ledger, clean fleet N of N.

Sizing for Max 5x (G39, DK-40/42): no mmx6 measured numbers exist, only source-project ones. Inferred suggestions: first wave 10-20 targets across the instruction range, ~4-6 concurrent agents, turn/cost cap scaled to instruction count per card (source: 98 of 270 attempts hit a fixed cap), harvest workflow counts against the concurrency cap, free local lanes before paid ones, mid-tier unless wall class is new. Planner should decide wave size after 1.5 census (GENERATION_PLAN.md:33).
