# C0331 — Struct headers ride on x4.h: fleet-inconsistent prototypes need a header x4.h does not include
tags: header,prototype,extern,hoist,x4,unit · date: 2026-11-02 · phase/task: 2.5/T10 · origin: mmx6 T10.c2

## Problem
A prototype hoisted into a struct header breaks compiles fleet-wide.
## Mechanism
x4.h includes player.h, object.h, projectile.h and state.h (x4.h:3217-3220), so they reach 464 files.
A symbol with conflicting declarations elsewhere (e.g. `extern s32 g_Player`) then fails with conflicting types.
A header first included mid-unit stays in force for the rest of the unit.
Its declarations must be compatible with every later declaration in that unit.
## Fix
Put fleet-inconsistent symbols in a header x4.h does not include (T10: weapon.h, sound.h, dash.h ...).
Include it only in the files whose declarations agree. Check the unit's later members, not only the file.
