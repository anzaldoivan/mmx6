# C0308 — Pull config/layout-moves.tsv before a host repoint, since pull src leaves it stale
tags: layout,repoint,apply,mx.sh,pull,moves · date: 2026-10-31 · phase/task: 2.4/T24 · origin: mmx6 T24.c1

Context: after `layout.py apply` in the container, `mx.sh pull src` brings the moved role files but not
`config/layout-moves.tsv`, which apply rewrites. A host `layout.py repoint` then reads the stale moves file:
it maps 0 cites, writes no `# repointed` marker, and exits clean. Nothing looks wrong.

Move: pull the moves file explicitly before repoint.
- `bash tools/docker/mx.sh pull src` (then mirror deletions, C0299)
- `bash tools/docker/mx.sh pull config/layout-moves.tsv`
- `PY tools/mmx6/layout.py repoint --prog <p>`: expect `repointed` > 0 when files moved (2.4 T24: 188 of 1259)

Check: a repoint after a non-empty apply that reports 0 repointed means the moves file is stale.
