# C0321 — Census a pool entry type through pool-only pointers and sibling pools
tags: census,pool,stride,objfields,evidence,projectile · date: 2026-11-01 · phase/task: 2.5/T6 · origin: 2.5 T6.c2

Context: a field census types a struct from the accesses it can see. Code touches a pool entry type such as
ProjectileObj (0xA0) mostly through local walker pointers (`p = g_projectiles; p += 0xA0`). It also walks sibling
pools of the same entry type (D_800950A0, 32 x 0xA0 just past g_projectiles' end). 2.5 T6.c2, tools/mmx6/objfields.py
scan_pool().

Trap: counting only `g_projectiles[i].m` leaves the tail fields unevidenced. Counting every pointer that ever
holds the pool's address over-counts reused walkers that later point elsewhere.

Move: treat a pointer as a pool pointer only when every assignment to it comes from a pool. A pool is the base, a
sibling pool of the same entry type, or another pool pointer. Count raw `p[off]` and macro accesses through those. A sibling
pool gives tail evidence (unk9C, unk9D came from D_800950A0 walkers).

Check:
- objfields --check: mismatches 0, off-start 0.
- the self-test census case reports typed > 0, raw > 0 and the asserted size.
