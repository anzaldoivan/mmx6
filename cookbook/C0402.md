# Map a stale `path:N via=<a>` cite with no unique old-text match: R1-R4 in layout.py repoint

`stale_of` finds the old text of line N at the first revision holding `\b<a>\b`. When it is not unique, or no revision ever held `<a>` at N ("wrong when written"), use these rules in order (`layout.py` `remap_line`, `anchor_line`):
- R1: one exact stripped line equal to the old text that holds the anchor.
- R2: clang-format reflow. The old line with whitespace removed equals 1-4 consecutive current lines joined. Map to the run's line holding the anchor, which is not always the first line.
- R3: duplicate text (more than one R1/R2 hit): take the hit nearest N. Refuse an equal-distance tie and never pass it to R4.
- R4: anchor. Take the one non-`//` line in the cited file holding the anchor. Otherwise take the nearest such line inside the C function around N, refusing a tie.
- Trap: R4 must search the cited file, not the file of the function the row names. In xref and caller rows `via=` names a callee. Searching the function's own file sent 2 of 9 cites to the wrong file on the first dry run.
- A row with two cites on one line changes only the cite whose `via` fails.
- The heuristics can map to a wrong line without saying so. repoint prints `LAYOUT REPOINT ... rule=R<k> | <target text>`. Read each target line before you commit.
