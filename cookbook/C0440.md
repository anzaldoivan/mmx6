# C0440 — Sum a wave's debt rises before staging: scratch index copy + debt --staged
tags: bank,debt,placeholder,git-index,bank_close · date: 2026-11-10 · phase/task: 3.1/T7 · origin: 3.1 T7 bank_close --rises

Symptom: a wave's bank needs one `debt --raise placeholder <n>` before staging. Plain `debt` reads only the
tracked files of the work tree. New (untracked) bank files are missed, so an agent cannot sum the rise.

Fix: `bash tools/mmx6/bank_close.sh --rises --paths-from <list>`. It copies `.git/index` into `.run/<phase>/`, runs
`GIT_INDEX_FILE=<copy> git add -A -- <paths>`, then `GIT_INDEX_FILE=<copy> psxd_floor.py debt --staged`, and parses
`DEBT FAIL rise <kind>: <total>, its row is <row>` (rise = total - row, mode from the `down:` list of the `DEBT CHECK` line).
The real index and the baseline are never written. Last line `BANK-RISES placeholder <n> other <kinds|none>`.

Traps:
- the debt counter skips files under `.run/` (ignored). A self-test plant sits in `src/`, untracked and removed by an
  EXIT trap. The test asserts that `git status` and the `.git/index` cksum are unchanged.
- the base is the index as it is: anything already staged counts too.
- `git add` under the copy still writes loose objects into `.git/objects` (harmless).
Proof: 3.1 T7 self-test, three planted `func_` bodies give `BANK-RISES placeholder 3 other none`.
