# Pair a table lui with the %lo that uses its own register, never the next addiu

Symptom: a propagated member fails R5 as reloc. The obj names the exemplar's table (`D_800F5FA0`), and retail names
the member's (`D_800F5FB0`). The member's D_ define never applied.

Cause: propagate.table_addr paired a `lui` with the next `lw`/`addiu` whatever its base register. In func_800F22D8
`lui v0,0x800f` is followed by `li v0,7` (`addiu v0,$zero,7`) before the real `%lo`. That gives 0x800F0007, no
`D_800F0007` in the body, and the table define dropped.

Move: take the `%lo` half only from an instruction whose base register is the lui's rt (3.1 T4.c2, under
`--repair rolefeed`). With the switch off, pairing is unchanged. A plant in propagate.py --self-test checks both.

Check: a member's defines list shows `D_<exemplar table>=D_<member table>` before the probe.
