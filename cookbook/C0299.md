# C0299 — layout apply in the container: mirror its deletions on the host (pull never deletes)

# layout.py apply in the container deletes old bodies. mx.sh pull does not mirror deletions

- `layout.py apply --prog p` runs in the container, because it needs the Makefile cpp. It deletes each old body
  that no unit still includes.
- `mx.sh pull src` copies new and changed files back to the Mac tree but never deletes. The host keeps stale bodies.
  The next `mx.sh sync` pushes them back.
- After each apply, list both trees in the C locale and `git rm` the host-only files:

```sh
mx.sh run bash -c 'find src -type f | LC_ALL=C sort' > c.txt
find src -type f -not -name .DS_Store | LC_ALL=C sort > h.txt
LC_ALL=C comm -13 c.txt h.txt > gone.txt   # host-only = deleted by apply
xargs git rm -q < gone.txt
```

- The gone count equals apply's `deleted <n>`. After the pull, `comm -23` (container-only) is empty.
- Sort both lists with LC_ALL=C. With the default locales (Linux glibc vs macOS), comm reports thousands of false
  differences.
