# Parameter copied to a plain local closes a callee-saved swap with the loop counter

Symptom: a draft scores a few rows short where only the parameter and a loop counter swap their callee-saved registers.

Cause: the incoming parameter pseudo and the counter compete for the same callee-saved registers. Their allocation order follows pseudo creation order.

Lever: copy the parameter into a plain (unpinned) local at the top (`void *p = arg;`) and use only the local. Pinning the counter instead made it worse. Check a banked twin first: it often already spells the copy.

Evidence: W15 SLUS 1EE7C (129 → 147/147, twin func_8001F320). W14 SLUS 1F320 (same lever among others).
Related: C0158 (pinned parameter copy with a cse barrier).
