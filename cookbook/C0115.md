# C0115 — A goto to the body in one arm stops jump2 cross-jumping identical compare tails
tags: lever,goto,cross-jump,jump2,arm-order,block-order · date: 2026-10-03 · phase/task: 1.8/T13 · origin: mmx6 W4

1. **Residual (tell)**: Two arms each end in the same threshold compare and branch to the same return. The draft merges them into one tail (one compare, jumps into it). Retail keeps a separate compare per arm. The first compare is a branch to the body, followed by a jump to the return.
2. **Mechanism**: This is observed. The jump2 cross-jumping merges identical instruction tails that flow to one label. An explicit `goto` to the body plus a bare `return` in the first arm changes the tail. Then the two no longer match.
3. **Lever**: In the first arm, write `if (d >= K) goto body; return;` instead of the shared condition. Also order the if/else arms as retail places the blocks (the non-zero-counter arm first here).
4. **Byte proof**: In wave W4 (1.8/T13), rock_04:0x800EE8D8 went 100 → 207 (arm order) → 282/282 (goto) (banked).
