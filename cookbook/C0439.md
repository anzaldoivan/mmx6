# Feed a twin member only the exemplar's own range when the shared path is a split-unit file
- Symptom: a dup member's masked object equals retail, but R5 is hash-red. build/<prog>.map places it past its retail vram (refusecause `address`).
- Check: the shift equals the exemplar vram less the start of the registry shared path (col 3). Then the path is a split-unit file, `src/<prog>/<addr>.c`, included by the unit.
- Cause: every function ahead of the exemplar in that file is compiled into the member's unit too.
- Fix: extract the exemplar's range into src/shared/<prog>/<func>.c with `#include` at the same spot. Every includer's object stays byte-equal (rolefeed's extract). Feed the member that body alone.
- The cut body needs copies of the file head and of the lines above the exemplar. Split-unit files carry their own include and extern block per function (else R2 `NULL undeclared`).
- "Whole unit" here is the split file, not a TU: do not require the file to be its own includer.
- Result (3.1 T6.c1, `--repair unitcut`): address 17 -> 0, all 17 then `reloc`. With relocdef also on, 16 of 17 gated with R5 green.
