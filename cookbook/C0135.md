# C0135 — Sweep statement order for L07 store-order and register-name residuals; retail's order is not the answer
tags: lever,L07,sched,store-order,permutation,sweep,regalloc · date: 2026-10-04 · phase/task: 1.8.1/T5 · origin: mmx6 W5

Symptom: plateau `sched residual` (L07): same-base stores in a different order than retail, or a register-name mismatch with an otherwise identical stream (lui/addiu pairs taking v0/v1 in reverse, a0/a1 on a call arg, an s-register swap between long-lived locals).
Mechanism: gcc 2.95 sched1 tie-breaks independent same-base memory ops roughly inversely to source order; statement order also changes insn luids and so global-alloc live lengths. The winning source order is often not retail's emitted order (m2c gives the emitted order).
Lever: sweep instead of reasoning. Two swapped stores: swap the lines first. Else exhaustive permutation of the arm's 2-4 stores (≤ 24-36 variants, per arm independently), then single-line-move sweeps (one statement to every slot), which found orders full permutations missed. plateau.py costs ~2 s per variant and no probe-cap runs.
Evidence (phase 1.8.1 T5): c15 c17 c36 c42 c54 c62 c65 c68 (logs/T5.c<k>.md); 1.8 T13 rock_11:0x800EAF90 (48-variant sweep).
Limit: a byte-constant store landing one slot early was not moved by order, volatile chains, struct typing or temps (c44); escalate (permuter) for those.
