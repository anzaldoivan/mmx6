# C0286 — Apply a names-verdict batch: refresh code refs after header inserts and renames
tags: names,verdicts,basis,docconv,rename,refs · date: 2026-10-30 · phase/task: 2.3/T12 · origin: mmx6 2.3 T12.c1/c2

Use: applying a batch of names verdicts whose basis cites `code:<path>:<line> via=<anchor>` (T11, T12 style).
- Verdict col 8 joins its parts with `; `: `xref:<rel>=<nb>; code:<path>:<line> via=<anchor>`. One part `xref:... code:...` fails as code-untracked.
- A DC header inserted above a def shifts every `code:` ref below it in that file, including other rows' refs into shared TUs (e.g. SLUS 32208.c). Refresh refs in verdicts col 8, `config/symbols/basis.tsv` and src/include: moved path from rename.py, line +header_len when line >= insert line.
- `via=func_<P>` anchors go stale when P is renamed: rewrite to the new name only when the new name is on the cited line.
- Then verify every `code:` ref: the anchor appears on the cited line (scratch check, 2.3/T12.c2 `.run/2.3/T12/hdr.py`).
- Leave the `// basis:` comments in `config/symbols.<prog>.txt` as rename.py wrote them (rename-time record). Refreshing them broke 37 refs.
- rename.py may append a second `; name:` clause where one exists: grep `; name:.*; name:` after the batch.
- A renamed function still in asm (INCLUDE_ASM) keeps its `func_` name in `campaign/ledger.tsv`, and fleet health fails `LEDGER BAD <prog>:<vram> func-name`. Rebuild it in the container (`python3 tools/mmx6/ledger.py --build`, then `--check`), pull it, and commit it with the rename (T10.c2, T12).
